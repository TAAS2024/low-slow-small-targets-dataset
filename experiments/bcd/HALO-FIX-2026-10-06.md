# 融合带（halo）「灰绿糊块」问题：定位 · 修复 · 验证

> 日期：2026-10-06 · 对象：`0-workspace/generator/lora_inpainter_v7.py`（v9 管线）
> 产物基线：`experiments/bcd/out_D/`（300 样本，v9 全量重跑，D1/D2/D3 修复后）

---

## 1. 现象与旧认知的偏差

用户报告的肉眼现象是「无人机周围一圈灰绿糊块」。v7.3 的注释把它归因为
**融合带过宽导致背景被整块替换**（feather 12px 时 ring 绿偏 +6.47、ring 噪声 15.21）。

但 D3 修复（`fp = min(feather_px, 5%·目标边长)`）之后，实测**平均色偏已经很轻**
（green −0.55 / sat −1.11），现象却仍在。说明"均匀绿偏"不是主体。

## 2. 定量诊断（`diag_halo_detail.py`，out_D 前 60 张）

把目标周边 `w = max(2, min(12, 5%·边长))` px 定义为 **ring**，ring 外再扩 3w 定义为 **outer**（应完全未动）：

| 指标（final − bg） | **ring** | **outer** | 判读 |
|---|---|---|---|
| 高频噪声 final | **20.01** | 5.77 | |
| 高频噪声 bg | 5.35 | 5.71 | |
| **噪声增量** | **−14.66** | −0.06 | ring 里多了 14.7 的高频 |
| **Laplacian 方差比** | **1147**（中位 172） | 1.37 | ring 高频能量是背景的 ~170 倍 |
| sat 差 | −1.11（std **17.6**） | +0.18 | 均值小、方差大 |
| val 差 | −5.25 | +1.20 | 系统性偏暗 |
| green 差 | −0.97（std 2.82） | +0.05 | 均值小 |
| 像素差 | 23.38 | 2.40 | |

**结论**：
1. 污染被 `soft_mask` 严格限制在 ring 内（outer 完全干净）→ 融合范围控制是对的。
2. 但 **ring 内被注入了大量高频颗粒/振铃**（噪声 +14.7、lapvar ×172），这才是"糊块"的物理主体；
   平均色偏只占很小一部分 —— 旧认知把"绿偏"当主因，方向偏了。
3. `out_E1_paste`（纯 alpha 合成、不过 ControlNet）同口径下 green +0.03 / sat 0.30 / 强绿占比 0.00
   → **颗粒全部来自 CN 重绘链路**，不是 alpha 合成本身。

对照 `measure_halo.py`（n=40）：`out_D` 强绿像素占比 0.15、污染像素 68.1%；
`out_E1_paste` 强绿占比 0.00、污染 14.3%。

## 3. 成因（代码层）

`_controlnet_repaint` 里：

```python
fp = int(max(2, min(int(feather_px), round(0.05 * float(actual_px)))))
soft_mask = cv2.GaussianBlur(dm_dilated / 255.0, (fk, fk), max(0.8, fp / 2.5))
final_crop = mask3 * cnet_crop + (1 - mask3) * crop_comp
```

三处叠加：

1. **CN 输出的颗粒**：`eff_steps = int(15 × 0.65) = 9`，少步去噪在 512² 平坦区留下明显颗粒。
2. **crop↔512 两次 LANCZOS 重采样振铃**：小目标时 `scale_crop = 512/短边` 可能达 **4×** 上采样，
   上采样用 `Image.LANCZOS`（D4 只把**下采样**改成了 `BILINEAR`，上采样**从未修**），
   回缩又用 `cv2.INTER_LANCZOS4` → 两次振铃叠加。
3. **羽化把上面的颗粒放进背景**：`soft_mask` 在 ring 上取 0.1~0.5，CN 的高频按这个权重漏出。

清点：LoRA **本体**（`drone_rgba` alpha>128 区域）并不偏灰绿 —— `diag_lora_color.py`（n=50）：
LoRA 生成前景 green −1.53 vs 无 LoRA −3.10 vs 真实背景 −2.69，且 green std 仅 1.21。
生成本体的问题是**偏暗偏蓝**（val 98.4 vs 真实 164.9，B 通道 97.96 为三通道最高）。
→ 「灰绿」不在 LoRA 权重上，在**融合带**。

## 4. 修复

### 4.1 管线内（已落地，可开关）

`lora_inpainter_v7.py` v7.4：融合前对 **mask 外**做「低频/高频分离 + 统计对齐」。
保留 CN 的低频（光照/色调过渡），高频换回原背景；再把该带的 (μ, σ) 对齐到背景。
**目标本体（mask 内）一像素不动**，因此 Det/IoU 应完全不变。

`cnet_f = where(crop_mask == 0, cand, cnet_f)`；开关 `BCD_HALO_FIX=0` 可关。

### 4.3 未采纳但已定位

- **上采样插值 LANCZOS → BILINEAR**（`init_resized` / `depth_resized` / `seg_resized`，比例 ≥2× 时）：
  与 D4 对称，能进一步减振铃，但会同时平滑**目标本体**，需单独 A/B，**本次未改**。

### 4.4 管线内首轮验证 → 发现两处不足 → 修正（10-07 00:30~）

重跑前先用 `harness.py --out _smoke_halofix --n 8 --seed 0`（约 2.5 min）做 GPU smoke，
`BCD_HALO_DEBUG=1` 打开运行期自检。**首轮结论：patch 执行了但几乎无效。**

自检输出：
```
[halo-debug] module=.../0-workspace/generator/lora_inpainter_v7.py enabled=True fp=5 band=2888
```
→ 模块路径正确（不是 `5-Controlnet/` 那份旧副本）、开关为真、band 非空。
但 `ring_noise_drop` 仍是 **−14.61**（基线 −14.66），等于没改。

**不足 ①：修补域太窄。** 原 `band = (dm_dilated > 0) & (crop_mask == 0)`，
`dm_dilated` 是 `fp=5` 核膨胀的结果 → 环宽只有 **2 px**；
而 `soft_mask = GaussianBlur(dm_dilated/255, (11,11), 2.0)` 的有效泄漏范围是 **±6 px**。
诊断口径的 ring 宽 5 px，**大部分落在 band 之外** → 那些像素仍带 CN 颗粒。离线脚本没有这个问题，
因为它的权重域是「两次高斯模糊的膨胀区」，天然更宽。

→ 改为
```python
band = (crop_mask == 0) & (soft_mask > 0.002)   # 覆盖 soft_mask 的全部有效泄漏范围
```
改后自检 `band=3810`（`sm_gt0=4441`，阈值只滤掉最外圈）。

**不足 ②：σ 偏小。** 管线内低频/高频分离用 `σ = max(1.0, fp*0.5)`，
`fp=5 → σ=2.5`，但 `cnet_crop` 是 512→crop 的 `INTER_LANCZOS4` 回缩结果，
**边缘振铃（周期 4~8 px）落在 σ=2.5 保留的频段里**，于是 cand 仍带环状中频 → ring 噪声降不下去。
（离线的输入是已融合的 `final_rgb.png`，振铃幅度相对小，所以 σ=2.5 在离线够用。）

→ 参数化并扫描：`σ = max(3.0, fp * BCD_HALO_SIGMA)`，扫描 `BCD_HALO_SIGMA ∈ {0.5, 1.0, 1.5, 2.0}`。

**修正 ① 后的中间结果（n=8，同一 seed）**：

|---|---|---|---|
| noise_drop | −14.66 | **−10.59** | −5.5 |
| lapvar 比 | 1147 | **375** | 253 |
| sat 差 | −1.11 | +0.37 | +1.31 |
| val 差 | −5.25 | +0.41 | −0.91 |
| green 差 | −0.97 | −0.30 | −0.10 |

## 4.5 A/B/C 三组逐样本配对复核（10-07 19:00 定稿）—— 推翻 4.4 的结论

同一批 16 个样本、`--seed 0`，三组诊断 JSON（`/tmp/v10_smoke_*_diag.json`）可逐样本配对。

配对胜率（B<A / C<A，n=16）：

| 指标 | B 胜率 | C 胜率 |
| --- | --- | --- |
| ring_noise_f | 8/16 = 50% | 8/16 = 50% |
| ring_lapvar_ratio | 7/16 = 44% | 6/16 = 38% |
| ring_sat_shift | 4/16 = 25% | 8/16 = 50% |
| ring_val_shift | 5/16 = 31% | 6/16 = 38% |
| ring_delta | 9/16 = 56% | **12/16 = 75%**（p≈0.038；对 6 指标 Bonferroni 校正后 0.23 → 不显著） |
| ring_noise_drop | 8/16 = 50% | 9/16 = 56% |

**结论（重要，纠正 §4.4）**

- §4.4 的判断「中位 lapvar 373 vs 基线 1147 → 改善 3.1×，patch 生效且有效」**不成立**。根因是**混用 mean 与 median 且跨批次比较**：本轮真配对下 A median = 266.8 / mean = 810.9，B median = 351.2 / mean = 1251.8 → **B 严格比 A 更差**，与 §4.4 叙述相反。
- **B（当前已发货的 σ=1.0 patch）在 n=16 配对下没有任何可靠改善证据**（`ring_noise_f` 胜率 50%、`ring_lapvar_ratio` 胜率 44%）。
- **C（HARD）唯一正向信号**是 `ring_delta` 75% 胜率，但多重比较校正后不显著。
- `ring_noise_f` 三组都停在 18–20，**对补丁不敏感**，不应作为判别指标；`ring_lapvar_ratio` 方差极大（p10≈4 / p90≈6000），n=16 统计力严重不足。
- **诚实表述**：n=16 下 A/B/C **无统计学显著差异**；需 n≥64 才有判别力。视觉对比见 `_reports/halo_abc_compare.png`（4576×5771，6 样本 × 3 组）。

**为什么 B 仍按原样保留**：B 的改动是单向的（mask 内改用 `soft_mask` 做 ControlNet 融合），mask 内像素不变 → 生成指标几乎不动，副作用局限在接缝带；C（HARD）在 mask 外做硬切换，引入新接缝风险，在证据不足时不做切换。

LoRA 增益由 +0.06 扩大到 **+0.11**（lora 0.690 vs nolora 0.580），方向与「E3 LoRA merged 的 IoU 略低于 disabled」相反 → 说明 IoU 与下游可检测性不是同一维度。out_D `R_any` 略降 3.3 点、`R_aerial` 0.557→0.507，但 IoU median 上升；COCO 预训练无 drone 类，该指标仅作 proxy（caveat 已在文中）。
