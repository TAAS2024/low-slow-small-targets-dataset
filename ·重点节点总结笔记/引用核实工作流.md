# 引用核实工作流（防假引用/防描述编造）

> 创建：2026-08-14 · 触发背景：2.1 章节发现 FLORA 描述编造、CFHA 虚构引用、InstaGen 作者错、DA-Fusion venue 错、段 87 六个方法描述几乎全部凭记忆写错。
> 铁律：**任何引用，无论多"熟悉"，新增或修改前必须走本流程，不得凭记忆填作者/年份/venue/机制描述。**

---

## 一、三个核实维度（缺一不可）

| 维度 | 核实内容 | 典型错误 |
|---|---|---|
| **① 存在性** | 论文/数据集真实存在 | 虚构引用（如 CFHA） |
| **② 条目准确** | 作者、标题、venue、年份、页码、arXiv ID | 第一作者写错（InstaGen）、venue 写错（DA-Fusion）、页码编造 |
| **③ 正文描述准确** | 正文对该方法的机制/贡献描述与原文摘要一致 | 把 A 方法的特点安到 B 头上（FLORA 被写成 inpainting+背景画布）、凭记忆编造细节（ODGEN 被写成 ResNet50 判别器） |

## 二、核实工具链（按顺序）

1. **OpenAlex**（最可靠，含摘要重建）：
   - 按 DOI 查：`https://api.openalex.org/works/https://doi.org/10.48550/arXiv.<id>`
   - 按标题搜：`https://api.openalex.org/works?search=<title>`
   - 摘要重建：`abstract_inverted_index` 反向索引 → 按 position 排序拼回
2. **DBLP**（venue/作者权威）：`https://dblp.org/search/publ/api?q=<title>&format=json`
3. **arXiv API**（确认会议 comment 字段）：`http://export.arxiv.org/api/query?id_list=<id>`
   - 注意：comment 字段会标注 "Accepted to CVPR 2024" 之类，用于确认 venue

## 三、标准流程（新增/修改引用时逐条执行）

```
1. 提取引用 → 记下标题 + 当前条目（作者/venue/年份/arXiv ID）
2. OpenAlex 查 → 对比标题/第一作者/年份（维度①②）
3. DBLP 查 → 对比 venue（维度②，DBLP 的 venue 比 OpenAlex 更准）
4. 读完整摘要 → 逐句核对正文描述（维度③，最关键）
5. 输出核实表 → 标注 ✅准确 / ⚠️偏差 / ❌错误 / 🚫虚构
```

## 五、教训与规则

1. **正文方法描述 = 摘要翻译，不是记忆复述。** 每个方法的一句话描述，必须能从摘要里找到依据。
2. **"like ours"、"与我们类似"这类表述 = 高危信号。** 出现即说明在往别人头上安自己的方案特点，必须回到摘要核对。
3. **venue 用 DBLP 确认，不用 OpenAlex。** OpenAlex 常把会议论文的 venue 标成 arXiv。
4. **页码（pp. xxxx–xxxx）若无法确认，宁可不写。** 编造页码 = 学术不端。
5. **重音符号**（Álvaro Patrício）不能丢，作者名按原文转录。
