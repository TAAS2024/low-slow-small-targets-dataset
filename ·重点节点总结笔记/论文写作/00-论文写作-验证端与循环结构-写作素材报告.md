## Part 1：验证端（§3.6 九阶段验证）写作素材

### 1.1 架构定位一句话

> 一个 Pipeline Step → 一个 Validator。九阶段验证链（V1–V9）直接挂载在 v7.2 生成管线每一步的输出上，失败码精确路由到出错模块 + 子步骤，无需中间翻译层。

**结构划分**：
- **V1–V5 输入端/中检**（5 个，在 GPU 推理前/中拦截，节省算力）
- **V6–V9 输出端终审**（4 个）

### 1.2 九阶段完整定义（论文可逐条引用）

| 阶段 | 挂载点 | 检查项数 | 方法 | 失败码前缀 | 状态 |
|:--|:--|:--|:--|:--|:--|
| **V1** | Agent 1 LLM 双 JSON | 5 | 纯规则（零 GPU） | `V1_SCHEMA_INCOMPLETE` / `V1_ENUM_INVALID` / `V1_LOGIC_CONFLICT` / `V1_TRAJ_INVALID` / `V1_CAMERA_INVALID` | ⏳ 待编码 |
| **V2** | Agent 2 背景匹配 | 3 | 规则 + CLIP（冻结） | `V2_SCENE_MISMATCH` / `V2_IMAGE_INVALID` / `V2_SEMANTIC_LOW` | ⏳ 待编码 |
| **V3** | Agent 3 深度/分割 | 4 | 规则 + 轻量统计 | `V3_DEPTH_INVALID` / `V3_SEG_EMPTY` / `V3_SEG_SKY_RATIO` / `V3_DEPTH_SEG_ALIGN` | ⏳ 待编码 |
| **V4** | Agent 3 LoRA 生成 | 4 | SSIM + 自相关 + 通道统计 | `V4_CONCEPT_BLEED` / `V4_TEXTURE_REPEAT` / `V4_COLOR_CAST` / `V4_DRONE_EMPTY` | ✅ 已编码 |
| **V5** | Agent 3 Focus 重定位 | 3 | 规则（坐标/尺寸） | `V5_POSITION_DRIFT` / `V5_SCALE_MISMATCH` / `V5_BBOX_OOB` | ⏳ 待编码 |
| **V6** | 输出-图像质量 | 1 主力 + 3 防御 | RGB: BRISQUE；IR: 三检（告警放行） | `V6_RGB_MISSING` / `V6_RGB_LOW_QUALITY` | ✅ 已编码 |
| **V7** | 输出-场景一致性 | 4 维 | 规则 + KL 散度 + IoU | D1 尺寸 / D2 光照 / D3 IR bbox / D4 跨模态 IoU | ✅ 已编码 |
| **V8** | 输出-轨迹连续性 | 4 物理规则 | 纯规则（不可绕过） | `POSITION_JUMP` / `SIZE_MUTATION` / `ACCELERATION` / `DIRECTION_TURN` | ✅ 已编码（反馈路由待更新） |
| **V9** | 输出-检测有效性 | 1 主力 + 1 对照 | YOLO + IoU（**v4 降级为记录**） | `V9_UNDETECTABLE` 等 | ✅ 已编码 |

**合计：9 阶段、29 项检查、5 待编码 / 4 已编码。**

### 1.3 V9 的 v4 定位（论文措辞关键）

V9 检测有效性在 v4 起**降级为轻量占位检查**：
- 不再作为「驱动 LoRA 微调的最重要信号」
- 只记录检测有效性，不训练下游检测器、不做 mAP
- 论文中 V9 应表述为「保留检测有效性记录以支撑 RQ4 的未来工作讨论」，而非「用 V9 信号训练生成器」

### 1.4 课程硬化三层机制（§3.7 的前置，也可归入 §3.6）

解决「Generator 变强但 Validator 原地不动 → 单向优化非对抗」问题：

| 层 | 机制 | 触发 | 成本 | 安全锚点 |
|:--|:--|:--|:--|:--|
| **L1** | 阈值自动递增（V2/V4/V6/V7 阈值 + 物理边界 + 回滚） | 通过率 >85–95% | 零（纯规则） | 预设物理边界 + 对齐/质量回滚 |
| **L2** | Hard-Negative 重校准（borderline >100 条 → 人工打标 → EfficientNet 增量微调） | borderline 堆积 | 低（增量微调） | 人工标注是唯一信号源 |
| **L3** | V_diversity 多样性惩罚（CLIP 特征 + FAISS 检索） | 每帧在线 | 极低（零训练） | CLIP 相似度客观度量 |

**回滚条件（v4）**：对齐精度/质量下降 > 1–2% 触发回滚（原为 mAP 下降，已替换）。

### 1.5 对齐精度评估（v4 新增核心模块，导师认可卖点）

> 自动产出像素对齐的 RGB+IR+Bbox 三元组，此模块专门验证这个对齐承诺，并作为闭环「独立对齐/质量裁判」的对齐精度输入。

| 评估维度 | 验证内容 | 指标 |
|:--|:--|:--|
| RGB↔Bbox | bbox 坐标 vs 实际目标位置 | 位置/尺度误差 |
| RGB↔IR | IR 确定性转换的像素级坐标一致性 | 坐标漂移（应为零漂移） |
| 三元组一致性 | RGB/IR/Bbox 三者联合 | IoU + 坐标误差 |

**定位**：独立于 V1–V9 验证链，是闭环裁判的对齐精度信号源 + 论文核心卖点的数据来源。对应任务清单 v4 模块四（4.1–4.5）。

## Part 2：循环结构（§3.7 闭环反馈）写作素材

### 2.1 核心叙事（Phase 4 论文叙事，可直接改写）

> 命名：**CDFF (Closed-loop Data Flywheel Framework)** — 闭环数据飞轮框架。
>
> 现代合成数据生成管线的核心瓶颈：固定模型在分布边缘反复失败，无法自我改进。
>
> CDFF 的答案（五步）：
> 1. 九阶段验证链识别失败模式（what fails）
> 2. 结构化失败日志归档失败样本（where it fails）
> 3. 异步学习循环将失败反馈转化为增量微调（fix it）
> 4. Generator-Validator 对抗隔离防止过拟合（stay safe）
> 5. 新权重替换旧权重，下一轮生成质量自动提升（continuous improvement）

**与现有工作的关键区别**：
- ODGEN/FLORA/InstaGen：生成 → 过滤 → 训练 → 结束（单向流水线）
- CDFF：生成 → 验证 → 反馈 → 学习 → 再生成（闭环飞轮）
- CDFF 闭环受 **V8 物理规则 + 人工校准 + 独立对齐/质量裁判** 三重锚定

### 2.2 失败码 → 模块路由表（核心差异化）

| 失败 | 责任组件 | 反馈目标 | 修复手段 |
|:--|:--|:--|:--|
| V1 JSON 自洽 | Agent 1 (LLM) | Agent 1 | 失败字段 + 矛盾描述 → LLM 纠正 prompt 重新生成 |
| V2 背景匹配 | Agent 2 | Agent 2 | 下一候选背景（最多 3 fallback） |
| V3 深度/分割 | Agent 3 Step 1 | Agent 3 Step 1 | 调参或换背景重提取 |
| V4 LoRA artifact | Agent 3 Step 2 | Agent 3 LoRA | 调 seed/CFG 重生成 → 积累负样本 → LoRA 微调 |
| V5 Focus 偏移 | Agent 3 Step 5 | Agent 3 Step 5 | 重新计算偏移矩阵 |
| V6 图像质量 | Agent 3 Step 2 | Agent 3 LoRA | 调参重生成 → 积累 → LoRA 微调 |
| V7 尺寸/光照 | Agent 1 + Agent 3 | 需诊断 | 人工判断 JSON 参数 vs CN 渲染 |
| V8 位置/尺寸 | Agent 1 (LLM) | Agent 1 | 重新生成轨迹参数 |
| V8 加速度/方向 | Agent 1 (LLM) | Agent 1 | ① LLM 负样本学习 ② 补帧插值平滑 |
| V9 检测不到 | Agent 3 Step 2 | Agent 3 LoRA | **负样本记录（v4：不驱动微调）** |

### 2.3 三 Buffer + 阈值（异步学习）

| Buffer | 来源失败码 | 阈值 | 触发动作 |
|:--|:--|:--|:--|
| LoRA-Buffer | V4 + V6（v4 起移除 V9） | 50 条 | Agent 3 LoRA 增量微调 |
| CN-Buffer | V3 + V7 | 30 条 | Agent 3 CN-LoRA 对比微调 |
| LLM-Buffer | V1 + V8 | 20 条 | Agent 1 LLM 提示词优化 |
| 🆕 Borderline Pool | V2/V4/V6/V7 borderline | 100 条 | 触发人工审核 → L2 重校准 |

### 2.4 三种自训练范式

| 范式 | 逻辑 | 适用组件 |
|:--|:--|:--|
| **A. 正样本筛选** | 通过 → 入训练集 → 标准微调 | LoRA 风格微调 |
| **B. 失败引导重生成 + 对比学习** | 失败 vs 修复对比对 → 对比/DPO 微调 | ControlNet、LLM 轨迹学习 |
| **C. 质量排序** | 生成 N 张 → 打分排序 → top-k 微调 | LoRA 质量提升 |

### 2.5 对抗隔离五规则（防 reward hacking 的核心贡献）

1. **Validator 绝不从 Generator 输出中自动学习**（只从人工标注数据更新）
2. **Validator 更新频率远低于 Generator**
3. **V8 物理规则永不可训**（绝对锚点，但修复手段可扩展为 LLM 学习 + 补帧）
4. **独立对齐/质量裁判做最终裁决**（对齐精度 + 生成质量 + 多样性）
5. **人工始终在环中**（Validator 每次更新必须人工确认）

### 2.6 三重外部硬锚点（防 Goodhart's Law）

| 锚点 | 防什么 | 实现 |
|:--|:--|:--|
| V8 物理规则 | Generator 生成不物理的轨迹骗过视觉检查 | 纯物理公式，无学习参数 |
| 独立对齐/质量裁判 | 闭环在 easy mode 自嗨 | 与生成管线隔离，只做对齐精度+质量+多样性裁决 |
| 定期人工抽样 | 自动化指标全绿但图不对劲 | 每 N 轮抽 50 帧人工打分 |

**关键结论（论文 Discussion 金句）**：对抗训练自动处理 80% 已知问题，剩余 20%（标准漂移、未知失败模式、方向性判断）靠三重锚点兜底。ODGEN/FLORA/InstaGen 不做闭环不是因为技术做不到，而是闭环的锚点设计成本和人工监控成本超过单向流水线收益。CDFF 证明闭环净收益的唯一方式是三重锚点足够扎实 + 实验数据证明「有闭环的对齐精度/质量/多样性增益 > 无闭环」。

### 2.7 创新定位（诚实声明）

审查端单个模块都不是创新（BRISQUE/KL/IoU/物理规则/COCO eval 都有成熟参考）。创新在**整体系统设计**：
1. 九阶段串联架构（短路求值）
2. 输入端预校验 V1–V5（GPU 推理前拦截省算力）
3. 对抗隔离约束（五规则）
4. 课程学习路径（五阶段渐进 + 逐阶段验证标准）
5. 反馈闭环路由（失败码 → 责任定位 → 精确微调）

## Part 3：课程学习路径（§3.7 或 Discussion 可用）

五阶段渐进课程（每阶段设 V 级通过率标准，不通过不进下一阶段）：

| 阶段 | 内容 | 学会 | 标准 |
|:--|:--|:--|:--|
| 1 | 近距离 + 简单背景 + 正面 | 无人机基本外观/轮廓 | V6 >90%, V9 >80% |
| 2 | 拉远距离 + 变换角度 | 尺度不变性、姿态多样性 | V7 尺寸 >85%, V9 远距 >60% |
| 3 | 复杂背景（城市/山林/海面） | 空间关系、遮挡边界 | V7 光照 >80%, V6 背景 >85% |
| 4 | 连续运动序列 | 帧间一致性、运动模糊 | V8 轨迹 >95% |
| 5 | 极端条件（低光/雾/小目标/遮挡） | 边缘情况鲁棒性 | 全 V 级综合 >70% |

> 作用：让学习方向可追溯——知道模型在哪一步掉队，而非对着最终分数猜原因。
