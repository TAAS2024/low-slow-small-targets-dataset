# 1. 诚实性检查：5 处必须改（+1 处措辞）

## H1（最严重）Anchor 5「省算力」与实测相反

| 项 | 内容 |
|---|---|
| 位置 | §4.5.7 para 217；§4.5.5「Negative findings」para 191 |
| 原文 | 「curriculum hardening reduces the attempts required per cycle from 180 to between 170 and 180 while holding target achievement near 0.72, **which is the clearest efficiency effect observed in the loop**」；「curriculum hardening **buys generation efficiency** rather than acceptance」 |
| 实测（v15 复算） | attempts 720 → 704（**−2.2%**），但生成总耗时 **12,854.4 s → 14,596.0 s（+13.5%）**，每尝试 17.28 s → 19.43 s。A3 的逐轮 pass_rate 与 A2 **逐轮同值**。 |
| 判定 | 尝试数微降、墙钟更差 → **不能称 efficiency**，这是本文最容易被抓的"结论强于数据" |
| 建议改法 | 「Curriculum hardening trims the attempt count slightly (704 vs 720) while holding target achievement near 0.72, but it does not buy wall-clock efficiency: generation time rises from 12,854 s to 14,596 s (+13.5%) and per-round pass rates are identical to A2 (Table 6). We therefore report it as a marginal attempt saving with no measurable throughput gain.」 |

## H2 V9 的「IoU 0.25」= 把 conf 阈值写成了 IoU 阈值

| 项 | 内容 |
|---|---|
| 位置 | §3.6.2 para 116（"nominal IoU threshold of 0.25"）、§4.4 para 186（"at IoU >= 0.25"）、A.2 表 V9 行（"detection recall at a nominal IoU ≥ 0.25"）、Table 9 文字（imgsz 960） |
| 实现 | `v9_detection_validator.py`：`iou_thr=0.5`、`conf_thr=0.25`；`self.model(image, conf=...)` **未传 imgsz → 640**；闭环链路显式用 `yolov8x.pt`（`experiments/bcd/loop_driver.py:189`），`6-Validator` 独立 config 的 `yolov8n.pt` 只是占位 |
| 落地自证 | `failure_log.jsonl` 里 S9 失败串为 `S9_UNDETECTABLE (1/1 GT missed, IoU thr=0.5)` |
| 建议改法 | 三处统一：「a COCO-pretrained YOLOv8x at confidence 0.25 with a 0.5 IoU criterion for GT recall, input 640」 |

## H3 V8「90°/frame」与实现 45° 不符

- 位置：§4.4 para 185「angular turns exceeding **90 degrees per frame**」。
- 实现：`v8_trajectory_validator.py:204` `theta_max: float = 45.0`（`s8_config.json` 亦为 45.0）。
- 改法：`exceeding 45 degrees per frame`。

## H4 V2 的「CLIP 语义对齐」在代码里不存在（唯一"描述了不存在的机制"）

- 位置：§3.6.1 para 105、§4.4 para 178、A.2 表 V2 行。
- 事实：`6-Validator/` 与 `0-workspace/` 全文检索 `clip` **0 命中**；背景检索 `app/background_searcher.py` 用的是 **元数据匹配**（category / time_of_day / weather，来自 `curated_backgrounds/*/_metadata.jsonl`），不是 CLIP。代码里 V2（`v2_transformer_validator.py`）实际做的是 bbox 越界 / 尺寸突变 `size_delta_threshold=0.3` / 深度有效性 `depth_diff_threshold=0.1` / 位置连续 / seg 非空。
- 改法（推荐）：把 V2 描述改为「metadata-based scene matching (category, time of day, weather) plus blank/corrupt frame detection, and structural consistency of the parsed geometry (size-delta 0.30, depth-diff 0.10)」，A.2 的 V2 行同步换掉，删掉 CLIP 一词。

## H5 「V1–V9 reliably identify…」与自陈的定性证据矛盾

- 位置：§4.4 para 187「These tests confirm that stages V1 to V9 **reliably** identify structural, photometric and kinematic defects…」
- 矛盾：同一节 para 175 已写「inspected **qualitatively rather than counted**, so **no per-stage detection rate is reported**」。
- 改法：「…each stage flagged its designated fault class in the engineered cases and short-circuit execution behaved as specified; no per-stage detection rate is claimed (Section 4.4).」

## H6（措辞越界）「false-acceptance rate 降低 79.0%」需要一个不存在的 ground truth

- 位置：§4.4 para 188。算术自洽（(0.884−0.185)/0.884 = 79.1%），但「false acceptance」隐含「staged chain = 真值」。
- 事实：对照组只是 BRISQUE ≤ 45，实验组是 V6–V9；而 V6–V9 的拒绝主要由 V9（检测器看不见）驱动（A1 失败里 S9 占 70.6%）。→ 这个 79% 很大程度是**机械结果**，不能读作质量提升。
- 改法：「the staged chain rejects 81.5% of the composites the calibrated scalar filter accepts; because the dominant rejection code is detector-invisibility (Section 4.5.7), we read this as a difference in what the two filters measure rather than as a validated reduction in defect rate.」

# 4. 最后一个问题：能不能直接训一个 bbox 定位模型 + 实拍验证？

## 4.1 已经做完的部分（训练侧，成本可忽略）

| 项 | 值 |
|---|---|
| 臂 | G0（纯负样本）/ G2（硬粘贴合成）/ G3（CDFF 全流程）/ G4（CDFF 去 ControlNet） |
| 每臂训练图 | 100 合成 + 200 真实背景负样本 = 300（G0 = 200） |
| 模型 / 输入 / 轮数 | YOLOv8n（COCO 初始化）/ imgsz 960 / 60 epoch / batch 8 |
| 单 run 耗时 | **540 s（9 min，8 GB GPU）**；8 runs ≈ 1.2 h |
| 测试集 | 150 张 held-out 真实背景 **+ 粘贴 sprite**（50% 硬剪切 / 50% CDFF 剪切），300 实例，tiny 123（0.41） |
| mAP@0.5 | 0.845 / 0.799 / 0.855（G2/G3/G4），G0 = 0.000 |
| AP50-tiny | 0.638 / 0.572 / 0.686 |
| 结论 | **臂间不可分**（CI 半宽 0.02–0.07，seed 间 spread ≤ 0.036） |

→ 「从我们数据集训练一个全新 bbox 模型」这件事**技术上已经做过**，而且很便宜：全量 2,000 帧（200 组 × 10 帧）也只是一小时级。

## 4.2 没做的部分：真实飞行影像验证 —— 缺的是数据，不是模型

本轮实测的本地实况：

| 位置 | 内容 | 有无 bbox |
|---|---|---|
| `0-database/kohya_dataset` | 1,313 图（98 无人机 + 49 口袋机 + 576 红外背景 + 590 RGB 背景）+ **1,314 个 .txt 全是 BLIP caption** | ❌ README 自陈来源 Unsplash/Pexels/Pixabay |
| `0-database/11_drone_clean` | 254 图（1280×853 等图库尺寸） | ❌ 无标注文件 |

| 视频 | 全项目 **0 个 mp4/avi** | — |
| 公开集 | `1-background-pool/extract_antiuav_rgb.sh` 指向 `0-database/Anti-UAV-RGBT`；全盘 `gsearch Anti-UAV` **0 命中** → 当年抽完背景即删除，标注没留 |

**结论：本地不存在任何"带人工框的真实无人机飞行影像"。**

## 4.3 「难不难」拆解

| 环节 | 难度 | 成本 |
|---|---|---|
| 训模型（YOLOv8n 8 臂） | 极低 | 1.2 h GPU（已跑过） |
| 素材获取 | **高** | 要么自己拍（手机/无人机跟拍 ≥30 s，含远距 tiny 目标），要么重下 Anti-UAV410（红外单模）/ RGBT / DroneMMset 并接受其模态与框口径噪声 |
| 人工标注 | 中 | 150–300 帧 × 10–20 s ≈ **1–2 h**（tiny <30 px 需放大框）；双人复核 ×2 |
| 统计功效 | 中 | 分辨 0.02 mAP 需数百张 held-out（v15 功效分析同结论） |
| 结果风险 | **高** | 合成→实拍域偏移，很可能 mAP 掉到 0.3–0.5 的负结果 |

## 4.4 明确回答

- **不是「已经做完了」**。已完成的是「生成器 → COCO 检测器」的**可行性探针**（合成复合测试集 + 同族检测器），按论文自己在 Table 9 Note 里写的两条协议约束**都不合格**。
- 若要真正完成 Table 9：缺 **① 真实带框测试集 ② 非 YOLO 族检测器（RT-DETR / TPH-YOLOv5）**。
- 但按导师"小论文不做下游 mAP"的定位，**更划算的是不做**：把 §4.6 缩成一节"为什么不做"，把 v15 探针作为附录说明。这样既省 1–2 周，也不引入负结果。
