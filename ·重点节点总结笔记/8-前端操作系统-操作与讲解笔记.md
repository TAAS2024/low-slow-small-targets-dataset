## 1. 讲解篇 — 它是什么、在哪一层

### 1.1 在整机架构中的位置

CDFF 是**双 Agent + 有界反馈环**结构。前端**只覆盖生成端（Generator，M1–M6）**，验证端（Validator，V1–V9）与循环机制**没有接入界面**。

```
                    ┌──────────── 前端只到这里 ────────────┐
自然语言 ──► M1 语义解析 ──► M2 背景检索 ──► M3 条件派生 ──► M4 LoRA 生成 ──► M5 ControlNet 重绘 ──► M6 RGB→IR
             (llm_parser)   (background_    (condition_      (lora_inpainter_v7)         (rgb2ir_converter)
                             searcher)       generator_v7)
                    └──────────────────────┘
                              │  pixel-aligned RGB–IR pair + bbox
                              ▼
                    V1–V9 九段验证链 ──► 失败码 ──► 三缓冲 ▸ 有界拒绝-重采环
                    ✗ 前端无入口，只能命令行跑
```

🔴 **必须记住的三件事**：

1. `web_app.py` **从不 import `ValidatorPipeline`**。界面上看到的十张图是**未经九段验证**的原始产物，不能直接当论文口径数据集用。
2. 论文里的 **300 对基准（`experiments/bcd/out_D/`）不是从这个界面点出来的**，是 `run_all_cb.sh` 批处理驱动的。
3. 因此前端的正确身份是 **生成端演示台 / 调试台 / 导师演示工具**，不是数据集产出流水线。

### 2.2 标准操作流程（手把手）

**步骤 ①：选后端**
右栏顶部下拉框：`DeepSeek`（默认）｜`OpenAI (GPT-4o)`｜`Claude`｜`Dry-Run (离线)`。
→ Dry-Run 不联网，用于无 Key 时验证界面链路。

**步骤 ②：写场景描述**
输入框 `描述无人机场景…`，或直接点 4 个示例标签快速填入：

| 标签 | 文本 |
|:--|:--|
| 🏙️ 城市仰拍 | 阴天下午，城市高楼背景，从下方仰拍 |
| 🌲 森林迷雾 | 雾天黎明，森林上空盘旋，距离约100米，侧面拍摄 |
| 🏜️ 沙漠飞近 | 大晴天上午，沙漠地带，四旋翼从100米远处飞近到50米 |
| 🏠 雪景住宅 | 雪天黄昏，住宅区，横向移动从左侧飞到右侧，俯拍 |

**写法要点**：把 LLM 能抽的字段说全 → **场景类型 + 时间 + 天气 + 相机方位 + 动作 + 距离**。
缺字段会被自动兜底并记进 `meta.default_fills`（例如 `trajectory.action=hover`、`trajectory.distance=75.0m`）。

**步骤 ③：生成**
按 `Enter` 或点「一键生成 →」。按钮会变成 `一键生成中…（约 50 秒）` 并禁用。
→ 后端在一个请求里串完：LLM 解析 → 搜背景 → 复制背景到 `output_images` → **跑完整 v7 管线（但默认跳过 CN 重绘）** → 建会话。
→ 首次运行要冷加载 MiDaS + SD1.5 + 双 ControlNet + rembg，**可能等 1–3 分钟**。

**步骤 ④：读双 JSON**
右栏两个 JSON 高亮面板：

| 面板 | 内容 | 下游 |
|:--|:--|:--|
| 📦 `background_spec` | `scene_type` / `time_of_day` / `weather` / `camera_position` | → M2 背景匹配 |
| 📦 `full_scene_spec` | `trajectory[]`（t / action / distance / norm_u / norm_v）+ `background` + `camera` + `meta` | → M3–M6 全管线 |

**步骤 ⑤：看十格产物**
中栏刷出十格图。多帧槽位右下角显示 `i/N`，用 `◂ ▸` 翻帧。详见 §2.4 槽位表。

**步骤 ⑥：调位置与尺寸 → 🎯 Focus**
1. 背景格（`bg`）上有一个**红点标记** = 无人机落点，拖拽移动；
2. 红点下方**比例尺滑块**（0.03–0.50，步长 0.01，默认 0.15）调目标大小，旁边数字实时显示；
3. 点 🎯 → 调 `POST /api/focus_drone/<sid>`；
4. 只重算 `drone_depth` / `drone_seg` / `final_rgb` / `bbox` / `ir` 五格，**跳过** MiDaS、分割、LoRA 生成、rembg 抠图 → 秒级响应；
5. 响应带回 `nu` / `nv` / `target_px` / `dval`，可核对换算是否合理。

> 红点视觉尺寸 = `8 + scale × 48` px（scale 0.03 → 9 px；0.50 → 32 px）。
> 拖拽走 document 级 `mousedown/mousemove/mouseup`，坐标经 `containerPosToImagePct()` 换算成**图片百分比**，因此可以避开 letterbox 留白，比容器百分比更准。

**步骤 ⑦：单格重置 ↻**
鼠标 hover 到任意格，右上角出现橙色 ↻。点击 → `POST /api/regenerate/<sid>` → 该格**及其全部下游**重算（级联表见 §2.5）。图片 URL 自动带 `?t=<timestamp>` 强制刷新，不会看到旧图。

**步骤 ⑧：放大查看**
点任意格右上角 ⤢ → 全屏放大视图：左侧大图 + 右侧缩略条，`◂ ▸` 切帧，`Esc` 或「← 返回网格」退出。
放大视图里**同样带红点 + 滑块 + 🎯**，所以精细调位置建议在放大视图里做。

**步骤 ⑨：关服务**
页面右上角固定 ✕ → 确认弹窗 → `POST /api/shutdown` → 后端 `SIGTERM` 自杀，页面显示「服务已关闭，请关闭此页面。」

### 2.3 M2 背景检索的真实行为

| 项 | 事实 |
|:--|:--|
| 图库根 | `1-background-pool/curated_backgrounds/` |
| 真实目录（9 类） | `airfield` `coastal` `desert` `forest` `industrial` `mountain` `pure_sky` `rural` `urban` |
| 选择方式 | 在目标目录里 `random.choice()` 抽一张，**不按时间/天气/相机方位筛** |
| 落盘 | 复制为 `output_images/session_<sid>_bg.<ext>` |
| fallback 规则 | `night_city → urban`；`residential → rural`；`snow → mountain` |
| 缺省 | `scene_type` 缺失 → `pure_sky` |

🔴 **重要认知**：`time_of_day` / `weather` / `camera_position` 三个字段**不参与背景筛选**，只写进 spec 供后续环节使用。所以「雪天黄昏」实际拿到的很可能是一张 `mountain` 目录里的普通山景。要真正可控，需要给背景池补元数据索引——这是当前已知的能力缺口。

### 2.4 十格槽位说明书

| 行·列 | 槽位 key | 中文名 | 帧数 | 来源模块 |
|:--|:--|:--|:--|:--|
| 1·1 | `bg` | 背景图 | 单帧 | M2 |
| 1·2 | `bg_depth` | 背景深度图 | 单帧 | M3 · MiDaS |
| 1·3 | `bg_seg` | 背景 Seg | 单帧 | M3 · heuristic_segment |
| 1·4 | `drone_raw` | LoRA 生成（备选） | 多帧 | M4 · txt2img |
| 1·5 | `drone_clean` | LoRA 抠图（备选） | 多帧 | M4 · rembg + dilate |
| 2·1 | `drone_depth` | 无人机深度图 | 多帧 | M3 标记注入 |
| 2·2 | `drone_seg` | 无人机 Seg 图 | 多帧 | M3 标记注入 |
| 2·3 | `final_rgb` | 最终 RGB（合成+重绘） | 多帧 | M5 合成 |
| 2·4 | `bbox` | BBox 标注 | 多帧 | M5 提取 |
| 2·5 | `ir` | 白热红外图 | 多帧 | M6 `rgb_to_whitehot` |

> 修图顺序建议：先看 `bg` 是否合理 → 再看 `drone_raw` 外观 → 再看 `final_rgb` 融合 → 最后核 `bbox`。

### 2.5 重置级联表（`downstream_map` 原样）

| 触发槽位 | 连带重算的下游 |
|:--|:--|
| `bg` | bg, bg_depth, bg_seg, drone_depth, drone_seg, final_rgb, ir, bbox（**并重新随机抽一张背景**） |
| `bg_depth` | bg_depth, drone_depth, drone_seg, final_rgb, ir, bbox |
| `bg_seg` | bg_seg, drone_depth, drone_seg, final_rgb, ir, bbox |
| `drone_raw` | drone_raw, drone_clean, drone_depth, drone_seg, final_rgb, ir, bbox |
| `drone_clean` | drone_clean, drone_depth, drone_seg, final_rgb, ir, bbox |
| `drone_depth` | drone_depth, final_rgb, ir, bbox |
| `drone_seg` | drone_seg, final_rgb, ir, bbox |
| `final_rgb` | final_rgb, ir, bbox |
| `ir` | ir |
| `bbox` | bbox |

> ⚠️ 实现细节：`/api/regenerate` 实际是**整条管线重跑一遍**再回填，而不是只算下游子集。所以「重置 ir」和「重置 bg」在服务器上耗时相同。"只算子集" 的优化**只在 🎯 Focus 里实现了**。

### 2.6 Focus 坐标换算（前端 → 后端）

| 前端值 | 后端量 | 公式 |
|:--|:--|:--|
| `dronePos.x`（0–100 %） | `nu`（归一化横坐标） | `x / 100` |
| `dronePos.y`（0–100 %） | `nv`（归一化纵坐标） | `y / 100` |
| `droneScale`（0.03–0.50） | `target_px`（目标像素尺度） | `clip(scale × 192, 12, 96)` |
| `droneScale`（0.03–0.50） | `dval`（归一化深度） | `clip(scale × 1.4, 0.15, 0.7)` |

**Focus 与首次生成的管线差异**：

| 步骤 | 首次生成 | 🎯 Focus |
|:--|:--|:--|
| MiDaS → bg_depth | ✅ | ❌ 复用 |
| heuristic_segment → bg_seg | ✅ | ❌ 复用 |
| LoRA txt2img → drone_raw | ✅ | ❌ 复用 drone_rgba |
| rembg + dilate → drone_clean | ✅ | ❌ 复用 drone_rgba |
| 轮廓注入 depth/seg | ✅ | ✅（新位置） |
| Alpha 合成 | ✅ | ✅（新位置） |
| ControlNet 重绘 | 可选 | 可选 |
| RGB→IR | ✅ | ✅ |
| bbox 提取 | ✅ | ✅ |

### 2.7 种子机制

```python
gen_seed   = int(time.time_ns() / 1000 + fi * 777) % (2 ** 31)
blend_seed = gen_seed + 100_000     # fi = 帧索引
```

微秒级时钟 + 帧偏移 → 跨请求、跨帧 seed 不重复；前端图片 URL 带 `?t=` 做 cache-busting。
⚠️ `condition_generator` 内部用 `time_ns` 且**不回传**，所以「锁定无人机外观」要靠包装层 `override_gen_seed` 强制覆写——这是同组多点位生成与配对消融的基础，界面上没有这个开关。

### 3.2 常用 curl

```bash
# 一键生成（走 skip_cnet 路径，与界面按钮等价）
curl -X POST http://127.0.0.1:5000/api/parse \
  -H 'Content-Type: application/json' \
  -d '{"text":"雾天黎明，森林上空盘旋，距离约100米，侧面拍摄","backend":"deepseek"}'

# 🔥 跑完整管线（含双条件 ControlNet 重绘）——界面上没有这个按钮
curl -X POST http://127.0.0.1:5000/api/generate-lora/0

# 🎯 重定位
curl -X POST http://127.0.0.1:5000/api/focus_drone/0 \
  -H 'Content-Type: application/json' \
  -d '{"dronePos":{"x":35,"y":22},"droneScale":0.08}'
```

🔴 **最关键的一条操作知识**：`/api/parse`、`/api/regenerate`、`/api/focus_drone` 三个都**硬编码 `skip_cnet=True`**（源码注释：「暂时跳过 ControlNet 重绘」）。界面上点出来的图**都是没做 ControlNet 重绘的版本**。要产出论文口径（双条件 CN 0.85）的图，必须直接调 `/api/generate-lora/<sid>`。

## 4. 数据集与产物总账（前端视角）

搞清「哪份文件属于哪一环」是这套系统最容易混乱的地方，这里一次性对齐。

| 环节 | 路径 | 内容 | 性质 |
|:--|:--|:--|:--|
| 背景池 | `1-background-pool/curated_backgrounds/{九类}/` | 37,852 张（论文口径；磁盘实测 38,872） | 输入资产，只用不写 |

| LoRA 权重 | `2-Lora training/best_models/drn3_pocket_uav_v3_step2000.safetensors` | rank-8, α4, 3000 步，取 step-2000 | 模型资产 |
| **前端落盘** | `3-LLM starter/output_images/session_<sid>_<slot>_<i>.png` | **人工调试截图**，当前已积累 **14,260 个文件** | ⚠️ 非论文口径 |
| **论文数据集** | `experiments/bcd/out_D/samples/d0000 … d0299/` | 300 对，每样本 8 个 PNG | ✅ 论文口径 |
| 数据集索引 | `experiments/bcd/out_D/manifest.json` | `schema_version` / `background_pool_size` / `generator{}` / `samples[]` | 元数据 |
| 评测汇总 | `experiments/bcd/out_D_eval/summary.json` | 嵌套结构：`summary.alignment.pos_err_px.mean` 等 | ⚠️ 扁平读会全 None |
| 下游代理 | `experiments/bcd/out_downstream/downstream.json` | 以目录名为键的**扁平 dict** | 论文主口径 `--conf 0.25` |
| 融合实验 | `experiments/bcd/out_fusion_e1e4/fusion.json` | BGE / RLJ / LCR + Wilcoxon | — |
| 实验报告 | `experiments/bcd/RESULTS.md` | 全部 E/B 组数值 | — |

**一句话区分**：`3-LLM starter/output_images/` = 用界面手点出来的**调试截图**；`experiments/bcd/out_D/` = 走批处理、经九段验证的**论文数据集**。两者不可混用。

**前端目录命名规则**（做数据清洗时按这个解析）：

```
session_<sid>_<slot>_<frameIdx>.<ext>
   e.g. session_100000_final_rgb_0.png     → 会话 100000，第 0 帧的最终 RGB
        session_100000_bg.png              → 背景图（单帧，无 frameIdx）
   slot ∈ { bg, bg_depth, bg_seg, drone_raw, drone_clean, drone_depth,
            drone_seg, final_rgb, ir, bbox, drone_rgba }
```

> 注：`drone_rgba` 也落盘（不显示在界面上），是 🎯 Focus 复用的素材来源。归档 web_app 用 `IMAGE_DIR.glob(f"session_{sid}_drone_rgba_*.png")` 取第一帧。

## 6. 已知坑与排查手册

### 6.1 🔴 点左侧 Demo 卡片会抛 TypeError

- **现象**：点 `🏙️ 城市阴天仰拍` 等 Demo，JSON 面板正常刷新，但浏览器控制台报 `Cannot read properties of null (reading 'style')`。
- **原因**：`selectDemo()` 第 1428 行无条件执行 `document.getElementById('btn-gen-cond').style.display = 'none'`，而 **`btn-gen-cond` 这个元素在 HTML 里已不存在**（原「生成条件图」按钮已随旧端点 `/api/generate-conditions` 一并移除，但 JS 引用残留）。
- **影响**：Demo 的 JSON 与网格渲染**在报错之前已完成**（`loadDemo()` 先执行），所以肉眼影响很小，但功能是断的。
- **临时修法**：给该行加空值保护

  ```javascript
  const b = document.getElementById('btn-gen-cond');
  if (b) b.style.display = 'none';
  ```

- 同源问题：第 1517 行 `genBtn.style.display = ...` 有同样空引用，但被外层 `catch(e) { /* ignore */ }` 吞掉，**静默失效**。

### 6.2 找不到「生成条件图」按钮

不是故障，是**功能被移除了**。条件图（bg_depth / bg_seg）现在由 `/api/parse` 一次性产出。若确实想单独只跑条件图，用原项目版本的 `/api/generate-conditions/<sid>`。

### 6.3 界面生成的图与论文里不一样

因为界面走的是 `skip_cnet=True`。想复现论文效果：`curl -X POST http://127.0.0.1:5000/api/generate-lora/<sid>`。

### 6.4 报「背景图搜索失败: 目录不存在」

检查 `1-background-pool/curated_backgrounds/<场景目录>/` 是否有 `.jpg/.jpeg/.png`。常见诱因：
- 场景名不在 9 类之内且没命中 fallback；
- `pure_sky` 目录被误写为 `puresky`；
- 数据盘未挂载。

### 6.5 🟠 在归档目录 `0-workspace/app/` 里启动会失败

`0-workspace/` 只软链了 `0-model` 与 `2-Lora training`，**缺 `1-background-pool`**。而 `background_searcher.POOL_ROOT` 解析为 `0-workspace/1-background-pool/curated_backgrounds` → 不存在 → 直接报错。补上即可：

```bash
cd "<项目根>/0-workspace"
ln -s ../1-background-pool 1-background-pool
```

（或者乾脆只在原项目 `3-LLM starter/` 里运行。）

### 6.6 模型卡死 / 显存不足

- 确认 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1` 已设；
- ❌ **绝不可**手动执行 `inp.pipe_cnet_nolora.to("cpu")` 之类的搬迁——会触发第二次权重搬运而卡死；
- 加载期峰值问题已在代码层用「惰性构建第二份干净 UNet」修好（7524 MiB 卡死 → 4552/8188 MiB 正常），不要再回退这段改动。

### 6.7 `FLASK_DEBUG=true` 导致显存翻倍

Flask 热重载会 fork 出第二个进程 → 模型被加载两次。演示/生产务必 `false`。

### 6.8 会话记录重启即清空

`sessions: list[dict]` 是**进程内内存变量**，没有任何持久化。重启后左栏只剩 5 条内置 Demo。
好消息：`output_images/` 里的图片文件仍在，可凭 `session_<sid>_` 前缀手工回溯。

### 6.9 `output_images/` 已积累 14,260 个文件

长期手点会持续堆积。清理建议（保留最近 N 天）：

```bash
cd "<项目根>/3-LLM starter/output_images"
# 先看占用
du -sh .
# 按 session 前缀粗筛（示例：删掉 session_99999 及更早的手工会话）
ls | grep -oE 'session_[0-9]+' | sort -u | head -50
```

### 6.10 端口被占用

```
OSError: [Errno 98] Address already in use
```
→ `FLASK_PORT=5001 python web_app.py`，或先 `pkill -f web_app.py`。

### 6.11 图片不刷新 / 看到旧图

已在设计上规避（URL 带 `?t=<timestamp>`）。若仍异常，硬刷新 `Ctrl+Shift+R`。另外左栏 10 s 轮询会重绘网格，切帧位置可能被重置。

### 6.12 10 s 轮询的副作用

`setInterval(loadSessions, 10000)` 每 10 秒重建左栏列表 DOM（`renderSessionList` 用 `innerHTML` 整体覆写）。后果：

- 会话列表**滚动位置会被重置**，长列表时体验略糟；
- 该轮询**不会**触发 §6.1 的报错（报错只在点击 Demo 时由 `selectDemo` 抛出）；
- 正在生成的会话期间列表会自动出现新条目，属正常行为。

### 6.13 切换会话后网格清空

`selectSession()` → `loadSessionDetail()` → `renderImageGrid(s.images || {})`。若某条会话当时生成失败（例如 `ImportError`），`images` 里**只有 `bg`** 一张，其余九格为空 → 这不是 bug，是当次生成没跑完。查后端日志确认。

## 7. 与论文口径的对齐红线

写界面文案、演示讲稿、导师 demo 解说时，**以下四句绝对不能出现**：

| ❌ 不能说 | ✅ 正确说法 | 依据 |
|:--|:--|:--|
| 「闭环让生成器持续自我改进 / flywheel / self-improving」 | 有界拒绝-重采机制，接受率 0.150 → 0.217–0.233 后**平台化** | A1 曲线非单调 |
| 「本数据集能提升下游检测器可检出性」 | 下游代理指标**方向为负**：D 0.170 / E1_full 0.153 vs E1_paste **0.540** | `downstream.json` |
| 「跨模态对齐经实测达 1.0」 | IoU = 1.0 是**构造性保证**，非独立测量 | 评测器 `ir_bbox is None` 时直接返回 1.0 |
| 「可生成任意类型无人机」 | 目标类别仅覆盖**单一小型多旋翼**（Pocket_UAV），换类须重训 LoRA | manifest 中 LoRA 写死 |

补充说明两条：
- V1–V9 的 **S9 用 YOLOv8x(conf 0.25) 做可检出性判定**，属于「相对既定检测器的可检出性」，且**闭环接受样本不得用于评估同族检测器**（避免循环论证）。
- 界面十图**未经任何验证**，展示时可以说明「这是生成端原始产物，验证链在命令行侧」。

## 8. 若要让前端更像一个「操作系统」——候选改进

按性价比排序：

1. **接回 ControlNet 开关**：在右栏加一个 `跳过 CN 重绘 (skip_cnet)` 复选框，把 `/api/parse` 里的硬编码 `True` 变成请求参数。改动最小、收益最大。
2. **恢复「生成条件图」按钮**：要么补回 `btn-gen-cond` 元素并接到 `/api/generate-lora`，要么清掉 §6.1 的两处死代码。
3. **加 Validator 面板**：调 `loop/validator_pipeline.py`，在十格旁边显示 V1–V9 逐级灯（绿/红 + 失败码），这才是 CDFF 真正的卖点所在。
4. **会话持久化**：`sessions` 落盘为 `sessions/<sid>.json`，重启可恢复。
5. **导出按钮**：把当前会话的 RGB + IR + bbox + metadata 落成 `out_D` 兼容格式（`samples/dXXXX/` + `manifest.json` 条目），打通「界面演示 → 数据集」的最后一段。
6. **批量生成面板**：指定 N + seed 范围，并发跑成组样本，替换现在的手点流程。
7. **背景筛选**：给 `curated_backgrounds` 补 `time_of_day` / `weather` 元数据索引，让这三个字段真正生效。
8. **红点坐标回显**：在 Focus 后把 `nu` / `nv` / `target_px` / `dval` 显示成一行读数，便于与论文表格对齐。
