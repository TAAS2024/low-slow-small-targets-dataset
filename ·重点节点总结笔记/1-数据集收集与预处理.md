## 二、数据集收集过程

### 2.1 收集策略

经过两轮迭代筛选，最终仅保留 2 个公开数据集。筛选的核心原则从「功能完整性」转变为「视角一致性」：

| 原则 | v2.0（旧） | v3.0（新） |
|:--|:--|:--|
| **视角** | 未考虑采集视角 | 必须是**地面仰拍低空目标**，无人机作为**被观测对象**而非采集平台 |
| **模态** | RGB + TIR 覆盖即可 | RGB + IR 全配对优先（DroneMMset），纯 TIR 作验证（Anti-UAV410） |
| **用途** | 布局训练 + 检测训练 + 验证 + 伪影 | 仅 LoRA 训练 + 下游验证 |

**核心教训**：绝大多数公开 RGB-T 无人机数据集是无人机**搭载相机俯拍地面**（如 VTUAV-det、RGBTDronePerson），而非地面设备**仰拍低空无人机**。前者对「低慢小目标检测」场景是视角污染，训练出来的模型学的是「从天空找地面物体」，而非「从地面找天空物体」。

### 5.9 背景 LoRA 训练池构建（v4.2 新增 ✅）

#### 5.9.1 采样流程

```

     │
     ▼
┌─────────────────────┐
│ ① pHash 去重        │  感知哈希去重，剔除视频相邻帧中的近重复帧
│   阈值 hamming < 8  │  → 大幅降低冗余，保留场景多样性
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│ ② K-means 聚类      │  按视觉特征聚类（使用预训练 ResNet-50 特征）
│   n_clusters=20     │  → 覆盖晴/阴/黄昏/夜晚/多云等场景分布
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│ ③ 各类均匀采样      │  从每个 cluster 中按比例采样，确保场景均衡
│   target ~600 帧    │  → IR 576 / RGB 590
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│ ④ 人工剔除          │  剔除模糊/过曝/无天空/无场景信息帧
│   质量控制           │  → 确保每帧都有可学习的背景纹理
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│ ⑤ BLIP Captioning   │  `Salesforce/blip-image-captioning-base`
│   逐帧生成 caption   │  → "a view of the sky with clouds and a drone"

```

**问题**：DroneMMset 内部混有两种 IR 色彩模式：
- **Inf01**（236 帧，47%）：伪彩色热力图（紫色-橙色调色板）
- **Inf02**（266 帧，53%）：纯灰度
- **Anti-UAV-RGBT**：接近灰度但含微量色差（编码压缩引入）

直接混合训练 LoRA 会导致颜色分布混乱，生成时随机出现紫色/橙色/灰色 artifact。

**方案**：统一转灰度（三通道复制），保留全部温度强度信息，丢弃伪彩色可视化。IR 的本质是单通道温度强度，假彩色仅可视化后处理，不增加物理信息。最终论文如需彩色热力图，可对生成结果后处理加固定 colormap。

**操作**：所有 IR 帧（DroneMMset 训练样本 + 原始帧 + Anti-UAV-RGBT 抽帧输出）统一 `cv2.COLOR_BGR2GRAY → COLOR_GRAY2BGR`。

| 目录 | 帧数 | 处理前模式 | 处理后 |
|:--|:--|:--|:--|
