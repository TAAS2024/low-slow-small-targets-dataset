## Step 1: 论文 Topic & Aim 确认

### 论文题目（暂定）

**面向低空低慢小目标的自然语言驱动空间可控多 LoRA 生成与多阶段 Agent 验证数据集构建框架**

### 研究边界（v4.0，已确认）

| 维度 | 内容 |
|:--|:--|
| **目标类别** | 低慢小目标：无人机（UAV）→ 泛化至风筝/气球/飞艇 |
| **生成模态** | RGB + 热红外（TIR）双模态 ✅ |
| **真实数据** | DroneMMset（RGB+IR 地面仰拍）+ Anti-UAV-RGBT（RGB+IR 地面仰拍 ✅）+ Anti-UAV410（热红外地面仰拍） |
| **空间控制** | **LLM 解析用户自然语言 → Transformer 编码时空序列 → ControlNet 输出空间条件图（depth/seg/pose）** |
| **外观生成** | **三 LoRA 在 ControlNet 空间约束下独立生成**：RGB 背景 LoRA + IR 背景 LoRA + 无人机目标 LoRA |
| **融合策略** | ControlNet 空间条件引导 + 物理一致性约束 → 统一融合 |
| **Agent 角色** | 三阶段生成后验证 + 结构化失败码反馈 + Human-in-the-loop 校准 |
| **核心叙事** | 用户说"一架无人机在黄昏多云天气下从右向左俯仰飞行"→ 系统自动生成符合物理规律的 RGB+IR 配对训练数据 |

### 核心问题定义

| 痛点 | 描述 |
|:--|:--|
| **真实采集成本极高** | 低慢小目标在多天气、多时段、多场景下的实拍数据获取耗资巨大 |
| **长尾场景覆盖严重不足** | 雨天/雾天/沙尘/逆光等极端环境样本稀缺，制约感知模型鲁棒性 |
| **公开数据集视角错配** | 大部分公开 RGB-T 无人机数据集是无人机**俯拍地面**，而非地面**仰拍低空目标** |
| **非 UAV 类别数据完全空白** | 风筝/气球/飞艇全球无公开检测数据集，是真正的数据荒漠 |
| **现有生成方法缺乏空间可控性** | 纯 prompt 驱动难以精确控制目标位置/姿态/尺度，纯 ControlNet 需要手工绘制条件图，均不适合大规模数据集构建 |

### 数据集收集

> 详见 `0-公开数据集汇总.md`

| 数据集 | 模态 | 视角 | 状态 | 用途 |
|:--|:--|:--|:--|:--|
| **DroneMMset** | RGB+IR 全配对 | 🔼 地面设备仰拍低空无人机 | ✅ 训练源 | RGB 背景 LoRA + IR 背景 LoRA + 无人机目标 LoRA |
| **Anti-UAV-RGBT** | RGB+IR 全配对 | 🔼 地面仰拍 | ✅ 训练扩充 + 主验证集 | 背景池扩充 + 验证基准（RGB+IR 双模态 mAP） |
| **Anti-UAV410** | 纯热红外 | 🔼 地面仰拍 | ✅ 验证基准 | 下游 YOLO mAP 评估（辅助验证） |

**核心教训**：无人机检测 ≠ 低慢小数据集。绝大多数公开数据集是无人机作为**采集平台**（俯拍地面），而非无人机作为**被观测目标**（地面仰拍天空）。

### 论文 Aim

构建一套 **LLM→Transformer→ControlNet 空间控制 + 多 LoRA 外观生成 + 三阶段 Agent 验证 + 闭环反馈** 的统一数据集构建框架：

1. **自然语言驱动的空间控制链（新）**：用户输入无人机的姿态、飞行轨迹、背景图、天气、时间等自然语言描述 → LLM 解析为结构化场景参数 → Transformer 编码时空序列为逐帧条件向量 → **ControlNet 生成空间条件图（depth/seg/pose），精确锁定目标在画面中的位置、尺度、姿态**
2. **ControlNet 引导的多 LoRA 外观生成**：在 ControlNet 空间条件图的引导下，三个 LoRA 分别生成 RGB 背景（天空+场景纹理）、IR 背景（热红外域映射）、无人机目标（多角度/距离的外观），最后在空间约束下统一融合
3. **三阶段 Agent 验证链**：语义验证（CLIP 视角对齐）→ 目标验证（YOLO 检测校验）→ 图像质量验证（模糊/伪影/LoRA 融合 artifacts），从粗到细逐层过滤
4. **闭环自适应机制**：验证链输出的结构化失败码分派到对应环节——语义失败调整 LLM prompt/ControlNet 布局，目标失败调整 Transformer 位置编码，质量失败调整 LoRA 融合权重
5. **跨类别泛化**：在 UAV 类别上校准全管线（有 DroneMMset ground truth），引擎泛化到非 UAV 类别（风筝/气球/飞艇）
6. **核心分工**：**ControlNet 决定 WHERE（空间骨架），LoRA 决定 WHAT（外观填充）**——两者在同一管线中协同，非独立分支

## Step 2: Literature Review & Research GAP

### 2.1 相关文献分类

#### A. 参数高效微调：LoRA 与扩散模型适配

| 论文 | 会议/年份 | 关键贡献 | 与我们的关系 |
|:--|:--|:--|:--|
| **LoRA: Low-Rank Adaptation** (2106.09685) | ICLR 2022 | 低秩矩阵分解实现参数高效微调，冻结预训练权重，仅训练低秩矩阵 | ⭐ 理论基础 |
| **LyCORIS / LoHa / LoKr** | 2023-2024 | 多种 LoRA 变体：Hadamard 乘积、Kronecker 分解等 | 方法参考：LoRA 训练算法选择空间 |
| **FLORA** (2508.21712) | arXiv 2025 | 基于 Flux LoRA 的高效合成数据生成，面向低数据场景的目标检测 | ⭐ 直接相关：低数据场景下的 LoRA 生成范式 |

**小结**：LoRA 用于扩散模型微调已是成熟范式。现有工作多为单 LoRA（一个 LoRA 负责整个风格/主题）。我们的核心差异化在于：**多个语义独立的 LoRA 在统一空间控制下协同生成**，每个 LoRA 只负责一个语义维度，ControlNet 提供空间骨架。

### 2.2 Research GAP 分析

| GAP | 现有工作 | 我们的创新 |
|:--|:--|:--|
| **GAP-1: 缺乏自然语言驱动的空间可控生成** | ControlNet 需要手工条件图；Layout-to-Image 仅支持离散标签布局；纯 prompt 驱动无法精确控制位置 | **LLM→Transformer→ControlNet 自动空间控制链**：用户说"从右向左俯仰飞行"→ 系统自动生成逐帧 depth/pose/seg 条件图，无需任何手工输入 |
| **GAP-2: 缺乏 ControlNet + 多 LoRA 的模块化协同** | ControlNet 通常与全量模型配合（单一风格）；LoRA 通常单独使用（单一主题） | **ControlNet 空间骨架 + 多 LoRA 外观填充**：ControlNet 确定 WHERE，RGB/IR/Drone 三个 LoRA 分别确定各自区域的 WHAT |
| **GAP-3: 缺乏多阶段智能验证链** | AeroGen 仅有简单过滤；CFHA 的 Hallucination Removal 是生成内过滤；合成图像检测仅做真假二分类 | **三阶段 Agent 串行验证**：语义→目标→质量，粗到细分层 + **结构化失败码**实现精确归因 |
| **GAP-4: 缺乏自动化闭环反馈** | DiffusionAgent 有 Human-in-the-loop；AeroGen/DetDiffusion 过滤为单向流程 | 验证链失败模式**自动反馈至生成端各环节**（LLM/Transformer/ControlNet/LoRA），**Agent→Agent 无人干预迭代** |
| **GAP-5: 低慢小领域无专用生成框架** | Anti-UAV 仅覆盖无人机；AeroGen/CFHA 面向通用遥感/行人 | 四类 LSS 目标 × 6 天气 × 4 时段 × RGB/IR 双模态 × 精确空间控制 |
| **GAP-6: 非 UAV 类别验证不对称** | 无前例 | 首次面对"无真实数据的稀有类别"验证：UAV 强校准泛化到非 UAV |

### 2.3 创新点总结

1. **LLM→Transformer→ControlNet 自然语言空间控制链**（⭐ 最大创新点）：首次将 LLM 语义理解 + Transformer 时空编码 + ControlNet 空间条件生成桥接为统一管线。用户自然语言输入 → 自动精确空间布局。与现有 ControlNet 需要手工条件图形成根本差异
2. **ControlNet + 多 LoRA 模块化协同架构**：ControlNet 提供空间骨架（WHERE），RGB/IR/Drone 三 LoRA 分别填充外观（WHAT）。每个组件职责单一、可独立训练、灵活组合
3. **三阶段 Agent 串行验证链**：语义(CLIP)→目标(YOLO)→质量(IQA) 粗到细分层 + 结构化失败码。超越 AeroGen 简单过滤和真假二分类
4. **精细化闭环反馈——失败码分派到对应环节**：语义失败 → LLM prompt/ControlNet 布局调整；目标失败 → Transformer 位置编码调整；质量失败 → LoRA 融合权重调整
5. **面向低慢小目标的完整条件空间**：四类目标 × 六种天气 × 四时段 × RGB/IR 双模态 × 精确空间控制
6. **跨类别生成泛化**：首次为无真实数据的稀有 LSS 类别（风筝/气球/飞艇）生成训练数据

#### 模块 1：LLM 语义解析

**输入**：用户自然语言描述
```
"一架 DJI Mavic 3，从右向左做俯仰机动，距地面观测点 50m，
 黄昏时分，多云天气，地面仰拍视角，同时输出 RGB 和热红外"
```

**LLM 任务**：解析为结构化场景 JSON

```json
{
  "drone_type": "DJI Mavic 3",
  "action": "pitch",
  "trajectory": {
    "start": {"x": 0.8, "y": 0.5, "z": 50.0},
    "end":   {"x": 0.2, "y": 0.4, "z": 50.0},
    "duration_s": 3.0
  },
  "distance_m": 50,
  "time_of_day": "dusk",
  "weather": "cloudy",
  "viewpoint": "ground_looking_up",
  "modalities": ["RGB", "TIR"],
  "camera_params": {
    "fov_horizontal": 60,
    "elevation_angle": 45
  }
}
```

**技术选型**：GPT-4o / Claude Sonnet / Qwen-VL，使用 few-shot prompt + JSON schema 约束输出格式。

#### 模块 2：Transformer 时空编码

**输入**：LLM 输出的结构化场景 JSON

**任务**：将飞行轨迹的时空序列编码为逐帧条件向量

```
轨迹序列: [(x₁,y₁,z₁,t₁), (x₂,y₂,z₂,t₂), ..., (xₙ,yₙ,zₙ,tₙ)]
天气嵌入: weather_embed(cloudy, dusk)
相机参数: [fov, elevation_angle]
        ↓
Transformer Encoder (带位置编码 + 时间编码)
        ↓
逐帧条件向量: [f₁, f₂, ..., fₙ]
每帧 fᵢ ∈ ℝᵈ 编码了该帧中目标应处的位置、尺度、旋转、深度信息
```

**设计要点**：
- 位置编码：将无人机在画面中的归一化坐标 (u,v) 嵌入
- 深度编码：将距离 (50m/200m) 映射为目标像素占比
- 姿态编码：将飞行姿态（俯仰/偏航/横滚）映射为关键点偏移
- 时间编码：序列中的时间步信息，支持多帧生成

**输出**：固定维度的条件向量，可直接映射为 ControlNet 的条件图输入。

#### 模块 3：ControlNet 空间布局生成（WHERE）

**输入**：Transformer 输出的逐帧条件向量

**任务**：将条件向量转换为 ControlNet 可理解的空间条件图

```
条件向量 fᵢ
    ↓
条件映射网络 (MLP / 小型 CNN)
    ↓
┌──────────────┬──────────────┬──────────────┐
│  Depth Map   │   Seg Map    │   Pose Map   │
│  512×512     │  512×512     │  512×512     │
│              │              │              │
│ 天空: depth  │ 天空: class 0│ 无人机关键点  │
│  = 1.0       │ 无人机:      │ 朝向矢量      │
│ 无人机:       │  class 1     │ 俯仰角编码    │
│  depth=0.3   │              │              │
└──────────────┴──────────────┴──────────────┘
        ↓
Multi-ControlNet (多个 ControlNet 单元并行注入)
        ↓
空间条件图同时送入 RGB 背景 LoRA 和 IR 背景 LoRA 的去噪过程
```

**为什么用 Multi-ControlNet**：Depth 控制场景深度结构，Seg 控制区域划分（天空 vs 无人机），Pose 控制目标朝向。三种条件互补，确保空间位置精确。

#### 模块 4：RGB 背景 LoRA

**基座模型**：SD1.5
**训练数据**：DroneMMset RGB 3,771 帧 + Anti-UAV-RGBT RGB 14,844 帧 = **18,615 帧**（地面仰拍天空+低空无人机）
**LoRA 参数**：rank=16, alpha=16（可调）
**推理时**：在 ControlNet 的 depth + seg 空间条件引导下生成天空背景纹理
**目标效果**：学习「黄昏多云天空长什么样」「晴天天空长什么样」，可在不同天气/时段下泛化

#### 模块 5：IR 背景 LoRA

**基座模型**：SD1.5
**训练数据**：DroneMMset IR 3,804 帧 + Anti-UAV-RGBT IR 14,844 帧 = **18,648 帧**（热红外仰拍，已全量灰度统一）
**LoRA 参数**：同 RGB LoRA
**推理时**：同样在 ControlNet 空间条件下生成热红外域的天空背景
**挑战**：SD1.5 训练数据以 RGB 为主，IR 域是 OOD。备选方案为叠加灰度转换层或使用专用热红外生成模型。

#### 模块 6：无人机目标 LoRA

**训练数据**：从 DroneMMset + Anti-UAV-RGBT RGB/IR 帧中裁切的无人机目标块（⏳ 待裁切）
- DroneMMset: 5 种无人机 × 6 种飞行动作 × 50m/200m × 昼夜
- Anti-UAV-RGBT: 1920×1080 高分辨率，有逐帧 `exist` 标志和 bbox 标注
**基座模型**：SD1.5
**推理时**：在 ControlNet 的 seg 条件图的 drone 区域内生成无人机外观
**目标效果**：学习无人机在不同角度/距离/光照下的外观，与背景独立可控

#### 模块 7：ControlNet 引导的多 LoRA 融合生成

这是整个管线的**核心生成环节**——关键在于 ControlNet 条件如何引导多 LoRA 协同：

```
ControlNet 空间条件图（depth + seg + pose）作为固定引导
                    ↓
         ┌─────────┴─────────┐
         ▼                   ▼
  RGB 去噪过程          IR 去噪过程
  (RGB LoRA 激活)       (IR LoRA 激活)
         │                   │
    seg=天空区域:         seg=天空区域:
    RGB LoRA 负责天空    IR LoRA 负责热红外天空
         │                   │
    seg=无人机区域:       seg=无人机区域:
    无人机 LoRA 负责目标  无人机 LoRA 负责热红外目标
         │                   │
         └─────────┬─────────┘
                   ▼
         物理一致性约束
         · 反光: RGB 天空亮度 → RGB 目标表面高光
         · 景深: depth 距离 → 目标边缘高斯模糊程度
         · 透视: depth 深度 → 目标像素面积缩放
                   │
         ┌─────────┴─────────┐
         ▼                   ▼
    RGB 合成图           IR 合成图
```

**融合策略**（待实验验证）：
1. **区域掩码融合**：seg 图划分天空/无人机区域，各 LoRA 仅在其区域内生效，最后拼接
2. **联合去噪**：ControlNet 条件同时注入 RGB 和 IR 去噪过程，各 LoRA 在全局激活但以权重衰减控制区域外贡献
3. **分步生成**：先 ControlNet + RGB LoRA + 无人机 LoRA 生成 RGB 图 → 再以 RGB 图为引导 + IR LoRA 转换为 IR 图

**物理一致性约束**：

| 约束 | 依赖条件 | 实现方式 |
|:--|:--|:--|
| **反光一致性** | seg 天空亮度 → 目标表面反射 | 提取天空区域平均亮度，在无人机 LoRA 推理时注入对应高光强度 |
| **清晰度匹配** | depth 深度值 → 边缘锐度 | 根据 depth 无人机深度，自动对目标区域施加对应 sigma 的高斯模糊 |
| **透视匹配** | depth 深度值 → 像素占比 | 50m 深度 → 目标 ~5% 画面；200m 深度 → 目标 ~1% 画面 |

#### 模块 8：三阶段 Agent 验证链

> 此模块与前版基本一致，验证链独立于生成端架构。

| 阶段 | Agent | 工具/方法 | 验证问题 | 技术依据 |
|:--|:--|:--|:--|:--|
| **Stage 1: 语义验证** | 语义验证 Agent | CLIP 语义对齐 + LLM 辅助判断 | 内容是否符合"地面仰拍低空目标"视角？天气/时段是否符合预期？ | CLIP for SID 可达 0.92-0.96 mAP |
| **Stage 2: 目标验证** | 目标验证 Agent | YOLO（Anti-UAV410 fine-tune）+ 规则引擎 | 目标数量=1？位置与 ControlNet seg 标注是否一致？尺度是否符合距离设定？ | Anti-UAV410 438K bbox |
| **Stage 3: 图像质量验证** | 图像质量 Agent | BRISQUE/NIQE + LoRA 融合 artifact 检测 | 是否存在模糊、AI 伪影、ControlNet-LoRA 拼接边界痕迹？ | 无参考 IQA |

**链式逻辑**：串行执行，任一阶段不通过即废弃。Stage 1→2→3 从粗到细：语义层 → 目标层 → 像素层。

#### 模块 9：精细化闭环反馈

这是 v4.0 相比前版最大的改进——失败码**分派到对应环节**，而非笼统调整：

```
验证链失败 → 失败码分类 → 精确定位问题环节
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   LLM/ControlNet        Transformer           LoRA 融合
   语义失败               目标位置失败            质量失败
        │                     │                     │
   调整 prompt            调整位置编码           调整 LoRA 权重
   调整 seg 布局          调整尺度参数           调整去噪步数
```

**失败码与分派表**：

| 失败码 | 含义 | 分派环节 | 调整动作 |
|:--|:--|:--|:--|
| `S1_SEMANTIC_MISMATCH` | 视角不匹配 | LLM + ControlNet | 调整 prompt 视角描述 / seg 天空占比 |
| `S1_WEATHER_WRONG` | 天气/时段不对 | LLM | 强化天气/时段 prompt 关键词 |
| `S2_COUNT_MISMATCH` | 检测数量≠1 | ControlNet seg | 检查 seg 无人机区域是否被天空覆盖 |
| `S2_POSITION_OFFSET` | 目标偏离预期位置 | Transformer | 调整位置编码映射精度 |
| `S2_SCALE_WRONG` | 尺度与距离不匹配 | Transformer | 调整 depth→像素占比映射 |
| `S2_MISSED_TARGET` | 目标未被检测 | ControlNet + LoRA | 检查 seg 标注 + LoRA 生成质量 |
| `S3_BLUR` | 模糊 | LoRA 融合 | 减少景深模糊强度 / 增加去噪步数 |
| `S3_ARTIFACT` | AI 伪影 | LoRA 融合 | 调整 LoRA 权重 / 步数 |
| `S3_BOUNDARY_ARTIFACT` | 拼接边界痕迹 | ControlNet seg | 羽化 seg 边界 / 区域掩码融合策略 |
| `S3_LORA_INTERFERENCE` | LoRA 冲突 | LoRA 融合权重 | 降低冲突 LoRA 的权重 |

### 4.2 需要采集的指标

| 类别 | 指标 | 说明 |
|:--|:--|:--|
| **空间控制精度** | ControlNet 条件图 vs 真值的 IoU（seg）/ MAE（depth） | LLM→Transformer→ControlNet 的空间控制准确性 |
| **生成质量** | FID / KID / CLIP Score | 合成图像与真实图像的分布距离 |
| **LoRA 效果** | LoRA 训练 loss 曲线 / preview 对比图 | 各 LoRA 训练收敛情况 |

## Step 5: Discussion

### 5.1 可讨论议题

1. **LLM→Transformer→ControlNet 自动空间控制的泛化能力**：当前在 DroneMMset 上训练/验证，能否泛化到非 UAV 类别的空间布局？这是整条管线的最关键假设
2. **ControlNet + LoRA 的协同 vs 冲突**：ControlNet 强空间约束是否会限制 LoRA 的生成多样性？需要找到空间精度与外观多样性的平衡点
3. **多 LoRA 模块化 vs 全量微调的取舍**：多 LoRA 保持基座泛化能力，但融合可能引入 interference/boundary artifacts
4. **LoRA 在 IR 域的迁移可行性**：SD1.5 以 RGB 为主，IR 是 OOD。若失败需专用 IR 扩散模型
5. **闭环收敛性与过拟合风险**：验证反馈是否会让生成端过拟合验证标准（类似 GAN 模式坍塌）？
6. **非 UAV 验证不对称性的论文叙事**：UAV 可以秀定量指标（有 Anti-UAV410 ground truth），非 UAV 只能秀 qualitative examples。需坦诚声明，将非 UAV 定位为"有 UAV anchor 的 semi-supervised quality estimation"
7. **LLM→Transformer→ControlNet 的端到端训练 vs 模块化训练**：当前为模块化设计（各组件独立训练），端到端联合训练是否更好？权衡工程可行性与性能上限

### 5.2 局限性与未来工作

| 局限 | 未来方向 |
|:--|:--|
| LLM→Transformer→ControlNet 的空间条件精度尚无实验验证 | 优先跑通 ControlNet 条件图生成的端到端流程 |
| IR 域迁移是 SD1.5 的 OOD 挑战 | 备选：基于 Anti-UAV410 TIR 帧从头训练专用 IR 扩散模型 |
| 多 LoRA 融合可能产生 boundary artifacts | 探索 seg 边界羽化、渐进式区域融合 |
| 三阶段 Agent 串行增加推理时间 | 探索并行验证 + 早期退出策略 |
| 闭环冷启动阶段反馈稀疏 | 引入少量人工标注引导初始策略 |
| 当前仅覆盖静态图像生成 | 未来扩展到视频序列（利用 Transformer 时序能力） |
| **非 UAV 类别无真实数据校准** | 互联网爬取 + 人工评估 + 物理仿真多信号共识 |
| DroneMMset RF 数据未利用 | 保留为三模态扩展接口 |
