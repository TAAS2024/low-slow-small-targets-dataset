**面向低空低慢小目标的 ControlNet 标记注入与条件驱动局部重绘数据集构建框架**

| 维度 | 内容 |

| **外观生成** | **LoRA v3 (Pocket_UAV) 白底生成 → rembg 抠图 → ControlNet(depth+seg) img2img 局部重绘 → rgb2ir_converter 转 IR** |
| **核心叙事** | 用户说"阴天下午，四旋翼从远处飞近"→ 系统自动匹配真实背景 → 提取 depth/seg → LoRA 生成无人机 → 抠图 → 标记注入 → ControlNet 局部重绘 → 8 产物输出 |

### 核心问题定义

| 痛点 | 描述 |
|:--|:--|
| **真实采集成本极高** | 低慢小目标在多天气、多时段、多场景下的实拍数据获取耗资巨大 |
| **长尾场景覆盖严重不足** | 雨天/雾天/沙尘/逆光等极端环境样本稀缺，制约感知模型鲁棒性 |
| **公开数据集视角错配** | 大部分公开 RGB-T 无人机数据集是无人机**俯拍地面**，而非地面**仰拍低空目标** |
| **非 UAV 类别数据完全空白** | 风筝/气球/飞艇全球无公开检测数据集，是真正的数据荒漠 |
| **现有生成方法缺乏空间可控性** | 纯 prompt 驱动难以精确控制目标位置/姿态/尺度，纯 ControlNet 需要手工绘制条件图，均不适合大规模数据集构建 |

### 数据集收集

> 详见 `0-公开数据集汇总.md`

| 数据集 | 模态 | 视角 | 状态 | 用途 |
|:--|:--|:--|:--|:--|
| **DroneMMset** | RGB+IR 全配对 | 🔼 地面设备仰拍低空无人机 | ✅ 训练源 | 无人机目标 LoRA + 背景物理校验 Agent（真实 IR 样本） |
| **Anti-UAV-RGBT** | RGB+IR 全配对 | 🔼 地面仰拍 | ✅ 训练扩充 + 主验证集 | 背景物理校验 Agent 扩充 + 验证基准（RGB+IR 双模态 mAP） |
| **Anti-UAV410** | 纯热红外 | 🔼 地面仰拍 | ✅ 验证基准 | 下游 YOLO mAP 评估（辅助验证） |

**核心教训**：无人机检测 ≠ 低慢小数据集。绝大多数公开数据集是无人机作为**采集平台**（俯拍地面），而非无人机作为**被观测目标**（地面仰拍天空）。

### 论文 Aim

构建一套 **LLM→背景匹配→ControlNet v7 条件驱动全管线（depth/seg/LoRA/CN重绘）→双层级 Validator 验证→闭环反馈** 的统一数据集构建框架：

1. **真实背景驱动的 ControlNet 标记注入管线（核心创新）**：37,852 张真实背景图库 → MidasDepth + 启发式分割 → LoRA v3 白底生成 → rembg 抠图 → drone silhouette 注入 depth/seg → ControlNet(depth+seg) 双条件引导局部重绘。不是"全图合成"，也不是"简单贴入"，而是**先标记空间位置，再让 ControlNet 按场景上下文重绘**
2. **8 产物全可观测**：bg / bg_depth / bg_seg / drone_raw / drone_clean / drone_depth / drone_seg / final_rgb — 管线每一步的中间产物都可视化，支持逐窗口重置级联
3. **时钟驱动随机性**：`time_ns()/1000 + fi*777` 微秒级种子，确保每次生成不可复现、永不重复
4. **双层级 Validator 验证链**：S1-5 输入端预校验（22项规则，扩散推理前拦截错误）+ S6-S9 输出端审查（BRISQUE→一致性→轨迹→YOLO），短路求值
5. **闭环自适应机制**：验证链输出的结构化失败码分派到对应环节
6. **跨类别泛化**：在 UAV 类别上校准全管线，引擎泛化到非 UAV 类别
7. **核心分工**：**ControlNet 决定 WHERE（空间位置），LoRA 决定 WHAT（外观填充），真实背景保证背景真实性**

## Step 2: Literature Review & Research GAP

### 2.1 相关文献分类

#### A. 参数高效微调：LoRA 与扩散模型适配

| 论文 | 会议/年份 | 关键贡献 | 与我们的关系 |
|:--|:--|:--|:--|
| **LoRA: Low-Rank Adaptation** (2106.09685) | ICLR 2022 | 低秩矩阵分解实现参数高效微调，冻结预训练权重，仅训练低秩矩阵 | ⭐ 理论基础 |
| **LyCORIS / LoHa / LoKr** | 2023-2024 | 多种 LoRA 变体：Hadamard 乘积、Kronecker 分解等 | 方法参考：LoRA 训练算法选择空间 |
| **FLORA** (2508.21712) | arXiv 2025 | 基于 Flux LoRA 的高效合成数据生成，面向低数据场景的目标检测 | ⭐ 直接相关：低数据场景下的 LoRA 生成范式 |

**小结**：LoRA 用于扩散模型微调已是成熟范式。现有工作多为单 LoRA（一个 LoRA 负责整个风格/主题）。我们的核心差异化在于：**多个语义独立的 LoRA 在统一空间控制下协同生成**，每个 LoRA 只负责一个语义维度，ControlNet 提供空间骨架。

#### B. 空间可控图像生成：ControlNet 与条件扩散

| 论文 | 会议/年份 | 关键贡献 | 与我们的关系 |
|:--|:--|:--|:--|
| **ControlNet** (2302.05543) | ICCV 2023 | 在扩散模型 UNet 中添加可训练副本，接受边缘/深度/分割/姿态等空间条件，实现精确空间控制 | ⭐ 核心技术：空间骨架生成的基础设施 |
| **T2I-Adapter** (2302.08453) | AAAI 2024 | 轻量级适配器实现空间条件注入，与 ControlNet 互补 | 方法借鉴：空间条件注入的替代方案 |
| **LayoutDiffusion** (2303.17189) | CVPR 2023 | 布局条件扩散模型，Object-aware Cross Attention 实现位置敏感控制 | 方法借鉴：布局条件的编码方式 |
| **Multi-ControlNet** | 2023 | 多个 ControlNet 单元并行注入多种空间条件（如同时使用 depth+pose） | ⭐ 技术参考：多空间条件协同的工程范式 |

**小结**：ControlNet 是空间可控生成的成熟方案。但现有工作要么让用户手工提供条件图（不适合大规模自动化），要么用简单的布局标签（缺乏精细的空间控制）。**我们的创新在于用 LLM→Transformer 自动生成 ControlNet 条件图**，使空间控制从手工操作变为自然语言驱动的大规模自动化。

### 2.2 Research GAP 分析

| GAP | 现有工作 | 我们的创新 |
|:--|:--|:--|
| **GAP-1: 缺乏标记注入 + ControlNet 重绘的自动化管线** | ControlNet 需要手工条件图；纯 prompt 驱动无法精确控制位置；简单贴入边缘生硬 | **标记注入 + 条件驱动重绘**：LoRA 生成 → rembg → silhouette 注入 depth/seg → ControlNet(depth+seg) img2img。先标记空间位置，再让 ControlNet 按场景上下文重绘，融合自然 |
| **GAP-2: 缺乏全管线可观测性** | 现有生成管线多为黑盒，中间产物不可见 | **8 槽观察窗口 + 逐窗口重置级联**：管线每一步的中间产物都可视化，支持单窗口 ↻ 重置 + 下游自动级联 |
| **GAP-3: 缺乏双层级智能验证链** | AeroGen 仅有简单过滤；CFHA 的 Hallucination Removal 是生成内过滤；合成图像检测仅做真假二分类 | **双层级 9 阶段串行验证**：S1-5 输入端预校验（扩散推理前拦截错误，零 GPU 浪费）+ S6-S9 输出端审查（质量→一致性→轨迹→检测），粗到细分层 + 结构化失败码实现精确归因 |
| **GAP-4: 缺乏自动化闭环反馈** | DiffusionAgent 有 Human-in-the-loop；AeroGen/DetDiffusion 过滤为单向流程 | 验证链失败模式**自动反馈至生成端各环节**（LLM/背景匹配/Transformer/Inpainting），**Agent→Agent 无人干预迭代** |
| **GAP-5: 低慢小领域无专用生成框架** | Anti-UAV 仅覆盖无人机；AeroGen/CFHA 面向通用遥感/行人 | 四类 LSS 目标 × 6 天气 × 4 时段 × RGB/IR 双模态 × 精确空间控制 |
| **GAP-6: 非 UAV 类别验证不对称** | 无前例 | 首次面对"无真实数据的稀有类别"验证：UAV 强校准泛化到非 UAV |
| **GAP-7: 缺乏「合成背景 vs 真实背景」在数据增广中的系统对比** | 现有数据生成工作（ODGEN/FLORA/InstaGen）均使用合成/生成背景，无人系统对比真实背景的效果 | 37,852 张真实背景图库 + CLIP 分类，首次实现「真实背景+局部生成」范式，并可通过消融实验对比 vs ControlNet 合成背景 |

### 2.3 创新点总结

1. **标记注入 + ControlNet 条件驱动局部重绘**（⭐ 最大创新点）：首次在低慢小数据生成中采用「LoRA 生成 → rembg 抠图 → silhouette 标记注入 depth/seg → ControlNet 双条件重绘」管线。不是全图合成、不是简单贴入，而是先标记空间位置再让 ControlNet 按场景上下文重绘，融合自然
2. **8 产物全可观测 + 重置级联**：管线每步中间产物都可视化，支持单窗口重置 + 下游自动级联，方便调试和迭代
3. **时钟驱动随机性**：`time_ns()/1000 + fi*777` 微秒级种子，每次生成结果不同，无重复风险
4. **双层级 9 阶段 Validator**：S1-5 输入端预校验（22项规则）+ S6-S9 输出端审查，短路求值
5. **精细化闭环反馈**：失败码分派到对应环节
6. **面向低慢小目标的完整条件空间**：四类目标 × 六种天气 × 四时段 × RGB/IR 双模态
7. **跨类别生成泛化**：首次为无真实数据的稀有 LSS 类别生成训练数据

#### 模块 1：LLM 语义解析

**输入**：用户自然语言描述
```
"一架 DJI Mavic 3，从右向左做俯仰机动，距地面观测点 50m，
 黄昏时分，多云天气，地面仰拍视角，同时输出 RGB 和热红外"
```

**LLM 任务**：解析为结构化场景 JSON

```json
{
  "drone_type": "DJI Mavic 3",
  "action": "pitch",
  "trajectory": {
    "start": {"x": 0.8, "y": 0.5, "z": 50.0},
    "end":   {"x": 0.2, "y": 0.4, "z": 50.0},
    "duration_s": 3.0
  },
  "distance_m": 50,
  "time_of_day": "dusk",
  "weather": "cloudy",
  "viewpoint": "ground_looking_up",
  "modalities": ["RGB", "TIR"],
  "camera_params": {
    "fov_horizontal": 60,
    "elevation_angle": 45
  }
}
```

**技术选型**：GPT-4o / Claude Sonnet / Qwen-VL，使用 few-shot prompt + JSON schema 约束输出格式。

#### 模块 2：背景匹配 + 深度/分割提取 🔥 v6.0 全新

**背景匹配**：

**输入**：LLM 输出的 JSON 中的 `background_constraints` 字段（scene_type / time_of_day / weather）

**任务**：从 37,852 张真实背景图库中匹配符合约束的背景图

```
JSON约束: {scene_type: "urban", time_of_day: "dusk", weather: "cloudy"}
    ↓
读取 _global_index.jsonl → 三层过滤 (scene→tod→weather)
    ↓
候选集 → random.choice(seed=int(time.time()*14) % 2^31)
    ↓
匹配结果: {filepath, depth_path, seg_path, ...}
```

**深度/分割提取**：

**深度图**：DepthAnything V2 (ViT-L) → 512×512 单通道深度图（0=近, 1=远）
**分割图**：SAM2 / SegFormer → 512×512 色彩分割图，映射到 6 超类：
- 天空=浅蓝、建筑=灰、树木=绿、山=棕、水=蓝、地面=土色

#### 模块 3：ControlNet v7 条件驱动全管线 🔥 v7.1 核心 ✅

> 实现：`condition_generator_v7.py` (373行) + `lora_inpainter_v7.py` (696行)

**五步管线**：

```
背景图 (真实)
  │
  ├── Step A: MidasDetector → bg_depth (深度图)
  ├── Step B: 启发式分割 → bg_seg (6超类分割图)
  │
  └── 每帧:
       Step 1: LoRA v3 txt2img 512² 白底 → drone_raw
       Step 2: rembg + dilate → drone_clean (silhouette)
       Step 3: silhouette 注入 bg_depth/bg_seg → drone_depth, drone_seg
       Step 4: Alpha 合成 → init_image
       Step 5:
         ├─ skip_cnet=False: ControlNet(depth+seg) img2img → final_rgb
         └─ skip_cnet=True:  直接 alpha 合成 → final_rgb
```

**关键参数**：

| 参数 | 默认值 | 说明 |
|:--|:--|:--|
| `gen_seed` | `time_ns()/1000 + fi*777` | 微秒时钟 + 帧偏移，每次不同 |
| `gen_steps` | 20 | LoRA txt2img 步数 |
| `blend_strength` | 0.65 | ControlNet img2img strength |
| `cnet_scales` | (0.85, 0.85) | depth/seg 条件强度 |
| `skip_cnet` | True (当前) | 跳过 CN 重绘 → 快速合成 |

**8 产物**：bg, bg_depth, bg_seg, drone_raw, drone_clean, drone_depth, drone_seg, final_rgb — 全部 Web 前端可见。

**为什么是标记注入而非简单贴入**：
- 简单贴入：无人机边缘生硬，与背景光照/纹理不一致
- 标记注入 + CN 重绘：先将 silhouette 写入 depth/seg 条件图 → ControlNet 把无人机区域当作"场景一部分"来重绘 → 融合自然
- 真实背景保留：ControlNet 只重绘 mask 内区域，背景原始质量不受影响

#### 模块 5：RGB→IR 伪彩色转换（域桥接）

**实现**：`rgb2ir_converter.py`
**算法**：RGB → 灰度 → 反转(白热) → 三通道重建(B×0.85微蓝调)
**为什么有效**：转换后三通道有色差 → VAE 可正常编解码 → 无域不匹配问题
**局限**：colormap 映射非基于真实热辐射物理，但对目标检测训练（关注形状和边缘）影响可控

#### 模块 6：背景物理逻辑校验 Agent（新 🔥）

**动机**：无人机 LoRA 生成的 RGB 背景可能存在虚假纹理/不合理天空/噪声，转 IR 后问题放大
**方案**：利用已收集但无法用于 LoRA 训练的 576 帧真实 IR 背景帧，训练一个轻量二分类器
**模型选择**：ResNet18 / EfficientNet-B0（轻量，推理快，可嵌入验证管线）
**训练数据**：
- 正样本：576 帧真实 IR 背景（DroneMMset + Anti-UAV-RGBT，pHash 去重 + 多样性采样）
- 负样本：从无人机 LoRA 生成的 RGB 图转换的 IR 背景（含人工标记的异常样本）
**输出**：0-1 物理逻辑分 → 阈值筛选 → 不合格背景丢弃+记录失败码
**定位**：验证链最前端，语义/目标/质量验证之前——先确保背景物理可行，再检查其余维度

**训练方案：**

| 参数 | 值 | 说明 |
|:--|:--|:--|
| 模型 | ResNet18（预训练 ImageNet） | 轻量：11.7M 参数，推理 <3ms/张 |
| 分类头 | 替换 fc 层：512→2 | 二分类（真实/虚假） |
| 输入尺寸 | 224×224 | 统一 resize + 中心裁剪 |
| 正样本 | 576 帧真实 IR 背景 | 路径：`2-Lora training/dataset/ir_background/` |
| 负样本 | ⏳ 待生成 | 无人机 LoRA 生成 N 张 → `rgb2ir_converter` → 人工剔除正常图 → 保留异常 |
| 数据增强 | 水平翻转 / ±10° 旋转 / 亮度 ±15% | 仅正样本增强，负样本不增强 |
| 损失函数 | CrossEntropyLoss | 标准二分类 |
| 优化器 | AdamW, lr=1e-4, weight_decay=1e-4 | — |
| Batch Size | 32 | — |
| Epochs | 30（早停 patience=5） | 正负样本平衡采样 |
| 训练/验证/测试 | 70% / 15% / 15% | 按帧来源分层划分 |
| 最佳阈值 τ₀ | ROC 曲线 Youden 指数 | 平衡精确率和召回率 |
| 评估指标 | ROC-AUC / F1 / Precision@τ₀ / Recall@τ₀ | — |

**训练流程：**

```
1. 正样本准备
   576 帧真实 IR 背景 → resize 224×224 → 标签=1 (real)

2. 负样本收集（⏳ 需先生成）
   无人机 LoRA 生成 ~200 张多场景 RGB
   → rgb2ir_converter 转换
   → 人工检查：正常图丢弃，保留异常图（虚假纹理/噪声/不合理天空）
   → resize 224×224 → 标签=0 (fake)

3. 训练
   PyTorch Lightning / 纯 PyTorch
   → 数据加载器（平衡采样：每 batch 16 real + 16 fake）
   → 训练 + 验证 → 保存最佳模型

4. 评估与阈值确定
   → 测试集 ROC 曲线
   → Youden 指数确定 τ₀（约 0.5-0.7）
   → 集成到验证链作为 Stage 0
```

**论文创新点：**
- 填补「生成式数据集中背景是否物理可行」的自动化验证空白
- 利用已收集但 VAE 不兼容的 IR 数据，变废为宝
- 背景校验失败的图像记录 `S0_BG_UNREALISTIC` 失败码 → 反馈到 LoRA 推理参数调整

#### 模块 7：ControlNet 引导的生成 + RGB→IR 转换

简化后的生成管线：

```
ControlNet 空间条件图（depth + seg + pose）作为固定引导
                    ↓
         ┌──────────────┐
         │  无人机 LoRA   │  ← 在 seg 各区域生成 RGB 场景（背景 + 无人机）
         │  (SD 1.5)    │
         └──────┬───────┘
                ↓
         RGB 合成图 (1024×1024)
                │
    ┌───────────┴───────────┐
    ▼                       ▼
  RGB 输出              rgb2ir_converter
   (原始)                    ↓
                      IR 合成图 (白热风格)
                      (三通道有色差)
```

**物理一致性约束**：

| 约束 | 依赖条件 | 实现方式 |
|:--|:--|:--|
| **反光一致性** | seg 天空亮度 → 目标表面反射 | 提取天空区域平均亮度，在无人机 LoRA 推理时注入对应高光强度 |
| **清晰度匹配** | depth 深度值 → 边缘锐度 | 根据 depth 无人机深度，自动对目标区域施加对应 sigma 的高斯模糊 |
| **透视匹配** | depth 深度值 → 像素占比 | 50m 深度 → 目标 ~5% 画面；200m 深度 → 目标 ~1% 画面 |

#### 模块 8：三阶段 Agent 验证链

> 此模块与前版基本一致，验证链独立于生成端架构。

| 阶段 | Agent | 工具/方法 | 验证问题 | 技术依据 |
|:--|:--|:--|:--|:--|
| **Stage 1: 语义验证** | 语义验证 Agent | CLIP 语义对齐 + LLM 辅助判断 | 内容是否符合"地面仰拍低空目标"视角？天气/时段是否符合预期？ | CLIP for SID 可达 0.92-0.96 mAP |
| **Stage 2: 目标验证** | 目标验证 Agent | YOLO（Anti-UAV410 fine-tune）+ 规则引擎 | 目标数量=1？位置与 ControlNet seg 标注是否一致？尺度是否符合距离设定？ | Anti-UAV410 438K bbox |
| **Stage 3: 图像质量验证** | 图像质量 Agent | BRISQUE/NIQE + LoRA 融合 artifact 检测 | 是否存在模糊、AI 伪影、ControlNet-LoRA 拼接边界痕迹？ | 无参考 IQA |

**链式逻辑**：串行执行，任一阶段不通过即废弃。Stage 1→2→3 从粗到细：语义层 → 目标层 → 像素层。

#### 模块 9：精细化闭环反馈

这是 v4.0 相比前版最大的改进——失败码**分派到对应环节**，而非笼统调整：

```
验证链失败 → 失败码分类 → 精确定位问题环节
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   LLM/ControlNet        Transformer           LoRA 融合
   语义失败               目标位置失败            质量失败
        │                     │                     │
   调整 prompt            调整位置编码           调整 LoRA 权重
   调整 seg 布局          调整尺度参数           调整去噪步数
```

**失败码与分派表**：

| 失败码 | 含义 | 分派环节 | 调整动作 |
|:--|:--|:--|:--|
| `S1_SEMANTIC_MISMATCH` | 视角不匹配 | LLM + ControlNet | 调整 prompt 视角描述 / seg 天空占比 |
| `S1_WEATHER_WRONG` | 天气/时段不对 | LLM | 强化天气/时段 prompt 关键词 |
| `S2_COUNT_MISMATCH` | 检测数量≠1 | ControlNet seg | 检查 seg 无人机区域是否被天空覆盖 |
| `S2_POSITION_OFFSET` | 目标偏离预期位置 | Transformer | 调整位置编码映射精度 |
| `S2_SCALE_WRONG` | 尺度与距离不匹配 | Transformer | 调整 depth→像素占比映射 |
| `S2_MISSED_TARGET` | 目标未被检测 | ControlNet + LoRA | 检查 seg 标注 + LoRA 生成质量 |
| `S3_BLUR` | 模糊 | LoRA 融合 | 减少景深模糊强度 / 增加去噪步数 |
| `S3_ARTIFACT` | AI 伪影 | LoRA 融合 | 调整 LoRA 权重 / 步数 |
| `S3_BOUNDARY_ARTIFACT` | 拼接边界痕迹 | ControlNet seg | 羽化 seg 边界 / 区域掩码融合策略 |
| `S3_LORA_INTERFERENCE` | LoRA 冲突 | LoRA 融合权重 | 降低冲突 LoRA 的权重 |

## Step 5: Discussion

### 5.1 可讨论议题

1. **真实背景 vs 合成背景的质量差异**：37,852 张真实背景图库是否能一致性地优于 ControlNet 合成背景？在极端天气（沙尘/逆光）下真实图库的覆盖是否充足？
2. **深度/分割提取的精度对下游的影响**：DepthAnything 和 SAM2 在仰拍天空场景中的深度/分割精度如何？提取误差是否会传导到 Transformer 空间注入和 Inpainting？
3. **Transformer 空间注入 vs 直接 Inpainting**：Transformer 是否真正提供了超越"在 mask 里随便画个无人机"的空间引导价值？消融实验 E7 将直接验证
4. **Inpainting 的边缘融合质量**：mask 外扩+羽化是否足以消除无人机与背景之间的拼接痕迹？不同背景纹理（天空纯色 vs 建筑复杂纹理）下的表现差异
5. **闭环收敛性与过拟合风险**：验证反馈是否会让生成端过拟合验证标准（类似 GAN 模式坍塌）？
6. **非 UAV 验证不对称性的论文叙事**：UAV 可以秀定量指标（有 Anti-UAV410 ground truth），非 UAV 只能秀 qualitative examples。需坦诚声明，将非 UAV 定位为"有 UAV anchor 的 semi-supervised quality estimation"
7. **Inpainting 范式的能力边界**：局部重绘无法改变全局光照/透视/景深——如果背景图的光照条件与 JSON 描述不一致（如 JSON 要求 dusk 但背景是 morning），Inpainting 能补偿多少？是否需要额外的全局色彩校正？

### 5.2 局限性与未来工作

| 局限 | 未来方向 |
|:--|:--|
| LLM→Transformer→ControlNet 的空间条件精度尚无实验验证 | 优先跑通 ControlNet 条件图生成的端到端流程 |
| IR 域迁移是 SD1.5 的 OOD 挑战 | 备选：基于 Anti-UAV410 TIR 帧从头训练专用 IR 扩散模型 |
| 多 LoRA 融合可能产生 boundary artifacts | 探索 seg 边界羽化、渐进式区域融合 |
| 三阶段 Agent 串行增加推理时间 | 探索并行验证 + 早期退出策略 |
| 闭环冷启动阶段反馈稀疏 | 引入少量人工标注引导初始策略 |
| 当前仅覆盖静态图像生成 | 未来扩展到视频序列（利用 Transformer 时序能力） |
| **非 UAV 类别无真实数据校准** | 互联网爬取 + 人工评估 + 物理仿真多信号共识 |
| **无人机 LoRA 仅覆盖单一四旋翼机型** | 当前训练数据（98张）仅含一种无人机外观。优先跑通单机型全链路，后续从 DroneMMset 按机型分类抽帧、分训多机型 LoRA，或迁移至 FLUX/SD3 利用基座泛化能力 |
| **LLM Parser Web 前端已上线** | [2026-07-30] Flask 服务运行于 `http://127.0.0.1:5000`，三面板布局：左(会话记录) / 中(场景解析器+JSON预览) / 右(RGB+IR 双图)。后端支持 DeepSeek/OpenAI/Claude/Dry-Run 四种模式。配色：白色主调 + 浅蓝(#3b82f6) + 绿色(#10b981)辅助。Tiger 使用自己的 DeepSeek API Key |
| DroneMMset RF 数据未利用 | 保留为三模态扩展接口 |

### 5.4 定位澄清：CDFF 是固定任务自主迭代精炼，不是持续学习

> 这是一个关键的论文定位问题。导师倾向于将 CDFF 闭环描述为"持续学习"，但 ML 领域的持续学习有严格定义——CDFF 做的事情在定义层面不匹配。以下分析用于论文中准确描述系统能力边界。

#### 5.4.1 ML 领域"持续学习"的严格定义

持续学习（Continual/Lifelong Learning）要求模型在非平稳数据流中逐步学习**新任务/新分布**，且满足三个硬约束：

| 约束 | 含义 |
|:--|:--|
| ① 不遗忘旧知识 | 学习新任务后，旧任务的性能不下降（无灾难性遗忘） |
| ② 前向迁移 | 能利用旧知识加速新任务学习 |
| ③ 存储受限 | 不需要重新访问全部历史数据 |

三大公认场景（Van de Ven & Tolias, 2019）：

| 场景 | 定义 | 例子 |
|:--|:--|:--|
| Task-Incremental | 新任务来了，系统知道"这是新任务" | 先学分类猫狗，再学分类车船，给任务ID |
| Domain-Incremental | 任务结构不变，输入分布变了 | 一直做猫狗分类，但先晴天数据，后雾天数据 |
| Class-Incremental | 新类别来了，系统得自己判断 | 先学猫狗分类，后来"鸟"类，但不知道总共几类 |

核心困难：**Stability-Plasticity Dilemma**（McCloskey & Cohen, 1989）。让模型学新东西的同时不冲掉旧东西——三十年了仍是 open problem。EWC / SI / PackNet / GEM / replay 都是权宜之计，没有根治。

#### 5.4.2 CDFF 为什么不是持续学习

| 维度 | CDFF 每轮循环 | 持续学习要求 |
|:--|:--|:--|
| 任务定义 | ❌ 不变——始终是"生成低慢小场景" | ✅ 必须有新任务出现 |
| 输出空间 | ❌ 不变——始终是图片 | ✅ 可能扩展 |
| 评判标准 | ❌ 不变——始终是 S0-S3 四道关卡 | ✅ 标准可能随任务变化 |
| Generator 能力边界 | ❌ 不变——LoRA 微调在扩散模型先验内 | ✅ 能力边界应扩展 |

**CDFF 的本质**：在同一个任务空间里，通过 Validator 反馈不断筛掉低质量样本、微调 Generator 减少已知失败模式。这是在**固定分布内提升质量的迭代精炼（iterative refinement / quality bootstrapping）**，不是持续学习。

**信息论层面的根本原因**：

```
闭合循环内的信息总量 = 初始数据信息 + 初始规则信息 = 固定有限集合
每轮循环: Generator 尝试新排列组合 → Validator 用同样标准审查
→ 新排列 ≠ 新信息
→ 50 轮循环后，输出分布范围 = 第 1 轮输出分布范围
```

对比：AlphaGo Zero 能自主持续学习是因为奖励信号（胜负）天然完美且可零成本计算。CDFF 的终极目标（下游检测 mAP）不在闭环内可计算——Validator 只是代理指标。**代理优化 ≠ 真实优化。这是所有闭合自训练系统的天花板。**

#### 5.4.3 如果加入人工校验呢？

**定义层面**：严格来说不算持续学习。持续学习的前提是模型自主学习，外部信号只在任务定义阶段出现，不在学习过程中。一旦每 N 轮需要人来决定"下一步学什么"，系统就不是自主持续学习了——变成了**人工驱动学习**。

**工程层面**：算不算不重要。关键是如何在论文中描述它：

| ❌ 别这么说 | ✅ 这么说 |
|:--|:--|
| "我们实现了持续学习" | "我们设计了一个固定任务空间内的自主迭代质量精炼管线" |
| "系统自主进化" | "系统在固定生成分布内自动修复已知失败模式" |
| "闭环持续学习框架" | "带反馈回路的半自动数据生成管线（人在战略层，机器在执行层）" |
| "Continual Learning framework" | "Iterative Quality Bootstrapping" 或 "Self-Refining Generation Pipeline" |

#### 5.4.4 论文叙事建议

**1. 术语上坚决不碰 "Continual Learning"**

这个坑太大。三十年的 open problem 不可能在硕士论文里解决。误用术语会被审稿人即时 red flag。

**2. 用 "Iterative Refinement" 或 "Feedback-driven Quality Optimization" 描述核心机制**

这两个词在生成式 AI 文献中有先例（如 SDEdit 的 iterative refinement、DiffusionAgent 的 feedback loop），审稿人不会觉得你在乱用术语。

**3. Discussion 中诚实声明边界**

推荐写法：

> "We do not claim that CDFF achieves fully autonomous continual learning. Rather, CDFF automates 80% of the quality control and iterative refinement within a fixed generation regime, while strategic decisions—diversity expansion, curriculum progression, and distribution redistribution—remain human-guided. We argue this semi-automated design is the pragmatic sweet spot: fully autonomous closed-loop learning in data generation remains an open problem, and we identify the information-theoretic bottleneck (proxy metric drift) as its root cause."

**4. Related Work 中正面讨论 CL 文献**

展示你清楚这个区别且思考过——这比误用术语强 10 倍。

#### 5.4.5 CDFF 能力的准确描述

| 能力 | CDFF 能做到吗 | 说明 |
|:--|:--|:--|
| 固定分布内提升生成质量 | ✅ 能 | 这是 CDFF 的核心价值 |
| 自动识别和修复已知失败模式 | ✅ 能 | 失败码聚类 → 针对性微调 |
| 学习生成新类型的场景 | ❌ 不能 | 需要外部信息注入（新背景池/新无人机资产/新条件模板） |
| 发现自己什么时候在退化 | ❌ 不能 | 需要独立测试集（下游检测 mAP 趋势） |
| 发现 Validator 标准是否偏了 | ❌ 不能 | 需要人工抽样校准 |
| 发现全新类型的失败模式 | ❌ 不能 | 需要人工抽查发现"未知的未知" |

**一句话总结**：CDFF 解决的是"给定一个目标分布后，高效产出合格数据"的自动化问题。它不是持续学习引擎，而是**固定任务空间内的自主质量精炼工厂**。持续学习的"持续"来自外部（人在环中的方向决策 + 下游检测信号回传）。

#### 5.4.6 与导师讨论的策略

直接否定可能有风险。建议换一个角度：

> "CDFF 的闭环做的事其实更有价值——它把一个生成管线的质量瓶颈自动化了，而且留了人在环中做方向决策。如果硬叫 Continual Learning，审稿人会用 CL 的标准来挑我们——比如问'灾难性遗忘你怎么解决的？'，我们根本答不上来，因为系统不涉及新旧任务切换。不如叫 Iterative Quality Bootstrapping 或 Self-Refining Generation Pipeline，更准也更有防御性。"
