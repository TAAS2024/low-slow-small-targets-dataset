## 二、三模态生成框架总览

```
┌─────────────────────────────────────────────────┐
│              共享条件编码                          │
│   机型 · 距离 · 姿态 · 环境 · 设备参数             │
├──────────┬──────────────┬──────────────────────┤
│ RF 分支   │  RGB 分支     │  IR 分支              │
│ 信号生成  │ 空间Transformer│ 热特征转换            │
│ GAN/Diff. │ 环境Agent     │ 环境Agent (共享)      │
│          │ 渲染引擎      │ CycleGAN/ControlNet   │
├──────────┼──────────────┼──────────────────────┤
│ RF 验证器 │ RGB 三阶段链  │ IR 验证器             │

├──────────┴──────────────┴──────────────────────┤

│   结构化失败码 → 分支独立信用分配 → 引擎修正       │
└─────────────────────────────────────────────────┘
```

## 三、逐分支可行性判断

### 3.1 RGB 分支：✅ 可行（成熟度最高）

**生成管线**：空间 Transformer（位置/尺度/姿态） + 环境 Agent（天气/光照/背景） → 渲染引擎

**验证链**（三阶段）：
1. **Stage 1 - CLIP 语义**：生成图像与条件文本的 semantic alignment
2. **Stage 2 - YOLO 检测**：DroneMMset 真实 UAV 帧 fine-tune → 检测分数可信
3. **Stage 3 - IQA 质量**：BRISQUE/NIQE 无参考图像质量评估

**闭环反馈**：
- 结构化失败码：`[stage]_[failure_mode]_[severity]`
- 空间/环境双分支解耦 → 信用分配明确
- Human-in-the-loop 用 DroneMMset 真实帧校准各 Stage 决策边界

**工作量**：主体，2-3 个月

---

### 3.2 IR 分支：🟡 可行但验证链较弱

**生成路径**：不独立生成红外图像，而是用 DroneMMset 的成对 RGB-IR 数据训练 image-to-image translation（CycleGAN / ControlNet 条件生成）。同一套空间布局控制共享。

**验证器**：
- DroneMMset 红外数据 fine-tune 轻量级 UAV 检测器
- 传统指标：对比度、信噪比（SNR）、热特征一致性

**风险点**：
- 红外验证器不如 RGB 成熟，结构化失败码定义更模糊
- 需要额外的 IR-human calibration

**工作量**：附加，1 个月

---

### 3.3 RF 分支：🔴 核心难点（三个层次）

#### 层次 1：特征级增强（🟢 最简单，推荐）
- 不对原始 IQ 信号做生成，而是对已有 RF 样本做数据增强
- 加噪声、频移、时域拉伸、多径衰落模拟
- 本质是传统信号处理，不需要生成模型
- **与"生成式 AI"标题的匹配度差**

#### 层次 2：时频图生成（🟡 中等，可接受）
- 将 RF 信号转为时频谱图（spectrogram），作为图像处理
- 可用扩散模型生成不同的时频图模式
- 验证可用图像质量指标
- **工作量**：附加，1-2 个月

#### 层次 3：原始 IQ 生成（🔴 不推荐）
- 直接生成 40MHz 采样的 IQ 复数序列
- DroneMMset 仅 ~320 条 IQ 样本，远不够训练
- 无现成 RF 质量评估器，验证链需要从零搭建
- **不建议硕士论文碰**

**推荐策略**：层次 1（特征增强）+ 层次 2（时频图生成）组合。论文中 RF 分支定位为"信号级增强 + 时频表示生成式增广"，不宣称原始 IQ 生成。

## 四、对抗 Agent 自学习网络：能做出来吗？

| 分支 | 生成可行性 | 验证链可靠性 | 闭环收敛性 | 综合判断 |
|:--|:--|:--|:--|:--|
| RGB | ✅ | ✅ 强 | ✅ 可收敛 | **核心模块，有把握** |
| IR | 🟡 | 🟡 中 | 🟡 可能收敛 | **能做，需额外校准** |
| RF（时频图） | 🟡 | 🟡 中 | 🟡 可能收敛 | **能做，需预研** |
| RF（原始 IQ） | 🔴 | 🔴 弱 | 🔴 不收敛 | **不做** |

### 关键机制

**信用分配（Credit Assignment）**：三模态各自独立验证链，失败信号直接归因到对应分支，不存在跨模态信用混淆。

**验证链校准**：DroneMMset 为所有 4 类 UAV 提供统一的真实校准基准——这是方案 A 的核心优势：**所有类别的闭环质量一致**。

**Human-in-the-loop**：少量人工标注校准各 Stage 决策边界，解决"验证链不等于 Oracle"的问题。

## 六、方案 A 的风险

| 风险 | 严重度 | 缓解措施 |
|:--|:--|:--|
| RF 生成做不出来 | 🔴 高 | 降级到时频图 + 特征增强，不碰原始 IQ |
| 三模态工作量过大 | 🟡 中 | RGB 是主力，IR 和 RF 做轻量版 |
| GAN vs Diffusion 措辞冲突 | 🟡 中 | 用"生成式模型"统称，不限定具体方法 |
| Agent 角色定义偏离 | 🟡 中 | 导师的 Agent 做分析，我们的 Agent 做验证——可以在论文里保留二者 |
