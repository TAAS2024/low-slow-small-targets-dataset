## 一、问题诊断

### 1.1 当前 Agent 7 能做什么

```
验证失败 → 查失败码分派表 → 调参数 → 重新生成 → 最多重试 3 次 → 人工审查
```

| 失败码 | 调整动作 | 性质 |
|:--|:--|:--|
| `S0_BG_UNREALISTIC` | 换 ControlNet seed | 参数级 |
| `S2_UNDETECTABLE` | 调 LoRA weight / CFG scale | 参数级 |
| `S3_BLUR` | 提高推理步数 | 参数级 |

### 1.2 不能做什么

**模型权重从未改变。** Agent 7 是在一个**冻结的 LoRA 上搜索更优的推理参数**，不是让 LoRA 从错误中学习。

```
当前 Agent 7:
  S2_UNDETECTABLE → 调 LoRA weight=0.7→0.9 → 重新生成
                    ↑
                    模型能力不变，只是赌另一组参数效果更好

期望的持续学习:
  S2_UNDETECTABLE → 这张图标记为负样本 → 加入训练集 → LoRA 增量微调
                    ↑
                    模型从失败中学习，消除该类错误
```

### 1.3 为什么不能直接在生成循环中学习

| 约束 | 说明 |
|:--|:--|
| LoRA 微调吃 GPU | RTX 4060 上至少 10 分钟，不可能嵌在 Web 请求里 |
| 单张图微调 = 过拟合 | 1 张负样本做梯度更新直接导致模式崩塌 |
| 验证链有噪声 | S2 误判需要人工核验，不能盲信 |
| 生成和训练互斥 | GPU 无法同时推理和训练 |

### 1.4 v1.0 的盲区：不只 LoRA 需要自训练

v1.0 方案默认「持续学习 = LoRA 增量微调」。事实上，生成管线有 **4 个可训组件**：

```
LLM → Transformer → ControlNet → LoRA → IR转换 → 验证链
        (未实现)        ✅          ✅      📐        │
                                                     ▼
                                              失败 → 该训谁？
```

| 组件 | 可训性 | 失败表现 |
|:--|:--|:--|
| ControlNet | ✅ CN-LoRA | S0 背景不真实，场景结构崩塌 |
| LoRA (无人机) | ✅ 增量 LoRA | S1 CLIP 低，S2 检测不到 |
| IR 转换器 | ⚠️ 取决于实现 | S3 IR 伪影持续偏高 |
| YOLO 检测器 | ✅ 标准微调 | 下游 mAP 不涨（外环） |

> LLM 不可训（第三方 API），Transformer 未实现先跳过。YOLO 是验证端非生成端，走独立外环。

核心问题从「LoRA 怎么从失败中学习」升级为：**失败来了，分派给哪个组件？每个组件用什么方式学？**

## 二、方案：统一分层自训练循环 (v2.0)

### 2.0 核心思路

**每个可训练组件拥有独立的 FailureBuffer + 独立的增量微调管线。中央路由器（Agent 7）根据失败码分派到对应组件的 buffer。**

```
                              ┌──────────────────────────────┐
                              │       Agent 6 四阶段验证       │
                              │  S0→S1→S2→S3                 │
                              └────────────┬─────────────────┘
                                           │
                                    失败样本 + 失败码
                                           │
                              ┌────────────▼─────────────────┐
                              │       Agent 7 失败路由器      │
                              │  根据失败码 → 分派到对应Buffer  │
                              └──┬───────┬───────┬───────────┘
                                 │       │       │
                    ┌────────────▼─┐ ┌───▼────┐ ┌▼──────────┐
                    │  CN-Buffer   │ │LoRA-Buf│ │ IR-Buf    │
                    │  阈值: 30条  │ │阈值:50 │ │ 阈值:20条  │
                    └──────┬───────┘ └───┬────┘ └─────┬──────┘
                           │            │             │
                    ┌──────▼───────┐ ┌──▼──────┐ ┌───▼────────┐
                    │  CN-LoRA     │ │增量LoRA │ │ 轻量CNN    │
                    │  rank=4      │ │lr=1e-6  │ │ 增量微调    │
                    │  对比微调     │ │400步    │ │            │
                    └──────────────┘ └─────────┘ └────────────┘
                                           │
                                    ┌──────▼──────┐
                                    │ YOLO 外环    │  ← 下游mAP不涨触发
                                    │ 合成+真实混合 │
                                    └─────────────┘
```

### 2.1 异步双循环不变

生成循环 (Online) 和学习循环 (Offline) 仍然解耦——每个组件各自异步训练，互不阻塞。

### 2.2 S1 二义性路由

CLIP 失败时无法直接判断是场景还是无人机问题：

```
S1_LOW_SIMILARITY
       │
  ┌────▼────────────┐
  │ 分别计算两个CLIP分 │
  │ 场景CLIP vs 无人机CLIP│
  └────┬────────────┘
       │
  ┌────▼─────┐   场景CLIP低  →  CN-Buffer
  │          │   无人机CLIP低 →  LoRA-Buffer
  └──────────┘
```

### 2.3 CN 触发防抖

CN 微调不是攒够就训——需要 **场景类型聚类**。同一类型占比 >50% 才触发。均匀随机失败=prompt/seed 问题，不训模型。

## 三、三种自训练范式

核心设计决策：**失败图是信号不是数据。** 不同范式决定「用什么数据、怎么训练」。

### A. 正样本筛选（Pass → Train）

```
生成 → 验证通过 → 加入训练集 → 标准微调
       验证失败 → 丢弃
```

- 最简单稳定，只喂"好图"
- 风险：只喂简单样本可能过拟合到已验证模式
- 适用：LoRA 风格微调、YOLO 检测器微调

### B. 失败引导重生成 + 对比学习（Fail → Fix → Contrast）

```
生成 → 验证失败 → 分析失败类型 → 调prompt重生成 → 修复成功?
                                                      │
                                          ┌───────────┘
                                          ▼
                              原失败图(负) vs 修复图(正)
                                          │
                                          ▼
                                DPO/对比损失微调
```

- 直接教模型「同样的条件，要那个不要这个」
- 实现复杂度高（Diffusion-DPO 较新）
- 适用：ControlNet（同条件出图质量波动大）

### C. 质量排序（Rank → Align）

```
生成N张 → 全部打分 → 按分排序 → top-k微调
```

- 不二值判断，用连续分引导
- 风险：打分指标有噪声
- 适用：IR CNN（有 BRISQUE 天然连续分）

## 四、组件-范式分配

| 组件 | 范式 | 具体做法 | 触发条件 |
|:--|:--|:--|:--|
| **LoRA** | A→C 渐进 | 初期二值通过，后期 CLIP 分数加权采样 | Buffer≥50条 |
| **ControlNet** | B | 失败图+条件保留→调prompt重生成→修复成功则对比pair→CN-LoRA rank=4 | 同场景类型≥30条 |
| **IR CNN** | C | 每批BRISQUE排序→top-50%训练→增量微调5epoch lr=1e-5 | Buffer≥20条 |
| **YOLO** | A | 合成图通过检测→混真实数据→标准微调 | 外环：下游mAP不涨 |

### 4.1 LoRA 增量微调（范式 A→C）

```
当前权重(v2) → 生成 → CLIP打分 → ≥0.75: 入正样本池
                                  <0.75: 分析失败码
                                         ├─ 场景CLIP低 → CN-Buffer
                                         └─ 无人机CLIP低 → 调prompt重生成
                                                          ├─ CLIP≥0.75 → 入池
                                                          └─ 仍失败 → FailureBuffer
正样本池 ≥50 → Kohya增量微调(lr=1e-6, 400步) → A/B评估 → 替换
```

> 不把失败图直接喂 LoRA——失败图的责任主体可能是 ControlNet。

### 4.2 ControlNet 对比微调（范式 B）

```
S0失败(背景不真实) → 场景类型聚类 → 同类型≥30条 → 触发CN微调
                                                    │
                                                    ▼
                                  取失败样本的depth/pose条件
                                  调整prompt（不动条件图）
                                  重生成 → 背景通过S0 → 形成对比pair
                                                    │
                                                    ▼
                                  CN-LoRA对比微调(rank=4)
```

> 选B不选A的原因：ControlNet核心问题是条件控制精度——同一depth map有时好有时烂。  
> 对比学习直接告诉模型"同条件，要那个不要这个"。

### 4.3 IR CNN 质量排序微调（范式 C）

```
RGB → 当前CNN → IR → BRISQUE → 全batch排序
                                 ├─ top-50% → 正样本 → 增量微调(5epoch lr=1e-5)
                                 └─ bottom-50% → 暂不纳入
```

> 选C的原因：IR质量有连续指标，不需要二值判断。CNN参数量小(~500K)，频繁微调成本低。

## 五、实现路径

### Phase 1：打地基（当前可做）

**目标**：让失败信息可追溯、可复用。

#### 3.1.1 结构化失败日志

在 Agent 6 验证输出处加一行 `record()`：

```python
# failure_buffer.py

class FailureBuffer:
    """
    失败样本缓冲池。
    生成循环只写不读，学习循环只读不写。
    """
    def __init__(self, path: str = "failure_log.jsonl", threshold: int = 50):
        self.path = path
        self.threshold = threshold

    def record(self, result: dict) -> None:
        """
        Agent 6 在每个样本验证完成后调用。
        result 必须包含:
          - sample_id, stage, failure_code, scores
          - input_spec (Agent 1 的 JSON)
          - gen_params (seed, steps, lora_weight, cfg_scale)
          - gen_images (rgb_path, ir_path — 失败图本身)
        """
        with open(self.path, "a", encoding="utf-8") as f:
            f.write(json.dumps(result, ensure_ascii=False) + "\n")

    def count(self) -> int:
        """返回当前缓冲量。超过 threshold 触发微调 pipeline。"""
        try:
            with open(self.path, "r", encoding="utf-8") as f:
                return sum(1 for _ in f)
        except FileNotFoundError:
            return 0

    def is_ready(self) -> bool:
        return self.count() >= self.threshold
```

#### 3.1.2 自动归档负样本

失败图的无人机区域裁剪保存到 `failure_buffer/crops/`：

```
failure_buffer/
├── failure_log.jsonl              # 结构化日志
├── crops/                         # 失败区域裁剪
│   ├── sample_0047_undetectable.png
│   ├── sample_0052_blur.png
│   └── ...
└── v1/                            # 第1轮微调产物
    ├── before_lora.safetensors    # 微调前权重备份
    ├── after_lora.safetensors     # 微调后权重
    └── eval_report.md             # 对比评估报告
```

#### 3.1.3 改动量

只给 Agent 6 加一个 `failure_buffer.record()` 调用。现有 7-Agent 架构不需要动任何一行。

### Phase 2：触发微调

**目标**：失败样本攒够一批后，自动构建训练集并执行 LoRA 增量微调。

#### 3.2.1 训练集构建

从 `failure_log.jsonl` 中提取两类样本：

| 类型 | 来源 | 标签 |
|:--|:--|:--|
| 正样本 | 原始 DroneMMset 训练集（98 张） | 复用已有 caption |
| 负样本纠正 | 用户人工标注的失败图 | 纠正后的 prompt + 生成图（或真实参考图） |

> 关键决策：不用失败图做正样本。失败图的无人机区域本身就是不正确的（模糊/崩坏/不可检测），用它做正样本会污染模型。正确做法是用失败图的 **prompt + 新的真实参照图** 做正样本，或人工标注失败图给出"这图该长什么样"。

#### 3.2.2 微调命令

```bash
# 在 drone_target_v2 权重基础上增量微调
cd /root/sd-scripts
PYTHONUNBUFFERED=1 accelerate launch train_network.py \
  --config_file "training_config_continual.toml" \
  --network_weights "drone_target_v2/drn3_uav_lora_v2.safetensors" \
  --network_dim 16 --network_alpha 8 \
  --learning_rate 1e-6 \          # 极低学习率，避免灾难性遗忘
  --max_train_steps 400 \
  --save_every_n_steps 100 \
  --min_snr_gamma 5.0 \
  --mixed_precision "fp16" --gradient_checkpointing
```

关键参数：
- `network_weights`：从 v2 权重复原，做增量微调而非从头训练
- `learning_rate=1e-6`：比 v2 的 `5e-5` 低 50 倍，只做小幅修正
- `max_train_steps=400`：数据集小（~50 张新图），早停防过拟合

#### 3.2.3 A/B 评估

微调完成后自动跑对比：

```
微调前 LoRA + 相同 prompt → 生成 20 张图 → 过四阶段验证 → failure_rate_before
微调后 LoRA + 相同 prompt → 生成 20 张图 → 过四阶段验证 → failure_rate_after
```

输出 `eval_report.md`，量化提升幅度。

### Phase 3：论文叙事

**目标**：将闭环数据飞轮包装为方法论贡献。

#### 3.3.1 命名

**CDFF (Closed-loop Data Flywheel Framework)** — 闭环数据飞轮框架。

#### 3.3.2 叙述结构

```
现代合成数据生成管线的核心瓶颈是什么？
  → 不是生成本身，而是生成质量退化——固定模型在分布边缘反复失败。

我们提出 CDFF：
  1. 四阶段验证链识别失败模式（what fails）
  2. 结构化失败日志归档失败样本（where it fails）
  3. 异步学习循环将失败反馈转化为增量微调（fix it）
  4. 新权重替换旧权重，下一轮生成质量自动提升（continuous improvement）

实验证明：
  - 第 N 轮的 failure rate 显著低于第 N-1 轮
  - 特定失败模式（如 S2_UNDETECTABLE）下降最明显
  - 增量微调不会灾难性遗忘原有能力
```

#### 3.3.3 论文定位

CDFF 是本研究的新颖性贡献之一，与四阶段验证链（S0-S3）构成 **"验证→反馈→学习"三位一体**的完整方法论：

```
                    ┌──────────────┐
                    │   四阶段验证   │ ← 新颖性贡献 1
                    │   S0-S3      │   「怎么发现问题」
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │   闭环反馈    │ ← 新颖性贡献 2
                    │   Agent 7    │   「怎么定位问题」
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │   持续学习    │ ← 新颖性贡献 3
                    │   CDFF       │   「怎么消除问题」
                    └──────────────┘
```

## 六、关键设计决策

| 决策 | 理由 | 备选方案 |
|:--|:--|:--|
| 异步而非同步 | GPU 不能同时推理+训练；同步会阻塞生成管线 | 同步（不可行） |
| 批量微调（50 条起） | 防单样本过拟合 | 在线学习（不稳定） |
| 增量微调而非从头训练 | 保留 v2 已有能力，只做针对性修正 | 从头训练（浪费） |
| 极低学习率（1e-6） | 防止灾难性遗忘 | — |
| 正样本用新图不用失败图 | 失败图本身是错的，用它训练会污染模型 | 用失败图（不可行） |
| 保留人工审核环节 | 验证链 S0-S3 不是 100% 准确 | 全自动（有风险） |

```json
{
  "sample_id": 47,
  "timestamp": "2026-07-30T18:00:00",
  "stage": "S2",
  "failure_code": "UNDETECTABLE",
  "scores": {
    "s0_bg_realism": 0.72,
    "s1_clip_similarity": 0.68,
    "s2_yolo_confidence": 0.23,
    "s3_brisque": 35.0
  },
  "input_spec": {
    "drone_type": "quadrotor",
    "weather": "overcast",
    "scene_type": "urban",
    "camera": {"position": "bottom", "elevation_deg": 45.0}
  },
  "gen_params": {
    "seed": 42,
    "steps": 30,
    "lora_weight": 0.8,
    "cfg_scale": 7.0
  },
  "images": {
    "rgb": "output_images/rgb/sample_0047.png",
    "ir": "output_images/ir/sample_0047.png"
  }
}
```

### 5.2 微调触发流程

```
FailureBuffer.count() >= 50
        │
        ▼
  打印提示: "已积累 50 条失败样本，是否启动微调？[y/N]"
        │
  用户确认 y
        │
        ▼
  构建 Kohya 训练集
        │
        ▼
  备份当前 LoRA 权重 → before_lora.safetensors
        │
        ▼
  执行增量微调（~10 分钟）
        │
        ▼
  A/B 评估 → eval_report.md
        │
        ▼
  效果提升？── Y → 替换生产权重，清空缓冲区
        │
        N
        │
        ▼
  退回 before_lora.safetensors，记录原因
```
