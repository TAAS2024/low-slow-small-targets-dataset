## 一、问题诊断

### 1.1 当前 Agent 7 能做什么

```
验证失败 → 查失败码分派表 → 调参数 → 重新生成 → 最多重试 3 次 → 人工审查
```

| 失败码 | 调整动作 | 性质 |
|:--|:--|:--|
| `V6_BG_UNREALISTIC` | 换 ControlNet seed | 参数级 |
| `V9_UNDETECTABLE` | 调 LoRA weight / CFG scale | 参数级 |
| `V6_BLUR` | 提高推理步数 | 参数级 |

### 1.2 不能做什么

**模型权重从未改变。** Agent 7 是在一个**冻结的 LoRA 上搜索更优的推理参数**，不是让 LoRA 从错误中学习。

```
当前 Agent 7:
  V6_BRISQUE_HIGH → 调 CFG/seed → 重新生成
                    ↑
                    模型能力不变，只是赌另一组参数效果更好

期望的持续学习:
  V6_BRISQUE_HIGH → 这张图标记为负样本 → 加入训练集 → LoRA 增量微调
                    ↑
                    模型从失败中学习，消除该类错误
```

### 1.3 为什么不能直接在生成循环中学习

| 约束 | 说明 |
|:--|:--|
| LoRA 微调吃 GPU | 增量微调耗时分钟级，不可能嵌在 Web 请求里 |
| 单张图微调 = 过拟合 | 1 张负样本做梯度更新直接导致模式崩塌 |
| 验证链有噪声 | V7/V8 误判需人工核验，不能盲信 |
| 生成和训练互斥 | GPU 无法同时推理和训练 |

### 1.4 闭环自训练的过拟合风险 ⚠️

#### 1.4.1 Goodhart's Law 陷阱

闭环的底层逻辑：Generator 产出的数据 → Validator 打分 → 分数回流微调 Generator。致命盲区：**Validator 本身不是真理**。当 Validator 的评分变成 Generator 的优化目标，Generator 不需要生成"对检测训练有用的图"，只需要生成"Validator 会给高分的图"。

在强化学习里这叫 **reward hacking**，在社会科学里叫 **Goodhart's Law**：当一个指标变成目标，它就不再是好的指标。

#### 1.4.2 按 V 阶段逐层剖析

| 阶段 | 风险 | 具体表现 |
|:--|:--|:--|
| V1 (LLM JSON) | 低 | 纯规则校验，Generator 无法绕过 |
| V2 (背景匹配) | 低 | 规则 + CLIP 校验，背景 pool 固定 |
| V3 (深度/分割) | 低 | 纯统计检查 |
| V4 (LoRA artifact) | 中 | Generator 可能学会生成"SSIM 好看但内容空洞"的 drone |
| V5 (Focus) | 低 | 纯坐标检查 |
| V6 (图像质量) | 纹理过平滑 | Generator 学会生成 BRISQUE 好看的图，但纹理过于平滑——与真实场景噪声分布不一致 |
| V7 (一致性) | 多样性崩塌 | Generator 学会生成"最容易验证一致"的场景——无人机永远在蓝天中央、姿态永远水平 |
| V8 (轨迹) | 间接信号 | 物理规则本身不变，但 LLM 可能学会"最不容易触犯规则的保守轨迹" |
| V9 (检测效果) | 最大风险 | Generator 可能退化成生成 easy samples——无人机越来越大、背景越来越简单 |

**V9 的风险最隐蔽**：它的反馈回路允许 Generator 和检测器"互相适应"，最终双方退化成在简单样本上的过拟合循环。

#### 1.4.3 三篇论文为什么不做闭环

ODGEN、FLORA、InstaGen 都只用判别器做**一次性过滤（剔除坏样本）**，从不做**反馈微调 Generator**。这不是缺陷，是刻意设计：

```
ODGEN:   生成 → 判别器过滤（仅剔除）→ 训练检测器 → 结束
FLORA:   生成 → 人工抽查（仅剔除）→ 训练检测器 → 结束
InstaGen: 生成+标注 → CLIP过滤（仅剔除）→ 训练 → 结束
```

#### 1.4.4 CDFF 的过拟合防护锚点

我们的闭环必须有**不受 Generator 影响的硬锚点**：

```
锚点1: V8 物理规则 —— 纯物理约束，不包含可学习参数
        (但 Gen 反馈路径包含 LLM 学习 + 补帧修复，见 §13)
锚点2: 独立对齐/质量裁判 —— 与生成管线完全隔离，只做最终裁决（对齐精度 + 生成质量 + 多样性熵），绝不参与训练
锚点3: 人工校准 —— Validator 的可训练部分永远以人工标注为 ground truth
```

**核心原则**：闭环中只有 Generator 在优化，Validator 的更新永远走人工校准路径，不随 Generator 自动漂移。

## 二、方案：统一分层自训练循环 (v3.0)

### 2.0 核心思路

**每个可训练组件拥有独立的 FailureBuffer + 独立的增量微调管线。中央路由器（Agent 7）根据失败码分派到对应组件的 buffer。v3.0 新增 V1-V5 输入端路由，移除 IR Buffer。**

```
                              ┌──────────────────────────────┐
                              │      Agent 7 九阶段验证        │
                              │      V1→V2→V3→V4→V5          │
                              │      →V6→V7→V8→V9            │
                              └────────────┬─────────────────┘
                                           │
                                    失败样本 + 失败码
                                           │
                              ┌────────────▼─────────────────┐
                              │       Agent 7 失败路由器      │
                              │  根据失败码 → 分派到对应Buffer  │
                              └──┬───────┬───────┬───────────┘
                                 │       │       │
                    ┌────────────▼─┐ ┌───▼────┐ ┌▼──────────┐
                    │  LoRA-Buffer │ │LLM-Buf │ │CN-Buffer  │
                    │  (V4+V6)    │ │(V1+V8) │ │(V3+V7)    │
                    │  阈值: 50条  │ │阈值:30 │ │阈值: 30条  │
                    └──────┬───────┘ └───┬────┘ └─────┬──────┘
                           │            │             │
                    ┌──────▼───────┐ ┌──▼──────┐ ┌───▼────────┐
                    │ 增量LoRA     │ │LLM提示词 │ │CN-LoRA     │
                    │ 低学习率     │ │学习     │ │低秩微调     │
                    │ 小步数       │ │        │ │对比微调     │
                    └──────────────┘ └─────────┘ └────────────┘
                                           │
                                    ┌──────▼──────┐
                                    │ 独立对齐/质量 │  ← 对齐精度+质量+多样性不达标触发
                                    │ 裁判(隔离)   │
                                    └─────────────┘
```

### 2.1 异步双循环不变

生成循环 (Online) 和学习循环 (Offline) 仍然解耦——每个组件各自异步训练，互不阻塞。

### 2.2 V7 二义性路由

CLIP 失败时无法直接判断是场景还是无人机问题：

```
V7_LOW_SIMILARITY
       │
  ┌────▼────────────┐
  │ 分别计算两个CLIP分 │
  │ 场景CLIP vs 无人机CLIP│
  └────┬────────────┘
       │
  ┌────▼─────┐   场景CLIP低  →  CN-Buffer
  │          │   无人机CLIP低 →  LoRA-Buffer
  └──────────┘
```

### 2.3 CN 触发防抖

CN 微调不是攒够就训——需要 **场景类型聚类**。同一类型占比 >50% 才触发。均匀随机失败=prompt/seed 问题，不训模型。

## 三、Generator-Validator 对抗隔离约束

### 3.1 对抗关系定义

Generator 和 Validator 不是合作关系，而是**对抗博弈关系**：

```
Generator 的目标: 生成 Validator 给高分的帧
                   → 不断改进生成质量

Validator 的目标: 准确识别"对检测训练有价值的帧"
                   → 随着 Generator 变强，Validator 的标准也提高
                   → 防止 Generator 找到"弱点"骗高分
```

### 3.2 隔离规则（不可违反）

| 规则 | 说明 |
|:--|:--|
| 1. Validator 绝不从 Generator 的输出中自动学习 | Validator 的可训练部分只能从人工标注数据中更新 |
| 2. Validator 的更新频率远低于 Generator | Generator 每轮生成后评估，Validator 只在积累足够人工标注后才校准 |
| 3. V8 物理规则永不可训 | 物理公式是绝对锚点，但修复路径包含 LLM 学习 + 补帧（锚点本身不变，变的是修复手段） |
| 4. 独立对齐/质量裁判做最终裁决 | 不管闭环里绕了多少轮，最终只看对齐精度 + 生成质量 + 多样性 |
| 5. 人工始终在环中 | Validator 的每次更新必须经过人工确认 |

### 3.3 安全闭环架构

```
                    ┌──────────────┐
                    │  Generator   │  ← 可自动微调（利用 Validator 分数）
                    └──────┬───────┘
                           │ 生成帧 + JSON
                           ▼
              ┌────────────────────────────┐
              │  Validator 验证链（隔离）     │
              │                            │
              │  V1-V5: 纯规则 (不训)        │
              │  V6: 可训练 (EfficientNet)   │
              │  V7: 半规则半可训练           │
              │  V8: 纯物理规则 (永不动)      │ ← 物理锚点不变
              │  V9: 复用 YOLO 检测器        │
              └─────────┬──────────────────┘
                        │
           ┌────────────┼────────────┐
           ▼            ▼            ▼
      通过验证      未通过验证     定期抽样
      → 入训练池    → Buffer      → 人工复检
                        │              │
                        │         Validator 判错？
                        │              │
                        │         ┌────▼────┐
                        │         │ 修正标签 │
                        │         │ Validator│
                        │         │ 重新校准 │ ← 唯一更新路径
                        │         └─────────┘
                        ▼
                  独立对齐/质量裁判
                  → 对齐精度+质量+多样性
```

### 3.4 三层反馈机制

| 层级 | 反馈循环 | 自动化 | 风险 |
|:--|:--|:--|:--|
| L1: 过滤 | Validator 打分 → 好图进训练池 / 坏图进 Buffer | 全自动 | 低（仅剔除，不修改模型） |
| L2: 校准 | Buffer 抽样 → 人工复检 → 修正 Validator | 半自动 | 中（人工锚定） |
| L3: 微调 | Validator 分数 → 奖励信号 → Generator 微调 | 需确认 | 高（需 L1+L2 做够才安全） |

**现阶段建议**：先只做 L1（过滤），L2（校准）在人手够时启动，L3（微调 Generator）等 L1 和 L2 稳定后再考虑。

## 四、三种自训练范式

核心设计决策：**失败图是信号不是数据。** 不同范式决定「用什么数据、怎么训练」。

### A. 正样本筛选（Pass → Train）

```
生成 → 验证通过 → 加入训练集 → 标准微调
       验证失败 → 丢弃
```

- 最简单稳定，只喂"好图"
- 风险：只喂简单样本可能过拟合到已验证模式
- 适用：LoRA 风格微调、YOLO 检测器微调

### B. 失败引导重生成 + 对比学习（Fail → Fix → Contrast）

```
生成 → 验证失败 → 分析失败类型 → 调prompt重生成 → 修复成功?
                                                      │
                                          ┌───────────┘
                                          ▼
                              原失败图(负) vs 修复图(正)
                                          │
                                          ▼
                                DPO/对比损失微调
```

- 直接教模型「同样的条件，要那个不要这个」
- 实现复杂度高（Diffusion-DPO 较新）
- 适用：ControlNet（同条件出图质量波动大）

### C. 质量排序（Rank → Align）

```
生成N张 → 全部打分 → 按分排序 → top-k微调
```

- 不二值判断，用连续分引导
- 风险：打分指标有噪声
- 适用：LoRA 质量提升（有 BRISQUE 天然连续分）

## 五、组件-范式分配 (v3.0)

| 组件 | 范式 | 具体做法 | 触发条件 | 对应 Validator |
|:--|:--|:--|:--|:--|
| **LoRA (Agent 3)** | A→C 渐进 | 初期二值通过，后期 CLIP 分数加权采样 | Buffer≥50条 | V4 + V6 |
| **ControlNet (Agent 3)** | B | 失败图+条件保留→调prompt重生成→修复成功则对比pair→CN-LoRA 低秩微调 | 同场景类型≥30条 | V3 + V7 |
| **LLM (Agent 1)** | B | V1 失败→纠正 prompt 重新生成；V8 失败→轨迹负样本学习 | Buffer≥20条 | V1 + V8 |
| **独立对齐/质量裁判** | 独立 | 与生成管线隔离，评估对齐精度 + BRISQUE + 多样性熵（替代原下游 mAP） | 每轮生成后抽样 | 模块四 |

> 🔥 **v3.0 移除 IR CNN (Agent 6)**。IR 是确定性代码转换，不引入独立生成失败模式，不需要 Validator 也不参与自训练循环。

### 5.1 LoRA 增量微调（范式 A→C）

```
当前权重(v2) → 生成 → CLIP打分 → ≥0.75: 入正样本池
                                  <0.75: 分析失败码
                                         ├─ 场景CLIP低 → CN-Buffer
                                         └─ 无人机CLIP低 → 调prompt重生成
                                                          ├─ CLIP≥0.75 → 入池
                                                          └─ 仍失败 → FailureBuffer
正样本池 ≥50 → 增量微调(低学习率·小步数) → A/B评估 → 替换
```

### 5.2 ControlNet 对比微调（范式 B）

```
V7失败(背景不真实) → 场景类型聚类 → 同类型≥30条 → 触发CN微调
                                                    │
                                                    ▼
                                  取失败样本的depth/pose条件
                                  调整prompt（不动条件图）
                                  重生成 → 背景通过V7 → 形成对比pair
                                                    │
                                                    ▼
                                  CN-LoRA对比微调(低秩)
```

### 5.3 LLM 轨迹学习（范式 B — v3.0 新增）

```
V8失败(轨迹物理异常R3/R4) → 收集失败轨迹 JSON + 物理违规描述
                            │
                    ┌───────┴───────┐
                    ▼               ▼
            ① LLM 负样本学习   ② 补帧插值平滑
            失败轨迹→提示词   在两帧间插入中间态
            优化→LLM避免生成   将突变分散为小幅变化
            同类违规轨迹
```

> 物理规则本身不可被绕过（V8 的 4 条物理公式不变），但修复手段从单一"重生成"扩展为"LLM 学习 + 插值"双路径。

## 六、实现路径

### Phase 1：MVP Validator + 基础循环（当前优先）

**目标**：训练一个可用的基线 Validator，接入生成循环。

#### Step 1：批量生成初始帧

```
从 Generator 跑 200-500 张帧
  ├─ 覆盖不同场景（城市、山、海、夜间）
  ├─ 覆盖不同难度（清晰正面、侧身、远景小目标、遮挡边缘）
  └─ 每个帧都有 JSON 标注（GT bbox、姿态、轨迹）
```

产出：`initial_dataset/` 目录，含 200-500 帧 RGB + JSON。

#### Step 2：人工打分

快速二分类标注：

```
每张帧: 👍 有用 / 👎 没用 / 🤷 跳过
```

200 张约 10 分钟。不需要精细打分，二分类足够启动。

#### Step 3：训练基线 Validator

```
架构:
  EfficientNet-B0 (或 MobileNetV3-Small)
  冻结 backbone 前 N 层
  训练二分类头: "对检测训练有价值 / 无价值"

训练数据:
  正样本: 人工标记 👍（~100 张）
  负样本: 人工标记 👎（~100 张）
```

产出：`validator_v1.pth`。

#### Step 4：接入循环

```
Generator → 生成帧 → Validator 评分
                        ├─ score > 0.5 → 入训练池
                        └─ score < 0.5 → 入 Buffer
```

#### Step 5：观察与校准

- 观察 Validator 评分分布是否合理
- 定期抽取低分帧 + 高分帧做人工复检
- Validator 判错的帧 → 修正标签 → 加入训练集 → Validator 重新微调

### Phase 2：打地基（结构化失败日志）

**目标**：让失败信息可追溯、可复用。

```python
# failure_buffer.py

class FailureBuffer:
    """
    失败样本缓冲池。
    生成循环只写不读，学习循环只读不写。
    """
    def __init__(self, path: str = "failure_log.jsonl", threshold: int = 50):
        self.path = path
        self.threshold = threshold

    def record(self, result: dict) -> None:
        with open(self.path, "a", encoding="utf-8") as f:
            f.write(json.dumps(result, ensure_ascii=False) + "\n")

    def count(self) -> int:
        try:
            with open(self.path, "r", encoding="utf-8") as f:
                return sum(1 for _ in f)
        except FileNotFoundError:
            return 0

    def is_ready(self) -> bool:
        return self.count() >= self.threshold
```

自动归档负样本：

```
failure_buffer/
├── failure_log.jsonl
├── crops/
│   ├── sample_0047_undetectable.png
│   ├── sample_0052_blur.png
│   └── ...
└── v1/
    ├── before_lora.safetensors
    ├── after_lora.safetensors
    └── eval_report.md
```

### Phase 4：论文叙事

**命名**：**CDFF (Closed-loop Data Flywheel Framework)** — 闭环数据飞轮框架。

```
现代合成数据生成管线的核心瓶颈是什么？
  → 固定模型在分布边缘反复失败，无法自我改进。

CDFF 的答案：
  1. 九阶段验证链识别失败模式（what fails）
  2. 结构化失败日志归档失败样本（where it fails）
  3. 异步学习循环将失败反馈转化为增量微调（fix it）
  4. Generator-Validator 对抗隔离防止过拟合（stay safe）
  5. 新权重替换旧权重，下一轮生成质量自动提升（continuous improvement）

与现有工作的关键区别：
  - ODGEN/FLORA/InstaGen: 生成→过滤→训练→结束（单向流水线）
  - CDFF: 生成→验证→反馈→学习→再生成（闭环飞轮）
  - CDFF 的闭环受 V8 物理规则 + 人工校准 + 独立对齐/质量裁判三重锚定
```

## 七、关键设计决策

| 决策 | 理由 | 备选方案 |
|:--|:--|:--|
| 异步而非同步 | GPU 不能同时推理+训练；同步会阻塞生成管线 | 同步（不可行） |
| 批量微调（30-50 条起） | 防单样本过拟合 | 在线学习（不稳定） |
| 增量微调而非从头训练 | 保留已有能力，只做针对性修正 | 从头训练（浪费） |
| 极低学习率 | 防止灾难性遗忘 | — |
| 正样本用新图不用失败图 | 失败图本身是错的，用它训练会污染模型 | 用失败图（不可行） |
| 保留人工审核环节 | 验证链 V1-V9 不是 100% 准确 | 全自动（有风险） |
| Generator-Validator 隔离 | 防止 reward hacking 和共谋 | 耦合更新（高风险） |
| V8 物理规则不可绕过 | 物理公式是绝对锚点，但修复手段可扩展（LLM学习+补帧） | 纯硬锚点（修复手段单一） |
| Validator 只从人工标注学习 | 防止 Validator 随 Generator 漂移 | 自动学习（自欺循环） |
| **不校验 IR** | IR 是确定性代码转换，不引入独立失败模式 | 加 IR Validator（冗余） |
| **输入端全覆盖** | V1-V5 在 GPU 推理前/中拦截，节省算力 | 仅输出端校验（浪费 GPU） |

## 十、附录：三篇论文判别器对比

### ODGEN：前景/背景判别器

```
架构: ImageNet 预训练 ResNet50 → 二分类头 → "该 patch 是否有物体？"

训练数据:
  正样本 = 真实检测数据集中按 GT bbox 裁剪的前景区域
  负样本 = 同一数据集中随机裁剪的背景区域
  分割: 70% 训练 / 10% 验证 / 20% 测试
  测试准确率: > 99%

核心洞察:
  判别的不是"真实 vs 合成"，而是"有物 vs 无物"
  这是一个存在性检查，不是真伪鉴别
  消融贡献: 约 1-2% mAP
```

### FLORA：隐式质量控制

```
没有独立判别器。质量控制来自三个设计决策:

1. Inpainting 天然自带 mask → bbox 位置已知
2. 只生成 500 张，人工可抽查 → 少而精
3. 真实背景图不引入背景域偏移 → 不需要检查背景合理性
```

### InstaGen：CLIP self-check

```
生成图像 → grounding head 输出 bbox
         │
         ├─ 裁剪 bbox 区域 → CLIP 视觉特征
         ├─ CLIP 文本特征 (类别名)
         └─ cos_sim > 阈值 → 保留/丢弃

与 ODGEN 的差别:
  ODGEN: 只检查"有没有物体"（存在性）
  InstaGen: 检查"是不是你想要的类别"（语义一致性）
```

### 三篇 vs CDFF

| 维度 | ODGEN | FLORA | InstaGen | **CDFF** |
|:--|:--|:--|:--|:--|
| 检查什么 | bbox 区域有无物体 | 靠设计避免需检查 | bbox 区域类别是否匹配 | **V1→V9 九阶段全链路** |
| 方法 | ResNet50 二分类 | 人工抽查+真实背景 | CLIP 语义对齐 | **多级自动+人工校准** |
| 训练开销 | 微调预训练模型 | 0（无独立模型） | 0（复用预训练CLIP） | **EfficientNet + 规则引擎** |
| 闭环反馈 | **不做** | **不做** | **不做** | **可选（有约束）** |
| 过拟合防护 | 7域真实测试集 | 真实背景 + 少样本 | COCO+novel split | **V8物理锚 + 独立对齐/质量裁判 + 人工校准** |
| 独特优势 | 工程验证最完备 | 最简洁有效 | 标注最优雅 | **输入端预校验 + 多模态 + 时序 + LLM输入** |

### 关键发现：为什么三篇论文都不用闭环

这不是缺陷，是刻意设计。判别器的输出不回流到 Generator——只做一次性过滤。闭环的风险（reward hacking、多样性崩塌、easy sample 退化）超过潜在收益。CDFF 如果要证明闭环的价值，必须展示在三重锚定（V8物理规则 + 人工校准 + 独立对齐/质量裁判）约束下的净收益。

## 十一、课程学习路径设计

### 11.1 为什么需要课程路径

低慢小物品的生成天然可分阶段，正确的做法是设置**有先后次序的课程路径**，每一步验证过关后才进下一步。课程路径是验证「AI 学习方向正确」的**唯一可追溯方式**。

### 11.2 五阶段渐进课程

```
阶段1: 近距离 + 简单背景 + 正面
  ├─ 学会: 无人机基本外观、轮廓
  ├─ 标准: V6 通过 > 90%, V9 通过 > 80%
  └─ 不通过 → 不进入阶段2

阶段2: 拉远距离 + 变换角度
  ├─ 学会: 尺度不变性、姿态多样性
  ├─ 标准: V7 尺寸一致性 > 85%, V9（远距离小目标）> 60%
  └─ 不通过 → 调整 Generator 架构

阶段3: 复杂背景（城市/山林/海面）
  ├─ 学会: 与背景的空间关系、遮挡边界
  ├─ 标准: V7 光照一致性 > 80%, V6 背景真实感 > 85%
  └─ 不通过 → 检查 Agent 3 CN 重绘质量

阶段4: 连续运动序列
  ├─ 学会: 帧间一致性、运动模糊
  ├─ 标准: V8 轨迹连续性 > 95%
  └─ 不通过 → 触发 V8 双路径：LLM学习 + 补帧

阶段5: 极端条件（低光照/雾/小目标/部分遮挡）
  ├─ 学会: 边缘情况、鲁棒性
  ├─ 标准: 全 V 级综合通过率 > 70%
  └─ 这是最终检验
```

每阶段设 V 级通过率标准，不通过不进下一阶段。确保学习方向可追溯——你知道模型在哪一步开始掉队，而不是对着最终对齐精度/质量分数猜原因。

## 十二、对抗训练偏差分析

### 12.1 对抗训练的必然偏差

Generator 和 Validator 的对抗博弈**没有外部裁判时**必然滑向 easy mode——这是 reward hacking 的典型表现：

```
双方目标:
  Generator: min 自己产出被 Validator 判为失败
  Validator: min 自己把好图判为失败 + 把坏图判为通过

纳什均衡点:
  双方都找到最省力的"互不找茬"状态
  → Generator 专产 Validator 最容易判过的图
  → Validator 的标准悄悄退化到 Generator 的舒适区
```

### 12.2 偏差在各阶段的具体表现

| 阶段 | 偏差表现 | 下游后果 |
|:--|:--|:--|
| V6 退化 | Generator 学会生成纹理平滑的图 → BRISQUE 高分 | 平滑纹理 ≠ 真实场景纹理 → 检测器泛化下降 |
| V7 多样性崩塌 | Generator 专产最容易验证一致性的场景（蓝天背景、水平飞行） | 训练数据多样性消失 |
| V9 easy sample 退化 | Generator 把无人机越来越大、背景越来越简单 | 检测器在复杂场景泛化能力下降 |
| **全局** | **每个指标都绿，但对齐精度/生成质量/多样性不提升** | 闭环最隐蔽的失败模式 |

### 12.3 三重外部硬锚点

闭环内部不可能自己发现自己在退化。必须有不参与反馈回路的独立裁判：

```
               ┌──────────────┐
               │ 闭环内部       │
               │ G ⇄ V 对抗     │  ← 会漂移
               │ "我们觉得很好"  │
               └──────┬───────┘
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
   ┌──────────┐ ┌──────────┐ ┌──────────┐
   │ V8 物理   │ │ 独立对齐/ │ │ 定期人工  │
   │ 规则不变  │ │ 质量裁判  │ │ 抽样      │
   │ 骗不了    │ │ 终极裁判  │ │ 盲区发现  │
   └──────────┘ └──────────┘ └──────────┘
```

| 锚点 | 防什么 | 实现 |
|:--|:--|:--|
| V8 物理规则 | Generator 生成不物理的轨迹骗过视觉检查 | 纯物理公式，无学习参数 |
| 独立对齐/质量裁判 | 闭环在 easy mode 自嗨 | 与生成管线隔离，只做最终对齐精度+质量+多样性裁决 |
| 定期人工抽样 | 自动化指标全绿但图不对劲 | 每 N 轮抽 50 帧人工打分 |

### 12.4 对抗训练的能力边界

**对抗训练能自主做的事**：
- 在固定审查标准下持续提升生成质量
- 自动识别和修复高频失败模式（失败码聚类 → 针对性微调）

**对抗训练不能自主做的事**：
- 知道 Validator 标准是否在漂移（需独立裁判）
- 知道自己的生成是否真正对检测训练有用（需人工抽样）
- 发现全新类型的失败（需人工发现未知的未知）

**结论**：让对抗训练自动处理 80% 已知问题，剩余 20%（标准漂移、未知失败模式、方向性判断）靠三重锚点兜底。ODGEN/FLORA/InstaGen 不做闭环不是因为技术做不到，而是因为闭环的锚点设计成本和持续人工监控成本超过单向流水线的收益。CDFF 要证明闭环有净收益，唯一方式是让三重锚点足够扎实，并用实验数据证明"有闭环的对齐精度/质量/多样性增益 > 无闭环"。

## 十三、反馈闭环路由机制 (v3.0)

### 13.1 路由表：失败追溯到 v7.2 管线组件

Validator 各级失败必须追溯到 v7.2 管线的对应组件，精确到子步骤：

| Validator 失败 | 责任组件 | 反馈目标 | 修复手段 |
|:--|:--|:--|:--|
| V1 JSON 自洽失败 | Agent 1 (LLM) | Agent 1 | 附带失败字段 + 矛盾描述 → LLM 纠正 prompt 重新生成 |
| V2 背景匹配失败 | Agent 2 (背景匹配) | Agent 2 | 尝试 37,852-image pool 下一个候选（最多 3 fallback） |
| V3 深度/分割质量差 | Agent 3 Step 1 (Depth/Seg) | Agent 3 Step 1 | 调整 MidasDepth/HeuristicSeg 参数或换背景重提取 |
| V4 LoRA artifact | Agent 3 Step 2 (LoRA Gen) | Agent 3 LoRA | 调 seed/CFG 重生成（3次）→ 仍失败则积累负样本 → LoRA 微调 |
| V5 Focus 偏移 | Agent 3 Step 5 (Focus) | Agent 3 Step 5 | 重新计算偏移矩阵 |
| V6 图像质量差 | Agent 3 Step 2 (LoRA Gen) | Agent 3 LoRA | 调 CFG/seed/steps 重生成 → 积累 → LoRA 微调（范式 B） |
| V7 尺寸不对 | Agent 1 (LLM) + Agent 3 | 需诊断 | 先人工判断：JSON 距离参数问题→Agent 1；CN 重绘尺寸偏差→Agent 3 Step 4 |
| V7 光照不一致 | Agent 1 (LLM) + Agent 3 | 需诊断 | 先人工判断光照参数 vs CN 渲染 |
| V8 位置/尺寸异常 (R1/R2) | Agent 1 (LLM) | Agent 1 | LLM 轨迹 JSON 不合理 → 重新生成轨迹参数 |
| V8 加速度/方向异常 (R3/R4) | Agent 1 (LLM) | Agent 1 | ① LLM 负样本学习（避免同类违规）② 补帧插值平滑 |
| V9 检测不到 | Agent 3 Step 2 (LoRA Gen) | Agent 3 LoRA | 负样本记录（v4：不驱动微调，RQ4 移入 future work） |

### 13.2 两种反馈速度

**快速反馈：即时 L1 过滤**
```python
for frame_batch in generator.produce():
    result = validator.check(frame_batch)
    if result.passed:
        training_pool.add(frame_batch)   # 即时入库
    else:
        buffer.add(frame_batch, result)  # 附带失败码
```
每帧生成后立即验证，通过→训练池，失败→FailureBuffer。这是防火墙——坏图不进训练池。

**慢速反馈：周期性 L2→L3 微调**

FailureBuffer 积累到阈值后触发，不逐条响应：
```
FailureBuffer → 按失败码聚类 → 识别高频失败模式 → 触发微调
    ├── V4+V6 失败堆积 > 50 条 → 微调 Agent 3 (LoRA)
    ├── V3+V7 失败堆积 > 30 条 → 微调 Agent 3 (CN-LoRA)
    ├── V1+V8 失败堆积 > 20 条 → Agent 1 (LLM 提示词优化)
    └── V2+V5 失败 → 低频，即时修复不堆积
```

### 13.3 三种微调范式的路由分配 (v3.0)

| 范式 | 触发条件 | 目标 Agent | 操作 |
|:--|:--|:--|:--|
| **A. 正样本增量** | 正常通过验证的帧 | Agent 3 LoRA | 通过帧 → 增量 LoRA |
| **B. 失败对比学习** | 特定失败模式堆积 | Agent 3 LoRA / CN / Agent 1 LLM | 失败 vs 修正 → 对比微调 / 提示词优化 |
| **C. 质量排序** | 精细化质量提升 | Agent 3 LoRA | 同场景多输出排序 → 偏好优化 |

### 13.4 完整循环示例 (v3.0)

假设批量生成 500 帧，经过九阶段 Validator：

```
V1 通过: 498/500, 失败: 2 → 即时返回 Agent 1 重新生成 JSON
V2 通过: 500/500 (2 个 fallback 到兜底)
V3 通过: 495/500, 失败: 5 → 重提取，3 恢复 + 2 失败入 CN-Buffer
V4 通过: 488/493, 失败: 5 → 重生成，4 恢复 + 1 入 LoRA-Buffer
V5 通过: 492/492 (Focus 重定位修复全部通过)
V6 通过: 430/492, 失败: 62 → LoRA-Buffer（52 BRISQUE + 10 其他）
V7 通过: 410/430, 失败: 20 → CN-Buffer (14 尺寸 + 6 光照)
V8 通过: 408/410, 失败: 2 → 2 条入 LLM-Buffer (加速度异常)
V9 通过: 390/408, 失败: 18 → 记录（v4：不驱动微调，RQ4 移入 future work）

最终: 390 帧入训练池, 92 帧入 Buffer（V9 失败 18 帧仅记录，不驱动微调）
```

触发反馈：
- 62+1 = 63 条入 LoRA-Buffer → 超过 50 阈 → 触发 Agent 3 LoRA 微调（范式 B）
- 5+20 = 25 条入 CN-Buffer → 未到 30 阈 → 继续积累
- 2 条入 LLM-Buffer → 低频，不触发

| V7（姿态） | 自动驾驶车辆姿态预测（Waymo/nuScenes） | **部分成熟** | 领域不同但方法论可迁移 |
| V8 | 无 | **N/A** | 纯物理约束（高中力学），不需要论文引用 |
| V9 | COCO eval 协议 (Lin, ECCV 2014) + Ultralytics YOLO | **成熟** | 目标检测评估事实标准 |

### 14.2 创新定位

**审查端单个模块都不是创新**——每个 V 都有成熟参考或极简单无需参考。创新在：
1. **九阶段串联架构**（V1→V2→V3→V4→V5→V6→V7→V8→V9 短路求值）
2. **输入端预校验 V1-V5**（在 GPU 推理前/中拦截，节省算力）
3. **对抗隔离约束**（Validator-Generator 隔离规则五条）
4. **课程学习路径**（五阶段渐进 + 逐阶段验证标准）
5. **反馈闭环路由**（失败码 → 责任定位 → 精确微调，覆盖 v7.2 全管线）

这是整体系统设计贡献，不是某个算法点的突破。

## 十五、Validator 硬化调度器 (Curriculum Hardening Scheduler)

> 🔥 v3.1 新增。解决 Generator 变强但 Validator 原地不动的问题——这是真正的对抗升级最后一环。

### 15.1 为什么需要硬化调度器

笔记6 §3.1 定义了对抗关系（Generator 目标欺骗，Validator 目标识别），但 v3.0 的反馈循环只更新 Generator。有效对抗需要双方协同升级。

```
v3.0 的问题:
  Generator: 不断微调变强 ↑
  Validator: 阈值永远不变
  → 通过率最终到 98%+ → Validator 变成橡皮图章

硬化调度器的作用:
  监控 Validator 通过率 → 自动收紧阈值（L1）
  收集 borderline 样本 → 触发人工重校准（L2）
  在线检测模式崩塌 → V_diversity 惩罚（L3）
  → 双方在物理锚定约束下共同升级
```

### 15.2 硬化调度器架构

```
                    ┌──────────────────────────────┐
                    │      Agent 7 九阶段验证        │
                    │      V1→V2→V3→V4→V5          │
                    │      →V6→V7→V8→V9            │
                    │                              │
                    │  🆕 V_diversity (多样性检查)  │
                    └────────────┬─────────────────┘
                                 │
                        失败样本 + 失败码
                                 │
                    ┌────────────▼─────────────────┐
                    │       Agent 7 失败路由器      │
                    └──┬───────┬───────┬───────────┘
                       │       │       │
              ┌────────▼─┐ ┌──▼────┐ ┌▼──────────┐
              │LoRA-Buffer│ │LLM-Buf│ │CN-Buffer  │
              │(V4+V6)   │ │(V1+V8)│ │(V3+V7)   │
              └────┬──────┘ └───┬───┘ └─────┬─────┘
                   │            │            │
        ┌──────────▼────────────▼────────────▼──────┐
        │         🆕 Validator 硬化调度器             │
        │                                            │
        │  每 N 轮生成后:                             │
        │  1. 统计各 V 级通过率                       │
        │  2. 若超过触发阈值 → 执行 L1 阈值递增        │
        │  3. 收集 borderline 样本 → L2 候选池        │
        │  4. 计算入库池多样性 → L3 相似度             │
        │  5. 独立对齐/质量裁判监控 → 异常则回滚        │
        └────────────────────────────────────────────┘
```

### 15.3 L1：阈值自动递增

| Validator | 指标 | 初始 | 触发(pass_rate) | 步长 | 物理边界 | 回滚条件 |
|:--|:--|:--|:--|:--|:--|:--|
| V2 | CLIP sim | ≥0.22 | >95% | +0.03 | ≤0.35 | 对齐精度/质量↓>1% |
| V4 | SSIM | <0.85 | >95% | -0.03 | ≥0.72 | 对齐精度/质量↓>1% |
| V6 | BRISQUE | <35 | >90% | -5 | ≥18 | 对齐精度/质量↓>2% |
| V7-D2 | KL div | <0.25 | >85% | -0.03 | ≥0.12 | 对齐精度/质量↓>1% |
| V7-D4 | IoU | >0.95 | >90% | 不动 | — | 已饱和 |
| V9 | YOLO conf | — | — | 不动 | — | 检测有效性（RQ4 降级为设计参考） |

**递增规则**：
- 每次收紧后至少观察一个 epoch（≥500 帧）才考虑下一次
- 步长约为初始~边界间距的 1/4，保证温和递进
- pass_rate 在收紧后跌破 70% → 立即回滚

### 15.4 L2：Hard-Negative 重校准

```
Generator 当前通过率 92%（V6 BRISQUE < 35）
    │
    ▼
收集 borderline 样本: BRISQUE ∈ [29, 42]（阈值±20%）
    │
    ▼
人工打标 → 这些是真的好图还是擦边过？
    │
    ├─ 真的好 → 阈值合理，不调整
    │
    └─ 假好图 → 标记为 hard negatives
              → EfficientNet 增量微调（冻结backbone，只训head）
              → 对比损失：positive=真好图，negative=人工标记假好图
```

### 15.5 L3：V_diversity 多样性惩罚

```
新帧 drone crop → CLIP 特征 → FAISS 最近邻检索 vs 入库池
    │
    ├─ max_sim < 0.90 → PASS
    ├─ 0.90 ≤ max_sim < 0.95 → WARNING（连续10帧→升级FAIL）
    └─ max_sim ≥ 0.95 → FAIL → 反馈 Agent 3 LoRA（增加多样性）
```

失败码: `V10_MODE_COLLAPSE` / `V10_LOW_DIVERSITY`（详见笔记6 §9.5）

### 15.6 Buffer 联动：硬化后的 Buffer 分配更新

L2 重校准引入了一个新的缓冲区类型——borderline 样本不立即反馈 Generator，而是进入人工审核队列：

| Buffer | 来源 | 阈值 | 触发动作 | 新增行为 |
|:--|:--|:--|:--|:--|
| LoRA-Buffer | V4+V6 失败 | 50 | Agent 3 LoRA 微调 | — |
| CN-Buffer | V3+V7 失败 | 30 | Agent 1/3 CN 微调 | — |
| LLM-Buffer | V1+V8 失败 | 20 | Agent 1 LLM 学习 | — |
| **🆕 Borderline Pool** | V2/V4/V6/V7 borderline | 100 | 触发人工审核→L2 重校准 | 新增 |

### 15.7 回滚机制

硬化不是单调推进。以下条件触发回滚：

| 触发条件 | 回滚动作 | 冷却期 |
|:--|:--|:--|
| 独立裁判对齐精度/质量 ↓ > 2%（vs 上一 epoch） | 回滚最新一次 L1 阈值收紧 | 继续观察 2 epochs |
| 连续 3 次 L1 收紧后对齐精度/质量均下降 | 永久锁定该 V 级阈值 | 除非人工手动解锁 |
| V_diversity 连续拒绝 > 40% 帧 | 放宽容忍度（0.90→0.85） | 直到 pass_rate 恢复 |
| 人工抽查发现系统性误判 | 触发紧急 L2 重校准 | 直到过人工审核 |

### 15.8 与三篇论文的差异化（更新）

| 维度 | ODGEN/FLORA/InstaGen | CDFF v3.0 | CDFF v3.1 + Hardening |
|:--|:--|:--|:--|
| Validator 角色 | 一次性过滤 | 静态多阶段审查 | **动态递进审查者** |
| 对抗关系 | 无 | Generator 单向优化 | **双向对抗升级** |
| 多样性保障 | 依赖数据源多样性 | 无显式约束 | **L3 V_diversity 显式惩罚** |
| 可证明性 | 难以证明 | 难以证明 | **回滚机制提供可追溯边界** |
| 长期稳定性 | 不变 | Generator 漂移风险 | **阈值物理边界 + 对齐/质量裁判监控** |

### 15.9 实施优先级

| 任务 | 优先级 | 成本 | 前置依赖 |
|:--|:--|:--|:--|
| L3 V_diversity (V10) | 🔴 最高 | 极低（零训练） | CLIP 模型 + FAISS |
| L1 阈值递增框架 | 🔴 最高 | 低（纯规则） | epoch 统计可用 |
| L1 回滚逻辑 | 高 | 低 | 对齐/质量裁判就位 |
| L2 borderline 收集器 | 中 | 低（纯存储） | 无 |
| L2 人工审核管线 | 中 | 中（需UI/流程） | borderline 池 > 100 |
| L2 EfficientNet 增量微调 | 低 | 中（需训练脚本） | 人工标注数据 |
| 硬化调度器主循环 | 高 | 中 | L1+L3 就位 |

**MVP 建议**：先上线 L3（V_diversity）+ L1（阈值递增），这两项成本极低但效果显著——L3 防止模式崩塌，L1 防止 Validator 失效。L2 重校准等积累足够数据后再启动。
