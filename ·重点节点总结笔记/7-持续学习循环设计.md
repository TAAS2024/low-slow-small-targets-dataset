## 一、问题诊断

### 1.1 当前 Agent 7 能做什么

```
验证失败 → 查失败码分派表 → 调参数 → 重新生成 → 最多重试 3 次 → 人工审查
```

| 失败码 | 调整动作 | 性质 |
|:--|:--|:--|
| `S6_BG_UNREALISTIC` | 换 ControlNet seed | 参数级 |
| `S9_UNDETECTABLE` | 调 LoRA weight / CFG scale | 参数级 |
| `S6_BLUR` | 提高推理步数 | 参数级 |

### 1.2 不能做什么

**模型权重从未改变。** Agent 7 是在一个**冻结的 LoRA 上搜索更优的推理参数**，不是让 LoRA 从错误中学习。

```
当前 Agent 7:
  S9_UNDETECTABLE → 调 LoRA weight=0.7→0.9 → 重新生成
                    ↑
                    模型能力不变，只是赌另一组参数效果更好

期望的持续学习:
  S9_UNDETECTABLE → 这张图标记为负样本 → 加入训练集 → LoRA 增量微调
                    ↑
                    模型从失败中学习，消除该类错误
```

### 1.3 为什么不能直接在生成循环中学习

| 约束 | 说明 |
|:--|:--|
| LoRA 微调吃 GPU | RTX 4060 上至少 10 分钟，不可能嵌在 Web 请求里 |
| 单张图微调 = 过拟合 | 1 张负样本做梯度更新直接导致模式崩塌 |
| 验证链有噪声 | S8 误判需要人工核验，不能盲信 |
| 生成和训练互斥 | GPU 无法同时推理和训练 |

### 1.4 闭环自训练的过拟合风险 ⚠️

> 2026-08-03 新增。这是本轮讨论的核心发现。

#### 1.4.1 Goodhart's Law 陷阱

闭环的底层逻辑是：Generator 产出的数据 → Validator 打分 → 分数回流微调 Generator。这里有一个致命盲区：**Validator 本身不是真理，它只是一个模型或一组规则**。当 Validator 的评分变成 Generator 的优化目标，Generator 不需要真正生成"对检测训练有用的图"，只需要生成"Validator 会给高分的图"。

这在强化学习里叫 **reward hacking**，在社会科学里叫 **Goodhart's Law**：当一个指标变成目标，它就不再是好的指标。

#### 1.4.2 按 S 阶段逐层剖析

| 阶段 | 风险 | 具体表现 |
|:--|:--|:--|
| S6（图像质量）| 纹理过平滑 | Generator 学会生成 FID 好看的图，但纹理过于平滑、边缘过于干净——与真实场景的噪声分布不一致 → 检测器在真实场景反而变差 |
| S7（一致性）| 多样性崩塌 | Generator 学会生成"最容易验证一致"的场景——无人机永远在蓝天背景中央、姿态永远水平 → 训练数据多样性消失 |
| S8（轨迹）| 间接信号 | 相对安全，但也是间接优化目标 |
| S9（检测器效果）| 最大风险 | Generator 可能退化成生成 easy samples——无人机越来越大、背景越来越简单 → 检测器在真实复杂场景泛化能力下降。你以为 mAP 提高了，其实是 Generator 在降级 |

**S9 的风险最隐蔽**：它的反馈回路允许 Generator 和检测器"互相适应"，最终双方退化成在简单样本上的过拟合循环。

#### 1.4.3 三篇论文为什么不做闭环

ODGEN、FLORA、InstaGen 都只用判别器做**一次性过滤（剔除坏样本）**，从不做**反馈微调 Generator**。这不是缺陷，是刻意设计：

```
ODGEN:   生成 → 判别器过滤（仅剔除）→ 训练检测器 → 结束
FLORA:   生成 → 人工抽查（仅剔除）→ 训练检测器 → 结束
InstaGen: 生成+标注 → CLIP过滤（仅剔除）→ 训练 → 结束
```

判别器的输出永远不回流到 Generator 的训练循环。

> 🔗 **保底方案**：如果 CDFF 自循环经多轮迭代后主方案（Dual CN 合成背景）仍不达标，我们有降级路径：切换至真实背景图 + Inpainting 方案。触发条件与具体方案详见 [[5-ControlNet场景生成管线#十三、保底方案：真实背景图 + Inpainting 降级路径]]。

#### 1.4.4 CDFF 的过拟合防护锚点

我们的闭环如果要存在，必须有一个**绝对不受 Generator 影响的硬锚点**：

```
锚点1: S8 物理规则 —— 纯物理约束，不包含任何可学习参数，不可能被 Generator "hack"
锚点2: 独立真实测试集 —— 与生成管线完全隔离，只做最终裁决，绝不参与训练
锚点3: 人工校准 —— Validator 的可训练部分永远以人工标注为 ground truth
```

**核心原则**：闭环中只有 Generator 在优化，Validator 的更新永远走人工校准路径，不随 Generator 自动漂移。

## 二、方案：统一分层自训练循环 (v2.0)

### 2.0 核心思路

**每个可训练组件拥有独立的 FailureBuffer + 独立的增量微调管线。中央路由器（Agent 7）根据失败码分派到对应组件的 buffer。**

```
                              ┌──────────────────────────────┐
                              │       Agent 6 四阶段验证       │
                              │  S6→S7→S8→S9                 │
                              └────────────┬─────────────────┘
                                           │
                                    失败样本 + 失败码
                                           │
                              ┌────────────▼─────────────────┐
                              │       Agent 7 失败路由器      │
                              │  根据失败码 → 分派到对应Buffer  │
                              └──┬───────┬───────┬───────────┘
                                 │       │       │
                    ┌────────────▼─┐ ┌───▼────┐ ┌▼──────────┐
                    │  CN-Buffer   │ │LoRA-Buf│ │ IR-Buf    │
                    │  阈值: 30条  │ │阈值:50 │ │ 阈值:20条  │
                    └──────┬───────┘ └───┬────┘ └─────┬──────┘
                           │            │             │
                    ┌──────▼───────┐ ┌──▼──────┐ ┌───▼────────┐
                    │  CN-LoRA     │ │增量LoRA │ │ 轻量CNN    │
                    │  rank=4      │ │lr=1e-6  │ │ 增量微调    │
                    │  对比微调     │ │400步    │ │            │
                    └──────────────┘ └─────────┘ └────────────┘
                                           │
                                    ┌──────▼──────┐
                                    │ YOLO 外环    │  ← 下游mAP不涨触发
                                    │ 合成+真实混合 │
                                    └─────────────┘
```

### 2.1 异步双循环不变

生成循环 (Online) 和学习循环 (Offline) 仍然解耦——每个组件各自异步训练，互不阻塞。

### 2.2 S7 二义性路由

CLIP 失败时无法直接判断是场景还是无人机问题：

```
S7_LOW_SIMILARITY
       │
  ┌────▼────────────┐
  │ 分别计算两个CLIP分 │
  │ 场景CLIP vs 无人机CLIP│
  └────┬────────────┘
       │
  ┌────▼─────┐   场景CLIP低  →  CN-Buffer
  │          │   无人机CLIP低 →  LoRA-Buffer
  └──────────┘
```

### 2.3 CN 触发防抖

CN 微调不是攒够就训——需要 **场景类型聚类**。同一类型占比 >50% 才触发。均匀随机失败=prompt/seed 问题，不训模型。

## 三、Generator-Validator 对抗隔离约束（2026-08-03 新增）

### 3.1 对抗关系定义

Generator 和 Validator 不是合作关系，而是**对抗博弈关系**：

```
Generator 的目标: 生成 Validator 给高分的帧
                   → 不断改进生成质量

Validator 的目标: 准确识别"对检测训练有价值的帧"
                   → 随着 Generator 变强，Validator 的标准也提高
                   → 防止 Generator 找到"弱点"骗高分
```

### 3.2 隔离规则（不可违反）

| 规则 | 说明 |
|:--|:--|
| 1. Validator 绝不从 Generator 的输出中自动学习 | Validator 的可训练部分只能从人工标注数据中更新 |
| 2. Validator 的更新频率远低于 Generator | Generator 每轮生成后评估，Validator 只在积累足够人工标注后才校准 |
| 3. S8 永不可训 | 物理规则是绝对锚点 |
| 4. 独立真实测试集做最终裁决 | 不管闭环里绕了多少轮，最终只看真实测试集 mAP |
| 5. 人工始终在环中 | Validator 的每次更新必须经过人工确认 |

### 3.3 安全闭环架构

```
                    ┌──────────────┐
                    │  Generator   │  ← 可自动微调（利用 Validator 分数）
                    └──────┬───────┘
                           │ 生成帧 + JSON
                           ▼
              ┌────────────────────────────┐
              │    Validator 验证链（隔离）   │
              │                            │
              │  S6: 可训练 (EfficientNet)  │
              │  S7: 半规则半可训练          │
              │  S8: 纯物理规则（永不动）     │ ← 硬锚点
              │  S9: 复用 YOLO 检测器        │
              │                            │
              └─────────┬──────────────────┘
                        │
           ┌────────────┼────────────┐
           ▼            ▼            ▼
      通过验证      未通过验证     定期抽样
      → 入训练池    → Buffer      → 人工复检
                        │              │
                        │         Validator 判错？
                        │              │
                        │         ┌────▼────┐
                        │         │ 修正标签 │
                        │         │ Validator│
                        │         │ 重新校准 │ ← 唯一更新路径
                        │         └─────────┘
                        ▼
                  独立真实测试集
                  → mAP 裁判
```

### 3.4 三层反馈机制

| 层级 | 反馈循环 | 自动化 | 风险 |
|:--|:--|:--|:--|
| L1: 过滤 | Validator 打分 → 好图进训练池 / 坏图进 Buffer | 全自动 | 低（仅剔除，不修改模型） |
| L2: 校准 | Buffer 抽样 → 人工复检 → 修正 Validator | 半自动 | 中（人工锚定） |
| L3: 微调 | Validator 分数 → 奖励信号 → Generator 微调 | 需确认 | 高（需 L1+L2 做够才安全） |

**现阶段建议**：先只做 L1（过滤），L2（校准）在人手够时启动，L3（微调 Generator）等 L1 和 L2 稳定后再考虑。

## 四、三种自训练范式

核心设计决策：**失败图是信号不是数据。** 不同范式决定「用什么数据、怎么训练」。

### A. 正样本筛选（Pass → Train）

```
生成 → 验证通过 → 加入训练集 → 标准微调
       验证失败 → 丢弃
```

- 最简单稳定，只喂"好图"
- 风险：只喂简单样本可能过拟合到已验证模式
- 适用：LoRA 风格微调、YOLO 检测器微调

### B. 失败引导重生成 + 对比学习（Fail → Fix → Contrast）

```
生成 → 验证失败 → 分析失败类型 → 调prompt重生成 → 修复成功?
                                                      │
                                          ┌───────────┘
                                          ▼
                              原失败图(负) vs 修复图(正)
                                          │
                                          ▼
                                DPO/对比损失微调
```

- 直接教模型「同样的条件，要那个不要这个」
- 实现复杂度高（Diffusion-DPO 较新）
- 适用：ControlNet（同条件出图质量波动大）

### C. 质量排序（Rank → Align）

```
生成N张 → 全部打分 → 按分排序 → top-k微调
```

- 不二值判断，用连续分引导
- 风险：打分指标有噪声
- 适用：IR CNN（有 BRISQUE 天然连续分）

## 五、组件-范式分配

| 组件 | 范式 | 具体做法 | 触发条件 |
|:--|:--|:--|:--|
| **LoRA** | A→C 渐进 | 初期二值通过，后期 CLIP 分数加权采样 | Buffer≥50条 |
| **ControlNet** | B | 失败图+条件保留→调prompt重生成→修复成功则对比pair→CN-LoRA rank=4 | 同场景类型≥30条 |
| **IR CNN** | C | 每批BRISQUE排序→top-50%训练→增量微调5epoch lr=1e-5 | Buffer≥20条 |
| **YOLO** | A | 合成图通过检测→混真实数据→标准微调 | 外环：下游mAP不涨 |

### 5.1 LoRA 增量微调（范式 A→C）

```
当前权重(v2) → 生成 → CLIP打分 → ≥0.75: 入正样本池
                                  <0.75: 分析失败码
                                         ├─ 场景CLIP低 → CN-Buffer
                                         └─ 无人机CLIP低 → 调prompt重生成
                                                          ├─ CLIP≥0.75 → 入池
                                                          └─ 仍失败 → FailureBuffer
正样本池 ≥50 → Kohya增量微调(lr=1e-6, 400步) → A/B评估 → 替换
```

### 5.2 ControlNet 对比微调（范式 B）

```
S6失败(背景不真实) → 场景类型聚类 → 同类型≥30条 → 触发CN微调
                                                    │
                                                    ▼
                                  取失败样本的depth/pose条件
                                  调整prompt（不动条件图）
                                  重生成 → 背景通过S6 → 形成对比pair
                                                    │
                                                    ▼
                                  CN-LoRA对比微调(rank=4)
```

### 5.3 IR CNN 质量排序微调（范式 C）

```
RGB → 当前CNN → IR → BRISQUE → 全batch排序
                                 ├─ top-50% → 正样本 → 增量微调(5epoch lr=1e-5)
                                 └─ bottom-50% → 暂不纳入
```

## 六、实现路径

### Phase 1：MVP Validator + 基础循环（当前优先）

> 2026-08-03 新增。目标是先跑通一根简单的线。

**目标**：训练一个可用的基线 Validator，接入生成循环。

#### Step 1：批量生成初始帧

```
从 Generator 跑 200-500 张帧
  ├─ 覆盖不同场景（城市、山、海、夜间）
  ├─ 覆盖不同难度（清晰正面、侧身、远景小目标、遮挡边缘）
  └─ 每个帧都有 JSON 标注（GT bbox、姿态、轨迹）
```

产出：`initial_dataset/` 目录，含 200-500 帧 RGB + JSON。

#### Step 2：人工打分

快速二分类标注：

```
每张帧: 👍 有用 / 👎 没用 / 🤷 跳过
```

200 张约 10 分钟。不需要精细打分，二分类足够启动。

#### Step 3：训练基线 Validator

```
架构:
  EfficientNet-B0 (或 MobileNetV3-Small)
  冻结 backbone 前 N 层
  训练二分类头: "对检测训练有价值 / 无价值"

训练数据:
  正样本: 人工标记 👍（~100 张）
  负样本: 人工标记 👎（~100 张）
```

产出：`validator_v1.pth`。

#### Step 4：接入循环

```
Generator → 生成帧 → Validator 评分
                        ├─ score > 0.5 → 入训练池
                        └─ score < 0.5 → 入 Buffer
```

#### Step 5：观察与校准

- 观察 Validator 评分分布是否合理
- 定期抽取低分帧 + 高分帧做人工复检
- Validator 判错的帧 → 修正标签 → 加入训练集 → Validator 重新微调

### Phase 2：打地基（结构化失败日志）

**目标**：让失败信息可追溯、可复用。

#### 结构化失败日志

在 Agent 6 验证输出处加 `record()` 调用：

```python
# failure_buffer.py

class FailureBuffer:
    """
    失败样本缓冲池。
    生成循环只写不读，学习循环只读不写。
    """
    def __init__(self, path: str = "failure_log.jsonl", threshold: int = 50):
        self.path = path
        self.threshold = threshold

    def record(self, result: dict) -> None:
        with open(self.path, "a", encoding="utf-8") as f:
            f.write(json.dumps(result, ensure_ascii=False) + "\n")

    def count(self) -> int:
        try:
            with open(self.path, "r", encoding="utf-8") as f:
                return sum(1 for _ in f)
        except FileNotFoundError:
            return 0

    def is_ready(self) -> bool:
        return self.count() >= self.threshold
```

#### 自动归档负样本

```
failure_buffer/
├── failure_log.jsonl
├── crops/
│   ├── sample_0047_undetectable.png
│   ├── sample_0052_blur.png
│   └── ...
└── v1/
    ├── before_lora.safetensors
    ├── after_lora.safetensors
    └── eval_report.md
```

### Phase 4：论文叙事

**命名**：**CDFF (Closed-loop Data Flywheel Framework)** — 闭环数据飞轮框架。

```
现代合成数据生成管线的核心瓶颈是什么？
  → 固定模型在分布边缘反复失败，无法自我改进。

CDFF 的答案：
  1. 四阶段验证链识别失败模式（what fails）
  2. 结构化失败日志归档失败样本（where it fails）
  3. 异步学习循环将失败反馈转化为增量微调（fix it）
  4. Generator-Validator 对抗隔离防止过拟合（stay safe）
  5. 新权重替换旧权重，下一轮生成质量自动提升（continuous improvement）

与现有工作的关键区别：
  - ODGEN/FLORA/InstaGen: 生成→过滤→训练→结束（单向流水线）
  - CDFF: 生成→验证→反馈→学习→再生成（闭环飞轮）
  - 但 CDFF 的闭环受 S8 物理规则 + 人工校准 + 独立测试集三重锚定
```

## 七、关键设计决策

| 决策 | 理由 | 备选方案 |
|:--|:--|:--|
| 异步而非同步 | GPU 不能同时推理+训练；同步会阻塞生成管线 | 同步（不可行） |
| 批量微调（50 条起）| 防单样本过拟合 | 在线学习（不稳定） |
| 增量微调而非从头训练 | 保留已有能力，只做针对性修正 | 从头训练（浪费） |
| 极低学习率（1e-6）| 防止灾难性遗忘 | — |
| 正样本用新图不用失败图 | 失败图本身是错的，用它训练会污染模型 | 用失败图（不可行） |
| 保留人工审核环节 | 验证链 S0-S3 不是 100% 准确 | 全自动（有风险） |
| Generator-Validator 隔离 | 防止 reward hacking 和共谋 | 耦合更新（高风险） |
| S8 永不可训 | 物理规律是绝对锚点，不能被优化 | 可训规则（失去锚点意义） |
| Validator 只从人工标注学习 | 防止 Validator 随 Generator 漂移 | 自动学习（自欺循环） |
| **保底降级路径** | 若 CDFF 多轮后主方案不达标 → 切换真实背景 + Inpainting 方案 | 硬撑主方案（有论文交付风险） |

## 十、附录：三篇论文判别器对比

> 2026-08-03 新增。为 CDFF 的 Validator 设计提供对标参考。

### ODGEN：前景/背景判别器

```
架构: ImageNet 预训练 ResNet50 → 二分类头 → "该 patch 是否有物体？"

训练数据:
  正样本 = 真实检测数据集中按 GT bbox 裁剪的前景区域
  负样本 = 同一数据集中随机裁剪的背景区域
  分割: 70% 训练 / 10% 验证 / 20% 测试
  测试准确率: > 99%

推理:
  每张合成图的每个 pseudo label bbox 区域裁剪
  → 喂判别器
  → 有物体 → 保留 label
  → 没物体 → 丢弃 label

核心洞察:
  判别的不是"真实 vs 合成"，而是"有物 vs 无物"
  这是一个存在性检查，不是真伪鉴别
  消融贡献: 约 1-2% mAP
```

### FLORA：隐式质量控制

```
没有独立判别器。质量控制来自三个设计决策:

1. Inpainting 天然自带 mask:
   物体生成位置已知 → Grounding DINO 在 mask 附近精修 bbox
   比 ODGEN"全图生成再判别"省一步

2. 只生成 500 张，人工可抽查:
   少而精策略，省掉复杂判别器的工程开销

3. 真实背景图不引入背景域偏移:
   ODGEN 判别器盲区：检查 bbox 有无物体，但不检查背景是否合理
   FLORA 没有这个问题——背景就是真实的
```

### InstaGen：CLIP self-check

```
生成图像 → grounding head 输出 bbox
         │
         ├─ 裁剪每个 bbox 区域
         ├─ CLIP 视觉编码 → 视觉特征 v
         ├─ CLIP 文本编码("car") → 文本特征 t
         └─ cos_sim(v, t) > 阈值？
              ├─ 是 → 保留
              └─ 否 → 丢弃

与 ODGEN 的差别:
  ODGEN: 只检查"有没有物体"（存在性）
  InstaGen: 检查"是不是你想要的类别"（语义一致性）
  后者更精确，但依赖 CLIP 本身的域泛化能力
```

### 三篇 vs CDFF

| 维度 | ODGEN | FLORA | InstaGen | **CDFF** |
|:--|:--|:--|:--|:--|
| 检查什么 | bbox 区域有无物体 | 靠设计避免需检查 | bbox 区域类别是否匹配 | **S6→S7→S8→S9 全链路** |
| 方法 | ResNet50 二分类 | 人工抽查+真实背景 | CLIP 语义对齐 | **多级自动+人工校准** |
| 训练开销 | 微调预训练模型 | 0（无独立模型）| 0（复用预训练CLIP）| **EfficientNet + 规则引擎** |
| 闭环反馈 | **不做** | **不做** | **不做** | **可选（有约束）** |
| 过拟合防护 | 7域真实测试集 | 真实背景 + 少样本 | COCO+novel split | **S8物理锚 + 独立测试集 + 人工校准** |
| 独特优势 | 工程验证最完备 | 最简洁有效 | 标注最优雅 | **多模态 + 时序 + 自然语言输入** |

### 关键发现：为什么三篇论文都不用闭环

这不是缺陷，是刻意设计。判别器的输出不回流到 Generator——只做一次性过滤。闭环的风险（reward hacking、多样性崩塌、easy sample 退化）超过潜在收益。CDFF 如果要证明闭环的价值，必须展示在三重锚定（S8物理规则 + 人工校准 + 独立测试集）约束下的净收益。

## 十一、课程学习路径设计

> 2026-08-04 新增。

### 11.1 为什么需要课程路径

把「学会生成低慢小目标」丢给模型，让它自己找学习方向——这是赌博。低慢小物品的生成天然可分阶段，正确的做法是设置**有先后次序的课程路径**，每一步验证过关后才进下一步。课程路径是验证「AI 学习方向正确」的**唯一可追溯方式**。

### 11.2 五阶段渐进课程

```
阶段1: 近距离 + 简单背景 + 正面
  ├─ 学会: 无人机长什么样（基本外观、轮廓）
  ├─ 标准: S6 通过 > 90%, S9 通过 > 80%
  └─ 不通过 → 不进入阶段2

阶段2: 拉远距离 + 变换角度
  ├─ 学会: 尺度不变性、姿态多样性
  ├─ 标准: S7 尺寸一致性 > 85%, S9（远距离小目标）> 60%
  └─ 不通过 → 调整 Generator 架构

阶段3: 复杂背景（城市/山林/海面）
  ├─ 学会: 与背景的空间关系、遮挡边界
  ├─ 标准: S7 光照一致性 > 80%, S6 背景真实感 > 85%
  └─ 不通过 → 检查 ControlNet 场景生成质量

阶段4: 连续运动序列
  ├─ 学会: 帧间一致性、运动模糊
  ├─ 标准: S8 轨迹连续性 > 95%
  └─ 不通过 → 检查 Agent 2 时空编码

阶段5: 极端条件（低光照/雾/小目标/部分遮挡）
  ├─ 学会: 边缘情况、鲁棒性
  ├─ 标准: 全 S 级综合通过率 > 70%
  └─ 这是最终检验
```

每阶段设 S6-S9 通过率标准，不通过不进下一阶段。这确保了学习方向可追溯——你知道模型在哪一步开始掉队，而不是对着最终 mAP 猜原因。

## 十二、对抗训练偏差分析

> 2026-08-04 新增。

### 12.1 对抗训练的必然偏差

Generator 和 Validator 的对抗博弈**没有外部裁判时**必然滑向 easy mode——这是 reward hacking 的典型表现：

```
双方目标:
  Generator: min 自己产出被 Validator 判为失败
  Validator: min 自己把好图判为失败 + 把坏图判为通过

纳什均衡点:
  双方都找到最省力的"互不找茬"状态
  → Generator 专产 Validator 最容易判过的图
  → Validator 的标准悄悄退化到 Generator 的舒适区
```

### 12.2 偏差在各阶段的具体表现

| 阶段 | 偏差表现 | 下游后果 |
|:--|:--|:--|
| S6 退化 | Generator 学会生成纹理平滑的图 → BRISQUE 高分 | 平滑纹理 ≠ 真实场景纹理 → 检测器泛化下降 |
| S7 多样性崩塌 | Generator 专产最容易验证一致性的场景（蓝天背景、水平飞行） | 训练数据多样性消失 |
| S9 easy sample 退化 | Generator 把无人机越来越大、背景越来越简单 | 检测器在复杂场景泛化能力下降 |
| **全局** | **每个指标都绿，但下游 mAP 不涨** | 闭环最隐蔽的失败模式 |

### 12.3 三重外部硬锚点

闭环内部不可能自己发现自己在退化。必须有不参与反馈回路的独立裁判：

```
               ┌──────────────┐
               │ 闭环内部       │
               │ G ⇄ V 对抗     │  ← 会漂移
               │ "我们觉得很好"  │
               └──────┬───────┘
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
   ┌──────────┐ ┌──────────┐ ┌──────────┐
   │ S8 物理   │ │ 独立真实  │ │ 定期人工  │
   │ 永不可训  │ │ 测试集    │ │ 抽样      │
   │ 骗不了    │ │ 终极裁判  │ │ 盲区发现  │
   └──────────┘ └──────────┘ └──────────┘
```

| 锚点 | 防什么 | 实现 |
|:--|:--|:--|
| S8 物理规则 | Generator 生成不物理的轨迹骗过视觉检查 | 纯物理公式，无学习参数 |
| 独立真实测试集 | 闭环在 easy mode 自嗨 | 与生成管线隔离，只做最终 mAP 裁决 |
| 定期人工抽样 | 自动化指标全绿但图不对劲 | 每 N 轮抽 50 帧人工打分 |

### 12.4 对抗训练的能力边界

**对抗训练能自主做的事**：
- 在固定审查标准下持续提升生成质量
- 自动识别和修复高频失败模式（失败码聚类 → 针对性微调）

**对抗训练不能自主做的事**：
- 知道 Validator 标准是否在漂移（需独立测试集）
- 知道自己的生成是否真正对检测训练有用（需人工抽样）
- 发现全新类型的失败（需人工发现未知的未知）

**结论**：让对抗训练自动处理 80% 已知问题，剩余 20%（标准漂移、未知失败模式、方向性判断）靠三重锚点兜底。ODGEN/FLORA/InstaGen 不做闭环不是因为技术做不到，而是因为闭环的锚点设计成本和持续人工监控成本超过单向流水线的收益。CDFF 要证明闭环有净收益，唯一方式是让三重锚点足够扎实，并用实验数据证明"有闭环的 mAP 提升 > 无闭环"。

## 十三、反馈闭环路由机制

> 2026-08-04 新增。

### 13.1 路由表：失败追溯到 Generator 组件

Generator 是三段式管线，Validator 各级失败必须追溯到对应组件，不能一刀切全训 LoRA：

| Validator 失败 | 责任组件 | 反馈目标 | 微调范式 |
|:--|:--|:--|:--|
| S6 RGB 质量差 | Agent 3（渲染问题） | Agent 3 LoRA | 范式 B：失败对比学习 |
| S7 尺寸不对 | Agent 2（bbox 不合理） | Agent 2 Transformer | 范式 B：失败对比学习 |
| S7 光照不一致 | Agent 1（光照参数）+ Agent 3 | 需诊断 | 先人工判断再路由 |
| S8 轨迹物理异常 | Agent 2（轨迹生成） | Agent 2 Transformer | 范式 B：失败对比学习 |
| S9 检测不到 | Agent 3（渲染不够真实） | Agent 3 LoRA | 范式 B：失败对比学习 |
| S9 IR 检测不到 | YOLO 域适应不足 | 不反馈（对照线） | 不触发微调 |

### 13.2 两种反馈速度

**快速反馈：即时 L1 过滤**
```python
for frame_batch in generator.produce():
    result = validator.check(frame_batch)
    if result.passed:
        training_pool.add(frame_batch)   # 即时入库
    else:
        buffer.add(frame_batch, result)  # 附带失败码
```
每帧生成后立即验证，通过→训练池，失败→FailureBuffer。这是防火墙——坏图不进训练池。

**慢速反馈：周期性 L2→L3 微调**

FailureBuffer 积累到阈值后触发，不逐条响应：
```
FailureBuffer → 按失败码聚类 → 识别高频失败模式 → 触发微调
    ├── S6 失败堆积 > 50 条 → 微调 Agent 3 (LoRA)
    ├── S8 失败堆积 > 20 条 → 微调 Agent 2 (Transformer)
    └── S9 失败堆积 > 100 条 → 微调 Agent 3 (LoRA)
```

### 13.3 三种微调范式的路由分配

| 范式 | 触发条件 | 目标 Agent | 操作 |
|:--|:--|:--|:--|
| **A. 正样本增量** | 正常通过验证的帧 | Agent 3 | 通过帧 → 增量 LoRA |
| **B. 失败对比学习** | 特定失败模式堆积 | Agent 2 或 3 | 失败 vs 修正 → 对比微调 |
| **C. 质量排序** | 精细化质量提升 | Agent 3 | 同场景多输出排序 → 偏好优化 |

### 13.4 完整循环示例

假设批量生成 500 帧，经过 Validator：

```
S6 通过: 430/500, 失败: 70 → FailureBuffer
  └─ 52 帧 BRISQUE 分数过低 → 堆积到阈值

S7 通过: 410/430, 失败: 20 → FailureBuffer
  └─ 14 帧尺寸不一致（距离 800m 但 bbox 占 40%）→ 堆积到阈值

S8 通过: 408/410, 失败: 2 → 低频，不触发

S9 通过: 390/408, 失败: 18 → FailureBuffer, 暂未到阈值

最终: 390 帧入训练池, 110 帧入 Buffer
```

触发反馈：
- 52 条 S6 低质量 → 触发 Agent3 LoRA 微调（范式 B）
- 14 条 S7 尺寸异常 → 触发 Agent2 Transformer 微调（范式 B）
- 18 条 S9 检测不到 → 加入下一轮观察，不触发

## 十四、S6-S9 参考案例对标

### 14.1 对标总览

| Validator | 参考来源 | 成熟度 | 说明 |
|:--|:--|:--|:--|

| S7（尺寸映射） | 无直接参考 | **简单** | 距离→面积映射表，几何关系，不需要论文支撑 |
| S7（姿态） | 自动驾驶车辆姿态预测（Waymo/nuScenes）| **部分成熟** | 领域不同但方法论可迁移 |

### 14.2 创新定位

**审查端单个模块都不是创新**——每个 S 都有成熟参考或极简单无需参考。创新在：
1. **四级串联架构**（S6→S7→S8→S9 短路求值）
2. **对抗隔离约束**（Validator-Generator 隔离规则五条）
3. **课程学习路径**（五阶段渐进 + 逐阶段验证标准）
4. **反馈闭环路由**（失败码 → 责任定位 → 精确微调）

这是整体系统设计贡献，不是某个算法点的突破。

### 14.3 为什么三篇对标论文不做闭环

ODGEN/FLORA/InstaGen 都只用判别器做一次性过滤，从不回流到 Generator。这不是技术做不到——是刻意设计：

```
ODGEN:   生成 → 判别器过滤（仅剔除）→ 训练 → 结束
FLORA:   生成 → 人工抽查（仅剔除）→ 训练 → 结束
InstaGen: 生成+标注 → CLIP过滤（仅剔除）→ 训练 → 结束
```

闭环有净收益的前提（锚点设计 + 持续人工监控）成本极高，对他们来说是杀鸡用牛刀。CDFF 要证明闭环值得，必须在三重锚定约束下展示净 mAP 收益。
